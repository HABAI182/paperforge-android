# PaperForge 下一步开发总计划

> 执行更新（2026-10-24）：已按用户追加要求改为手机优先；Office 手机引擎、表格、结构 Word 与 PPTX 的实际实施状态见第11章。下文保留完整研究路线，不代表全部已经实现。

**本文件是开发规格。研究阶段没有修改应用；用户随后追加授权：计划完成后继续开发下一代版本。实际实施和发布结果另见交付记录，方案图仍不代表已实现界面。**

PaperForge 应当成为一个随手就能用的个人文档工作台：拍得准，读得舒服，找得快，格式转得明白，原件和修改始终分得清。下一步先把这些日常动作做到顺畅，再扩大功能覆盖面。

## 1. 本次决定

1. **扫描与 OCR 继续列为最高优先级。** 已经接入模型，不代表真实纸张、书页、不同手机上已经稳定。接下来优先解决取景纸框与最终裁切不一致、小字变糊、裁掉边缘文字、重复拍摄、OCR 慢和文字层错位。
2. **阅读器立即进入下一版的核心范围。** 新增左右滑动分页、全屏、纵向连续三项基本体验，记住每份文档的位置与阅读方式；之后补高清分块、文字选择、目录、书签、双页、夜间和重排。
3. **文件互转成为正式产品模块。** 统一输入、目标格式、质量模式、页码范围、保存位置、批处理、结果预览；每条转换路线有真实能力说明，不把所有格式都塞进一个含糊的“万能转换”按钮。
4. **UI 做一次有范围的整体梳理。** 文档优先、工具按需、操作靠近内容；保留现有多选、直接删除、回收站、个性化等能力。简约不能靠藏起功能实现。
5. **默认仍然适合一个人使用。** 无账户、无广告、无水印；本地扫描、阅读、基础转换保持独立可用。可选的电脑辅助、联网更新、翻译与 AI 作为扩展，不绑在启动、打开文件和拍照链路上。
6. **先交付可感知的改善，不做一轮全栈重写。** 保留 Kotlin/Compose、CameraX、Room 和现有 PDF 工具基础；逐步抽离阅读、转换、任务、文档资源模块。

优先顺序是：**不丢内容 → 扫描可用 → 阅读舒服 → 转换顺手 → OCR 与查找可靠 → 专业编辑与自动化 → 高级研究功能。**

### 3.2 明确未完成

- 左右滑页、真正全屏、阅读位置恢复、原生文字选择、可点击链接与完整目录导航。
- 曲面自动判断、真实双页书脊定位、去手指、手写擦除、去反光、可靠超分。
- 原生 PDF 文字原位编辑、证书签名、XFA 等高级 PDF 能力。
- 已落地的第二 OCR 引擎；不能只加入一个没有后端的切换按钮。
- 统一持久任务中心、跨流程配方、电脑辅助转换与设备间文件接力。

### 3.3 证据必须与目标分开

现有 OCR 对比来自 9 张固定合成页：平均 CER 约 3.35%，中文约 5.12%；多路处理后模拟器 p50/p95 约 4.95/7.13 秒，早期约 0.76/1.19 秒。这说明优化正确率同时付出了明显时间成本，不能把“更复杂”直接理解成“更好”。这些是历史开发集结果，并非 0.5.0 的新真机测量，也不是竞品横评。

固定四角和实际自动裁边的 OCR 曾有明显差别。下一轮应优先看完整链路，避免在已知样例上反复提高某个数字，却留下手机实际拍照的问题。

0.5.0 的新模型、跟踪和曲面入口做过有限模拟器验证；没有足够证据宣布真实弯曲书页、弱光反光、各类国内 ROM、50MP、温升和续航已经解决。本轮不重复构建或为计划跑无关测试。

## 5. 下一步应解决的十条完整任务链

### A. 拍一张通知，立刻分享

首页扫描 → 自动识边/手动拍摄 → 可直接完成 → 使用上次 PDF 预设 → 系统分享。标题可稍后改；OCR 在需要可搜索导出时处理。普通清晰页不弹一串质量确认，不强迫调角。页面不足时显示轻提示，不封锁快门。

成功标准：首次启动后进入相机只需一次明确操作；拍到的页面不因后台识别失败丢失；保存后知道文件在哪里。

### B. 连续扫描一叠材料

连续拍摄 → 实时显示页数和缩略图 → 某页可重拍替换 → 批量套用增强 → 页序检查 → 一份 PDF。拍摄和后处理分离，不能等 OCR 完成才能拍下一张。会话中断后恢复已拍页面；最后保存失败可原任务重试。

### C. 扫一本展开的书

书籍档案 → 一次拍两页 → 调书脊 → 左右分别修边与曲面 → 设置封面/左右页序 → 自动递增 → PDF/图片/可搜索文本。允许保留单页、漏页补拍、交错排序、奇偶旋转。当前中分功能升级为可视书脊拆分，不能把所有书都硬切成对半。

### D. 睡前看一份 PDF

点开即恢复到上次位置 → 左右滑动翻页 → 单击中部收起工具 → 全屏 → 双击适宽/还原 → 目录或搜索跳转 → 返回上一阅读位置。退出时保存位置、缩放、显示方式。夜间外框与页面着色分开，彩色图表可保持原色。

### E. 找到半年前的一张票据

全局搜索店名/金额片段/标签 → 结果显示命中页和局部文字 → 一点跳到原页 → 分享或加入资料包。支持“最近打开/最近修改/收藏/未整理”快速筛选。中文检索要覆盖短词和混合编号；近似搜索是可选补充，精确编号先返回。

### F. PDF 里的表格拿去算

圈选表格 → 自动检测行列 → 调整表头与合并单元格 → 原图/表格对照 → 导出 XLSX/CSV。保留原始识别值，金额、前导零、日期、百分比用列类型处理；不悄悄把编号改成科学计数法。先支持明确有边框表，再扩展无边框和跨页表。

### G. Word/Excel/PPT 变成可发送的 PDF

选择文件 → 自动识别可用转换引擎 → 选纸张/方向/工作表或幻灯片范围 → 看预览 → 导出。表格重点是打印区域、缩放比例和重复表头；幻灯片重点是比例、备注和隐藏页；文档重点是字体、分页、页眉脚注。无可用引擎时直接给出实际可用路线，不显示一个必定失败的执行按钮。

### H. 多份文件组成申请材料

多选 PDF/图片/支持的 Office → 转为页面 → 可视排序 → 插封面、目录、页码 → 按指定大小压缩或分卷 → 保存。预设如“证件正反面 A4”“论文阅读”“10 MiB 内发送”，允许自定义。

### I. 读资料并做可带走的摘录

选中文字/框选图表 → 高亮或摘录 → 写一句笔记 → 卡片保留文件名、页码和回跳链接 → 导出 Markdown/DOCX/带批注 PDF。笔记和原文分开；跨页摘录可以逻辑合并，文件里仍用多个合法区域表示。

### J. 一个人的自动归档

“票据归档”配方：扫描 → OCR → 建议文件名 → 加标签 → 导出到用户选定目录 → 显示完成记录。运行前可看配方步骤，完成后能知道哪一步失败；不弹企业审批，不自动删除未核对的原件。

## 6. 扫描核心详细方向

### 6.1 取景与照片必须使用同一几何约定

建立一条完整映射：传感器/分析图 → 预览裁切与旋转 → 照片 EXIF → 原图四角 → 透视裁切 → 曲面网格 → 页面坐标。每个阶段保存变换、输出尺寸和版本；矩阵只能描述仿射/透视，非线性曲面需保存网格映射，不能继续假装一张单应矩阵足够。

显示纸框的平滑只影响视觉；最终拍摄角点使用新鲜、可验证的检测结果。沿用取景框时同时记录时间、旋转、裁切区；过期或画面变化时重新定位。不要因为 UI 状态刷新反复解绑 CameraX。

### 6.2 自动拍摄应该理解“换了一页”

稳定度、对焦和画面运动用于短时判断；翻页后的局部内容变化用于重新布防；相似度只帮助抑制误连拍，不能阻止两张内容相似的表格。提供连续、手动、定时三种方式；物理音量键和可选耳机/蓝牙快门提升架书场景效率。

### 6.3 裁切从四角扩展为好操作的工具

- 四角和整条边均可拖；放大镜不盖住落点，十字与实际角点严格对齐。
- 自动识边、全图、原比例、纸张比例、重置、撤销都有清楚入口。
- 可调外扩边距；默认宁可留一点纸边，避免切掉页码或贴边文字。
- 低对比白纸、暗纸、桌纹、塑料套、屏幕、票据各有样例；多候选时可轻点选纸张，不能只给神秘置信度数字。
- 多页批处理允许只复核低把握页面；“有疑问”只是提示，用户可直接完成。

### 6.4 增强要保护内容

“自然”保留纸张和彩色；“清晰文字”增强对比；“去阴影”处理照明；“黑白”做实际二值编码。每种效果可长按对比原图、调整强度、应用到当前/所选/全部。局部阴影修复、反光修复和去手指需要原图对照，不能用生成模型把缺失字符补成自信的假字。

高级恢复可研究 DocRes、UVDoc、DocScanner 等，但论文/GPU demo 与手机实时可用是不同阶段。优先复用现有推理运行时，先离线验证原图与网格，再决定移动端接入。[CV01][CV02][CV03]

## 7. OCR 与结构识别详细方向

1. **三个速度档位。** 快速：一次主识别；均衡：仅在小字、低把握区域补识别；精细：明确启动多路或第二引擎。默认均衡，不让清晰整页也支付所有重试的时间。
2. **识别输入独立于显示滤镜。** 文档展示用彩色，不代表 OCR 只能吃彩色；识别可使用原图、适当灰度、局部放大，但文字框必须映射回同一页面。
3. **纠错保持透明。** 原始识别、候选、自动选择、用户修改分别保存；疑似错误可点开看原图。金额、证件号、日期等不靠语言模型润色。重复标题的上下文投票应可关闭，不能把相关视图当成独立投票保证。
4. **区域 OCR 和校对。** 框一段重识别，逐行/逐词修订；原图和文本联动；改正文本文字框如何失效或重建有明确规则。
5. **结构化中间层。** 页、块、段落、行、词、表格、图片、公式、阅读顺序、坐标、来源版本，是所有导出共用的数据。先支持标题/单栏/双栏/有线表格，不一开始追求任意杂志。
6. **第二引擎试验有退出条件。** 候选 PP-OCRv6 tiny/small、PP-OCRv5 mobile 以及适合特定脚本的 Tesseract。当前官方发布已到 PaddleOCR 3.7.0/PP-OCRv6，不能继续把较老 v5 文档当最新能力；v5 移动端链路仍可作为成熟基线。[OC03][UP01]
7. **可搜索不等于好选择。** 在至少两个独立阅读器检查复制顺序、汉字定位、多栏和旋转页。搜索应渐进返回已完成页，取消后保留已识别结果。

## 8. 阅读、转换与 UI 的独立规格

这三部分直接来自本轮新增要求，分别有完整专篇：

- 《阅读模式与交互规范》：所有翻页方式、全屏状态、缩放冲突、文本选择、书签、页面标签、阅读进度、双页、重排、朗读和快捷键。
- 《文件转换能力矩阵》：格式家族、方向、实施阶段、手机/电脑引擎、保真模式、批处理、预览、失败恢复，以及表格/Office/电子书/图片的专门要求。
- 《UI 设计与页面规范》：信息架构、设计变量、各屏布局、深浅色、状态、触控尺寸、平板折叠屏、自定义和方案图。

这三份是开发要求，不是可有可无的灵感页；下一版阅读基础、转换入口和 UI 收敛均属于交付范围。

## 9. 文档、文件与历史统一

### 9.1 用户只应面对几个清楚的概念

**文档**是一个可继续编辑的项目；**原件**是导入/拍摄时的源；**导出文件**是某次参数生成的结果。默认首页显示文档，展开“导出记录”才看各版本。避免导出一次就在最近列表里新增一串同名项目。

来源写“相机 / 相册 / 微信分享 / 系统文件”；保管位置写“应用内 / 用户选择目录”；最近写“上次打开”，不要把最近修改冒充阅读历史。导出完成提供“打开、分享、查看位置”，不只说“保存成功”。

### 9.2 多选继续加强

保留长按进入、明确多选按钮、全选/反选、数量与范围。文档多选支持分享、合并、转换、压缩、标签、文件夹、收藏、导出、回收、直接删除；页面多选支持重排、旋转、增强、OCR、抽取、删除、复制。危险动作一次明确确认；普通可撤销移动用短暂撤销提示，不为每一项弹窗。

### 9.3 储存不要越来越不透明

增加按原件、历史、缩略图、OCR/布局、导出缓存的容量视图。清缓存只删可重建物；保留历史的空间成本可设上限，清理前说明影响。资源引用应覆盖当前页、历史、书签/摘录依赖和备份快照；不能只看当前页面是否引用便删除仍在历史中的源文件。

备份包含文档、原件、处理参数、OCR、批注、书签、阅读位置、配置与配方；任务临时缓存可不带。恢复先看数量、容量和冲突策略，默认追加；允许按内容识别重复，但不强行吞掉用户有意保留的两份版本。[CM07][CM10][MG01]

## 10. PDF 编辑与输出补全

- 页面工作台支持跨文件取页、拖动、奇偶交错、双面扫描反序、按章节拆分、按目标大小分卷、统一纸张和边距。
- 区分临时阅读裁边、CropBox 可见区域调整、真正移除内容。黑色矩形覆盖不等于脱敏；现有全页栅格脱敏继续可用，高级路线再做对象级删除。[CM15]
- 新增文本高亮/下划线/删除线、便签、区域截图、图章、常用签名库；对外导出标准批注，可编辑/合并到页面分别选择。
- 合并和抽页保留链接、目录、页面标签、表单字段、附件与字体；同名表单字段要明确合并/重命名策略。[PD11]
- 增加 PDF 属性与诊断：是否扫描件、是否含文字、字体、图像分辨率、加密、批注/表单/签名摘要；说明工具能否处理，避免让人盲试。
- 压缩提供画质预览和前后大小，不承诺每份文件都缩小；文档已经优化时保留原件。黑白可研究 CCITT G4 或无损 JBIG2，不用有损字形聚类追求小体积。[CV08]
- PDF/A 是验证后的归档输出，不是给扩展名加 A。对不支持的透明度/字体/加密组合给实际原因；校验失败不能标成通过。
- 原位文字编辑和证书签名放在后续专业阶段；手写签名继续按“手写签名”命名，不制造证书签名的误解。

## 12. 技术结构的渐进调整

建议抽出 `document`、`capture`、`reader`、`ocr`、`conversion`、`pdfops`、`jobs`、`settings` 八个边界，先在现有模块内分包，不为分模块数量而重构。

核心数据逐步增加：

- `Document`：稳定 ID、来源、原件、类型、创建/修改/打开时间、标签、输出记录。
- `Page`：稳定页 ID、源文件页号、当前顺序、尺寸/坐标、处理版本。
- `Asset`：路径/URI、内容哈希、大小、引用关系、可重建状态。
- `Operation`：裁切、增强、曲面、旋转等参数与来源版本；复杂网格单独保存。
- `TextLayout`：原始/校正文字、块/词坐标、阅读顺序、引擎和模型版本。
- `ReaderState`：文档版本、页 ID、逻辑/印刷页码、视口、布局、书签和跳转历史。
- `ConversionJob`：输入快照、路线、预设、阶段、进度、输出、部分失败和恢复点。

操作图不必一口气替换全部历史。先为新转换任务和阅读位置建立稳定 ID，再让扫描编辑逐步接入。旧文档升级必须可读；新增字段有默认值。

## 13. 分阶段交付路线

工作量为单人集中开发的区间估计，包含必要集成与少量回归，不是承诺日期。一次只推进一个主要里程碑；若某个重型引擎超出时间盒，保留已有后端继续交付其他确定改进。

| 阶段 | 建议版本 | 主要交付 | 估计 |
| --- | --- | --- | --- |
| M0 基线收敛 | 0.5.x | 扫描真实故障分类、捕获/几何核对、草稿与输出不丢、性能/容量基线、功能保留清单 | 3–6 人日 |
| M1 每天能感到的改善 | 0.6.x | 横向分页+全屏+位置记忆；首页/编辑/阅读简化；转换中心与现有转换迁入；项目/更新入口 | 全池约10–18人日，首版选最直接切片 |
| M2 文字与文档顺畅 | 0.7.x | 快/均衡/精细 OCR、区域校对、文字选择、高清渲染、搜索命中、预设与持久任务、基础表格转换 | 全池约20–40人日，多次小版 |
| M3 转换与资料工作台 | 0.8.x | Office→PDF 可靠引擎、XLSX/CSV、可视页面组合、资料包、书籍双页与曲面改进、电脑助手最小版 | 全池约30–55人日，多次小版 |
| M4 个人档案成熟 | 0.9.x | 智能集合、配方、备份恢复完善、容量管理、批注互通、格式扩展、平板优化 | 全池约25–45人日，多次小版 |
| M5 长期打磨 | 1.0 候选 | 根据本人真实使用收敛；高级文档编辑、学习、翻译、AI/恢复模型按价值接入 | 按实际需要滚动 |

首个开发窗口优先做：**阅读横向/全屏/记忆 → 统一文档首页 → 转换中心接现有引擎 → 导出预设 → 扫描捕获几何问题**。扫描若出现裁掉文字或丢页，插到最前面修；单纯缺少高级滤镜不打断基础体验主线。

详细任务 ID、依赖、验收点和建议拆分见《分阶段开发任务清单》；不要把整份远期清单塞进 v0.6.0。

## 14. 少而有用的验证

本轮没有实施，因此不跑应用测试。未来每个改动只做与风险相称的检查：

- 读模式：真实触摸滑页、缩放到边缘、全屏退出、杀进程后恢复、100/500 页样本的可见页内存。
- 扫描：少量真实纸张留出样本，覆盖已发生的问题；每次修复留一例回归，不反复刷已经见过的合成页。
- OCR：内容正确、坐标正确、复制顺序正确、速度可接受，四者一起看。
- 转换：代表页视觉对照 + 文件能打开 + 目标结构检查；表格看单元格/类型，PPT 看页序/比例，DOCX 看段落/图片/分页。
- 保存/恢复：一次中断或失败重试、原件哈希不变、最终文件完整；不用为普通颜色或文案变更写镜像测试。
- UI：检查手机窄屏、系统大字号、深色和系统栏；每阶段只做一次完整主链路，不每个小改动都跑整套。

指标是开发目标，未达到前不写“已通过”。详见《验收用例与关键检查》。

## 15. 成功标准

最终衡量 PaperForge 的方式，应是自己日常使用时是否少了麻烦：

1. 我可以直接拍，不必每页从头拖四角。
2. 我能看清原文，放大不会只把模糊位图放大。
3. 我能左右翻页、全屏，重新打开继续上次位置。
4. 我找到功能时不必猜菜单，常用动作可以固定。
5. 我选格式时知道结果是什么，转换完成后真能继续编辑或使用。
6. 我批量处理时可以离开页面，中断后有恢复点。
7. 我知道原件、修改版和导出文件在哪里，删除和备份不会含糊。
8. 我可以把界面、手势、输出和自动化调成自己的习惯，同时默认配置已经足够好用。

这些标准优先于功能数量和营销式准确率。做到后，PaperForge 才会从“功能很多的扫描 demo”逐步成为可以长期依赖的个人工具。
