# 分阶段开发任务清单

共 98 张任务卡。所有卡片初始状态为 planned；实施记录另行更新，计划中的存在不等于功能已经完成。

优先级：P0影响基础可用与内容完整；P1日常高频；P2扩展效率；P3研究/高级。工作量是粗估，多个卡可能共享实现，不能机械相加当工期承诺。依赖中的AN05指SAF平台规范。

下一版先完成M1；M0中发现裁字/丢页时先修。远期卡不全部进入首个版本。

## M0 · 基础故障收敛

3 张卡。

### CORE02 · 捕获几何故障核对

优先级 P0；粗估 1–2 人日；依赖：无前置卡。

范围：核对取景、分析图、照片EXIF和裁切坐标，定位已发生的切角/错位。

完成条件：一组横竖与旋转照片最终裁切对应实际纸边。

### CORE03 · 拍摄结果与取景同步

优先级 P0；粗估 1–2 人日；依赖：CORE02。

范围：沿用新鲜候选，画面变化/过期候选重新定位，显示平滑不影响原始角点。

完成条件：移动纸张后不沿用旧框；手动快门始终可拍。

### CORE05 · 批量解码与草稿保全

优先级 P0；粗估 1–2 人日；依赖：无前置卡。

范围：限制同时解码大图，捕获后先记录草稿，失败项可重试。

完成条件：中断后已有页还在，失败输出不当成功文件。

## 执行规则

1. 开始一个里程碑前选定可交付切片，卡片可拆小；不要为了完成数量把空开关算实现。
2. 每张卡只做相关必要验证；已有检查通过后，除非出现新风险，不反复扩大测试。
3. 跨引擎或模型试验有时间盒；不能收益明确就停止，不阻塞可确定的阅读/UI改进。
4. 状态建议使用planned/in_progress/done/partial/deferred，并写明实际证据；不要靠删除计划卡掩盖未做项。
5. 发布说明围绕实际行为，分别写本机、模拟器、真机和未核验范围。
