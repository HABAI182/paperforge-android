# 文件转换能力矩阵与工作台设计

> 执行更新（2026-10-24）：已按用户追加要求改为手机优先；Office 手机引擎、表格、结构 Word 与 PPTX 的实际实施状态见第11章。下文保留完整研究路线，不代表全部已经实现。


目标是把常见文件转换做成一个可以长期扩展的模块。格式之间的转换是有方向、有损失、有引擎条件的图，不是任意两种扩展名都能互相替换。

## 1. 产品入口

工具页提供“文件转换”主入口，文档菜单和系统分享也能进入同一流程：

**选择文件 → 选择目标 → 调整必要参数 → 预览 → 转换/批量转换 → 打开、分享或查看保存位置。**

支持先选目标再选文件，也支持导入文件后只显示实际适用的目标。输入多种格式时，先显示共同可用的目标，再显示需要分别处理的路线。不把不可用引擎藏到执行后才报错。

近期主要分组：PDF、图片、文字、Office、表格、电子书；后续增加版式/归档、邮件/网页、开发与数据。可搜索“Word、docx、图片、表格、转长图”等别名，收藏常用路线。首页最多显示少量常用转换，全部能力留在可搜索工具页。

## 2. 状态与执行端标记

- **已有**：0.5.0 有基础实现，需要迁入统一流程或完善。
- **近期**：v0.6–0.7 的手机本地优先路线。
- **扩展**：v0.8–0.9，依赖版面/表格或可选电脑引擎。
- **研究**：远期路线，先验证格式和引擎，不能直接挂“已支持”。

执行端：**手机**是离线本地；**电脑**是自己电脑上的可选助手；**外部应用**是系统“打开方式/分享”交接，不能冒充应用内部转换成功；**自托管**是用户自己设置的转换服务。默认不依赖公共在线网站。

“基础支持”和“高保真”分别登记。例如 PDF→DOCX 已有段落模式，但图片表格复杂排版尚未重建；两个事实都要在界面里说清。

## 3. PDF 与图片路线

| 路线 | 状态/执行端 | 输出要求 | 关键参数与边界 |
| --- | --- | --- | --- |
| JPG/JPEG→PDF | 已有，手机 | 作为页面嵌入，方向正确 | 页序、EXIF、原比例/纸张、边距、OCR；能直接嵌入时避免再压一次 |
| PNG→PDF | 已有基础，手机 | 保留透明度或明确背景色 | 线稿/截图可无损；不要一律先转 JPEG |
| WebP→PDF | 近期，手机 | 清楚处理透明度 | 解码能力与动画分开；多帧不默认只取一帧不说明 |
| HEIC/HEIF→PDF | 近期/扩展，手机能力分级 | 主图/多图选择，方向与色彩 | 运行时确认解码器，必要时电脑转换；不按扩展名猜一定可解 |
| AVIF→PDF | 扩展，手机/电脑 | 单帧或明确多帧 | 平台解码能力与编码能力不同 |
| BMP/GIF→PDF | 近期/扩展，手机 | 静态图与帧序明确 | GIF 可选首帧/所有帧，不将动画声称保留在普通 PDF 中 |
| 多页 TIFF→PDF | 扩展，手机插件/电脑 | 每个 IFD 按序生成一页 | 灰度/二值、多页、压缩类型、DPI |
| SVG→PDF | 扩展，手机插件/电脑 | 优先矢量，字体替换可见 | 外部资源可用性、viewBox、文本与路径；提供栅格回退 |
| PDF→JPG | 已有，手机 | 每页图片，ZIP 或逐项保存 | 页码、DPI/像素、画质、背景、文件名 |
| PDF→PNG | 已有，手机 | 清晰线稿/透明背景按能力 | 页码、长边像素、alpha；注意体积 |
| PDF→WebP | 近期/扩展，手机 | 有损/无损模式明确 | 质量、透明度、兼容性，不默认最小文件即最好 |
| PDF→TIFF | 扩展，手机插件/电脑 | 单页/多页 TIFF | 二值/灰度/彩色、G4/其他真实编码 |
| PDF→SVG | 研究，电脑优先 | 每页矢量元素或明确混合内容 | 字体嵌入/转轮廓；不能将一张位图包在 SVG 里标成矢量恢复 |
| PDF→长图 | 近期，手机 | 多页顺序拼接 | 间距/背景/页宽；超长时自动分段并显示段数 |
| 图片→长图 | 近期，手机 | 顺序/重叠拼接两种模式 | 手调接缝、对齐、方向、裁切；不暗中裁掉内容 |
| PDF 嵌入图提取 | 已有，手机 | 资源级原始图与页面渲染分开 | 能保留编码时原样提取；软蒙版/色彩空间另处理 |
| 图片↔JPG/PNG/WebP | 近期，手机 | 尺寸、透明度与画质可控 | 转 JPEG 需选背景；重命名不等于转码 |
| 图片↔HEIC/AVIF/TIFF | 扩展，能力分级/电脑 | 依实际编码器支持展示 | 保留色彩/方向元数据，目标设备兼容性预设 |
| 图片包↔CBZ | 扩展，手机 | 自然排序的图片阅读包 | UTF-8 文件名、封面、页序；CBZ 就是归档容器，不是 OCR |

图片导出必须区分“渲染整页”和“提取原图”。原图提取可能得到遮罩或分块资源，不能保证一个资源就是一张完整页面。

## 4. PDF、文本与文档路线

| 路线 | 状态/执行端 | 输出要求 | 关键参数与边界 |
| --- | --- | --- | --- |
| 扫描/图片→可搜索 PDF | 已有，手机 | 原图 + 可选文字层 | 文字坐标、阅读顺序、字体/ToUnicode、可关闭 OCR |
| PDF→TXT | 已有，手机 | 正确阅读顺序的纯文字 | 页码、换行、编码、页间分隔；扫描件先 OCR |
| PDF→Markdown | 已有文本基础，扩展结构 | 标题/段落/列表/表格/图片引用 | 先段落，后结构；保留源页链接，公式按实际能力 |
| PDF→HTML | 已有文本基础，扩展版面 | 可流式阅读与固定版面分开 | 单文件/资源包、图片嵌入、目录、字体 |
| PDF→DOCX 段落 | 已有，手机 | 可编辑段落与阅读顺序 | 不声称恢复复杂表格和原排版 |
| PDF→DOCX 对照 | 已有，手机 | 原页图 + 可编辑段落 | 图片用于对照，不是可编辑排版恢复 |
| PDF→DOCX 版面 | 扩展，手机轻量/电脑 | 标题/段落/表格/图片的结构重建 | 保真/易编辑取舍；表格、脚注、跨页、字体预览 |
| TXT→PDF | 近期，手机 | 中文字体、自动换行与分页 | 编码、字号、边距、纸张、行距、页码 |
| Markdown→PDF | 近期/扩展，手机/电脑 | 标题、列表、代码、表格可读 | 先有限语法，复杂数学/脚注单独声明 |
| HTML→PDF | 近期/扩展，手机 WebView/电脑 | 打印 CSS、链接、页眉分页 | 本地 HTML 与 URL 分开；脚本、网络资源、延迟加载策略 |
| TXT↔MD↔HTML | 近期，手机 | 结构转换或纯文字提取分开 | HTML→TXT 会丢布局；不把丢失当成故障偷偷忽略 |
| DOCX→PDF | 扩展，电脑/成熟手机引擎 | 字体、分页、图片、页眉脚注 | 优先已有渲染引擎，不自己用 POI 画完一个 Word 排版器 |
| DOC/RTF/ODT→PDF | 扩展，电脑优先 | 旧格式/ODF 的实际页面渲染 | 字体、修订、浮动对象、字段、打印范围 |
| DOCX↔ODT/RTF/TXT/HTML | 扩展，电脑优先 | 有结构的直接转换 | 不绕 PDF 进行可编辑格式转换，避免先丢结构再猜回来 |
| WPS/WPT→DOCX/PDF | 研究，已确认引擎 | 依版本识别 | 不同代容器与兼容性；先验证样本再开放 |
| Pages→DOCX/PDF | 研究，电脑/可用引擎 | 区分包格式与预览图 | 提取内置预览不等于完整转换 |
| PDF→纯图 PDF | 已有，手机 | 明确栅格化副本 | 文字/矢量/表单/批注对象处理和签名状态可见 |
| PDF→优化 PDF | 已有基础，手机 | 优先保留原生对象 | 图像降采样/重编码、资源去重、结构优化分别控制 |
| PDF↔PDF/A | 扩展，电脑优先 | 目标 PDF/A 等级 + 实际验证 | 转回普通 PDF 不恢复被移除的交互；归档转换不保证签名继续有效 |
| PDF→打印拼版 PDF | 已有基础，扩展，手机 | 2/4合1、书册、海报分割 | 出血/装订边、奇偶、缩放、页码与纸张 |

微软官方也说明 PDF→Word 依靠结构推断，表格、脚注、图形、书签和评论等可能不能完整恢复；大多数 PDF 没有保留原 Word 的逻辑关系。[OF01] 因而必须给用户选“容易编辑”还是“外观接近”，并提供结果预览。

## 5. 表格与数据路线

| 路线 | 状态/执行端 | 输出要求 | 关键参数与边界 |
| --- | --- | --- | --- |
| 图片/扫描 PDF→XLSX | 扩展，手机轻量/电脑 | 真单元格、行列关系、可编辑值 | 有线表→无线表→跨页表；合并单元格与多表分别处理 |
| 原生 PDF→XLSX/CSV | 扩展，手机/电脑 | 优先从文字/线条提取 | 不对原生清晰表格一律截图 OCR |
| 圈选表格→CSV/TSV | 近期结构试验，手机 | 行列预览、文本类型保护 | 前导零、分隔符、引号、换行、编码 |
| XLSX/XLS/ODS→PDF | 扩展，电脑优先 | 可选择工作表/打印范围 | 自动适宽、分页、重复表头、横向、公式显示值 |
| XLSX↔ODS/XLS/CSV | 扩展，电脑 | 工作簿和单表边界明确 | CSV 单表、丢样式/公式；XLS 行列限制须识别 |
| CSV/TSV→XLSX | 近期/扩展，手机 | 选编码、分隔符、列类型 | 不自动吞前导零或把长编号变成浮点数 |
| XLSX→CSV/TSV | 扩展，手机解析/电脑 | 每个工作表单独文件 | 选公式或缓存值；没有计算引擎时不假装已重算 |
| CSV/JSON表格↔HTML/MD表格 | 近期/扩展，手机 | 明确仅二维规则表 | 嵌套 JSON 选择展开路径，缺字段与空值分开 |
| 发票/票据→CSV/JSON | 扩展，结构识别 | 字段、原文、页码、区域 | 建议值与原始值分开；金额/税率不进行无依据纠错 |
| 表单 PDF→FDF/XFDF/CSV | 扩展，手机/电脑 | 字段名、类型和值 | 多选、复选框、同名字段和只读状态 |

CSV 不提供字体、颜色、合并单元格或多工作表。数值类型规则应由用户预设，金额可以选小数点/千位分隔，身份证号/订单号默认文本。复制到 Excel 的快速方式可先提供 TSV，完整 XLSX 在结构可靠后再开放。

## 6. 幻灯片、电子书与版式文件

| 路线 | 状态/执行端 | 输出要求 | 关键参数与边界 |
| --- | --- | --- | --- |
| PPTX/PPT/ODP→PDF | 扩展，电脑/成熟引擎 | 一页一张、比例和页序正确 | 隐藏页、备注页、讲义拼版、字体；动画不保留 |
| PPTX→图片包 | 扩展，电脑 | 每张幻灯片固定像素输出 | 背景、透明度、图表/字体、页号 |
| PDF→PPTX 外观 | 扩展，手机/电脑 | 每页图放一张幻灯片 | 标注“整页图片”，适合演示但不具备原生文字编辑 |
| PDF→PPTX 可编辑 | 研究，电脑结构引擎 | 文字、图、形状重建 | 复杂图表/渐变/动画无法逆向恢复为原始对象 |
| 图片→PPTX | 扩展，手机 | 一图一页，可加标题 | 比例、裁切/完整放入、排序 |
| EPUB→PDF | 扩展，电脑/手机排版 | 根据纸张重新分页 | 字体、目录、图片、脚注、纵排；固定版面 EPUB 另处理 |
| PDF→EPUB | 扩展/研究，结构引擎 | 重建章节与流式段落 | 不用每页截图伪装电子书；原布局/公式可回退插图 |
| TXT/MD/HTML→EPUB | 扩展，手机/电脑 | 标题分章、目录和封面 | 编码、资源、语言、章节顺序 |
| EPUB→TXT/MD/HTML | 扩展，手机解析/电脑 | 按 spine 阅读顺序 | 脚注和内链保留，不能按 ZIP 文件名排列 |
| MOBI/AZW3/FB2→EPUB/PDF | 研究，电脑 | 支持的无保护输入 | 引擎/容器版本确认；暂不把解密当成格式转换需求 |
| DjVu→PDF/图片 | 扩展，电脑优先 | 多页、文字层与分辨率 | 黑白编码与彩色层，目录能否迁移单独核对 |
| XPS/OXPS→PDF | 扩展，电脑优先 | 固定版面、字体与页面 | 实际引擎兼容范围；读取与导出分别登记 |
| OFD→PDF/图片 | 扩展，电脑优先 | 版面、字体和印章外观 | 印章外观与签名效力分开，保留源 OFD [CV09] |
| PDF→OFD | 研究，电脑 | 可核对版面的转换副本 | 不是“复原原始电子发票”；不伪造原签名 |
| CAJ→PDF/图片 | 研究，独立适配器 | 版本探测、目录与文本 | 格式差异大；先验证公开样例，不承诺所有文件 |
| LaTeX→PDF | 研究，电脑 | 指定引擎/字体的可重复编译 | 本地工程附件、编译日志；不是手机内置整套 TeX 的近期任务 |
| PDF→LaTeX | 研究，结构/公式引擎 | 可编辑近似源与图片资产 | 不承诺拿回原始 TeX；公式逐块复核 |
| DXF/DWG→PDF/图片 | 研究，电脑插件 | 图层/比例/纸张/线宽 | 专业引擎路线，不塞进基础扫描版本 |

ONLYOFFICE 的转换表本身就是逐方向登记，calibre 也明确列出复杂 PDF 输入的限制。[OF03][CV07] 产品应表达具体支持面，而不是“支持一种格式”就推导出所有双向转换。

## 7. 网页、邮件、归档和内容动作

- 本地 HTML/MHTML→PDF；网页 URL→PDF 作为可选联网功能，打印模式、正文模式和完整长截图分开。
- EML/MSG→PDF/HTML：邮件头、正文、附件清单可选择；附件按独立任务处理。优先电脑助手，不在手机重做 Outlook。
- ZIP→资料包：列出可用文件、自然排序、选页组合；ZIP 不是一个自带页面的文档格式，不把解压成功当成全部文件转换成功。
- PDF/图片→ZIP：按原件、导出结果或图片包打包；可选清单、目录结构、说明与校验信息。
- OCR 联系信息→VCF；日期/事项→ICS；二维码内容→TXT/图片。用户可以看并修改识别值，不在后台自动创建联系人/日程。
- 高亮/笔记→MD/DOCX/HTML/JSON；复习卡→Anki CSV；所有摘录保留源页。
- OCR 区域→JSON/hOCR/ALTO 或应用结构 JSON，便于自用脚本；坐标、单位、页旋转和源版本必须有定义。

这些能力放在“更多转换/内容提取”，不挤占扫描首页。

## 8. 三种保真目标

### 8.1 外观优先

适合打印、发送、归档和演示。允许生成页面图，但明确告诉用户输出是图像还是原生内容。源文件保留，文本层可单独添加。PDF→PPTX 外观模式、整页图 DOCX 属于这一类。

### 8.2 编辑优先

适合复制、重新排版、修改表格和再次计算。尽量输出标题、段落、列表、表格、图片与阅读顺序；可能与原分页不同。PDF→DOCX 段落、PDF→XLSX、PDF→EPUB 属于此类。

### 8.3 内容保留优先

适合页面整理和轻压缩。保持原生文字、矢量、链接、批注、表单、目录、附件与字体，尽量只改目标对象。当前图片优化路线以此为基础；不能因为压缩就重绘整份 PDF。

默认选择根据路线决定；高级设置说明将保留/重建/丢失的对象。只展示与当前任务有关的说明，不弹一张无关免责声明表。

## 9. 转换中心页面

### 9.1 选择与参数

顶部显示源文件名和数量；中间“当前格式 → 目标格式”；下面是“常用预设、页码/范围、输出位置”。更多设置折叠。首次只要求必要输入，之后记住本路线的设置。

批量任务支持同参数与逐文件覆盖；页码范围可预览缩略图，不只提供难读字符串。目标文件名提供模板与冲突示例，保存位置明确显示提供程序和用户可见目录。

### 9.2 预览

大文件先预览当前/首页和一张代表页，用户可选择任意页；表格展示真实单元格预览，DOCX 展示段落布局而非把原 PDF 图当转换结果。可并排/滑块对比原件与结果，显示已知丢失项和字体替换。

没有可渲染输出时可先显示结构摘要“3 个工作表、12 列、180 行”，并允许打开外部预览；不能伪造一个像原图的结果图。

### 9.3 执行与完成

执行过程中显示处理文件、当前阶段、已完成/总页数、取消和离开继续。估算不准时只显示阶段进度，不编造剩余秒数。

完成页显示成功/失败数量、实际输出体积、目标位置、打开/分享/继续处理。失败任务保留输入与参数，允许只重试失败文件；外部提供程序写入失败不重跑全部 OCR。

## 10. 批处理与配方

转换可以接在配方中，例如：

1. 扫描 → 自然增强 → 中文均衡 OCR → 可搜索 PDF → 命名 → 导出。
2. 多选图片 → 按拍摄时间排序 → A4证件合版 → 300DPI PDF → 分享。
3. Excel → 选择所有可见工作表 → 适宽 PDF → 合并封面 → 小于目标大小分卷。
4. PDF → 只取第3–8页 → 圈选表格 → XLSX → 保存到上次目录。
5. 多份 Office/图片/PDF → 生成统一资料包 → 目录/页码 → ZIP 归档。

每步接收和输出有类型，配方编辑器只允许兼容的下一步。默认不出现复杂编程画布；用有序步骤卡即可。步骤结果可以复用，修改最后保存位置不重跑前面的昂贵识别。

## 11. 引擎与结构设计

`ConversionRoute` 至少登记：输入 MIME/签名字节/容器版本、目标格式、模式、所需引擎、运行位置、支持参数、页级/文件级能力、可取消/恢复、保留对象、已知限制、能力版本。

`ConversionEngine` 提供探测、预览、估算、执行和验证接口。`DocumentIR` 保存页面、段落、表格、图片、公式、阅读顺序与源页区域，供 OCR 与结构导出共用。不是所有路线都经过 IR：JPG→PDF 应走直接嵌入，DOCX→ODT 应走结构引擎，PDF 页面重排应保留对象。

建议三层：

- **手机基础层**：现有 PDFBox/Android 绘制与解码器、ML Kit、文字/图片转换、文件打包和页面操作。
- **手机模型层**：按需离线模型包，优先共用 MNN/ORT；版面/表格能力有资源预算。
- **可选电脑层**：LibreOffice、Docling、OCRmyPDF、qpdf、calibre、OFDRW 等适配器；不要求每个用户都安装全部组件。[OF02][OC05][CV06][CV07][CV08][CV09]

Apache POI 等 Office 解析工具不等于完整分页渲染器；Docling 的结构解析也不等于所见即所得 Office 转 PDF。对外输出的能力名称必须对应真正的引擎结果。

## 12. 电脑助手最小方案

先支持**文件夹交接**：手机导出任务包，电脑助手处理后生成结果包，手机导入。这条路线离线、容易排错，不依赖长期服务。之后再加局域网二维码配对、任务查询、断点传输和 USB 交接。

助手界面只要任务队列、可用引擎、目标目录、进度与日志。不做账户体系；默认只接受自己配对的设备。命令参数用独立参数传递，不将文件名拼成可执行 shell 文本；固定任务目录与输出映射，避免中文、空格或特殊字符使转换失控。

每个 Office 任务使用独立临时配置/工作目录，字体清单和实际渲染引擎版本写入记录。字体缺失在预览阶段标出；允许用户指定个人字体目录。完成后保留源件和结果，临时文件可清理。

电脑不在线时手机基础转换仍可运行；需要助手的任务显示“等待电脑”而不是持续转圈。用户可取消等待、改用外部应用或保留待处理。

## 13. 内容、编码与细节要求

- CJK、emoji、混排、竖排和 RTL 按引擎逐步支持；不能用一个“多语言”开关掩盖实际脚本限制。
- 文本编码优先 UTF-8，兼容 BOM、UTF-16 和常见 GB18030 输入；检测只是建议，可手动选择并预览。
- 文件名统一 Unicode、扩展名和 MIME；保存到 Nextcloud/系统分享等提供程序时核对实际名称。[CM12]
- 文档字体嵌入/替换、行距、分页、表头、页眉页脚、脚注、超链接都有保留策略。
- PDF 图像优化保留透明蒙版/色彩配置；目标大小是近似目标，不无限降低质量。
- 数字签名、表单、附件、目录、图层等可能受转换影响；在相关路线的一行说明中表达，不给每个文件加一堆无关确认。
- 输出先写临时文件，成功后再登记文档；已有完整文件才提供分享。外部写入不支持原子替换时保留本地完整结果供重试。[CM10]
- 配方缓存按输入内容版本、参数、模型/引擎版本区分；改了原文件不能误用上次输出。

## 15. 转换验收不靠“文件存在”

每个新路线挑一个简单样例、一个带中文/图片/表格的代表样例，以及一个已知失败情况即可开始。检查打开、页序/尺寸、关键内容、结构与输出说明。现有路线参数复用和纯 UI 入口调整只做相关冒烟，不每次重跑所有格式。

具体失真或崩溃出现后增加对应一例回归。不要为追求格式数量，发布大量只在空白样例上“成功”的转换按钮。
