# 手机优先实施记录与能力边界

更新：2026-10-24。项目：[PaperForge](https://github.com/HABAI182/paperforge-android)。目标版本：0.6.0。

## 一、使用方式

1. 在手机安装纸匠主 APK。阅读、扫描、OCR、文档管理和大部分转换可直接使用。
2. 首次使用 Office 排版转换，再安装同一发布页的 Office 手机引擎 APK。普通手机优先 ARM64 包。
3. 回到转换中心选文件；引擎在手机完成排版，结果自动返回纸匠。整个过程不需要电脑或网络。
4. 表格转换在纸匠内完成，先预览/校正，再导出 XLSX 或 CSV。

手机引擎使用固定版本 LibreOfficeKit Android 运行时，JNI 接口、F-Droid 构建、对应源码与校验值均登记在源码中。[MO01][MO02][MO03]

## 二、已实现的主链路

| 领域 | 本次行为 | 验证 |
|---|---|---|
| 阅读 | 左右翻页/连续滚动、全屏、工具显隐、双击/双指缩放、进度与缩放位置恢复、书签、暖纸/夜读 | Android 模拟器交互检查 |
| 最近文档 | 最近打开与内容修改分开保存；数据库6→7迁移，备份兼容旧数据 | 旧数据保留、打开不改modified |
| UI | 统一浅/深色语义配色、单行可滚动快捷入口、四个主入口、工具搜索 | 实际界面检查 |
| 本地转换 | TXT/MD源码/HTML文字/DOCX正文→PDF；JPG/PNG/WebP；PDF图片与分段长图 | 输出文件读取、末段内容检查 |
| Office 排版 | 手机 Word/Excel/PowerPoint/ODF→PDF，同类 Office 格式互转 | 原生 Android 引擎实际执行，含中文、图片、分页、页眉页脚和合并表格 |
| 表格 | 原生文字优先、有线/无线表、扫描OCR、合并单元格、可选跨页同表头连接、逐格校正 | 原生/扫描样例值与合并关系核对、独立openpyxl读取 |
| Word结构 | 手机重建文字、字号/粗斜体、表格及嵌入图片；扫描页OCR | DOCX由独立python-docx读取，检查表格与图片 |
| PPTX外观 | 手机每页生成一张图片幻灯片，按页面比例放入 | 独立python-pptx读取并核对页数 |
| 项目与更新 | 真实项目主页、发布页，显示当前安装版本 | 界面入口和包版本检查 |

## 三、准确表达完成范围

- Office 排版保留图片、表格、打印分页等由引擎实现；字体替代、罕见公式、修订和浮动对象需要对照原件。
- PDF→DOCX 是结构重建，复杂跨栏、裁剪图像、图表和脚注的原始结构不能保证还原。
- PPTX 当前是整页图片，不声称原文字和图表已变为独立可编辑对象。
- 无线表和扫描件依赖位置推断与OCR；识别结果可在手机校正。跨页连接仅在用户开启、相邻页同首行表头时进行。
- MD 和 HTML 的快速文字入口只处理源码/正文；完整样式分页可选实际支持的 Office 引擎输入，不能笼统承诺所有网页一致。
- 扫描沿用0.5.0实现，本次未重新测量真实手机拍摄质量；没有用本轮UI/转换检查证明扫描问题全部解决。
- ARM64 产物需要构建、签名与结构核验；本轮交互环境是API35 x86_64模拟器，不能称为实体手机验收。

## 四、其余路线仍保留

原生 PDF 内容原位编辑、完整书脊网格、去手指/反光超分、PDF/A验证、证书签名、复杂CAD/CAJ等研究型路线继续保留在98卡能力池。未完成卡明确保持planned/partial；本次完成的具体能力通过独立实施状态记录关联证据。

电脑版使用 LibreOffice、PyMuPDF与pdf2docx，仅是可选适配器，不是手机功能前提；上游维护状态明确登记。[MO04][MO05][MO06]
