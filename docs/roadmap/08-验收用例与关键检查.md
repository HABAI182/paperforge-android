# 验收用例与少量关键检查

这份文件规定未来开发如何判断完成。本轮研究没有对竞品做实机横评，也没有重跑 PaperForge 全套测试。实施后的真实结果另写，不把计划中的检查项目写成已通过。

## 1. 原则

只做能发现真实问题的检查。小文案/颜色/入口调整不建立大量镜像测试；涉及页序、坐标、内容删除、文件输出和状态恢复时，保留少数高价值检查。改动相关检查通过后继续交付，不为了刷数量重复测试。

验证分开记录：构建/静态分析、本机逻辑、模拟器交互、真实手机、真实纸张、跨软件输出。模拟器相机不能证明手机曝光/对焦、国内ROM或曲面书页可用；文件存在也不能证明转换正确。

## 2. 下一版必要的五条主链路

### 2.1 阅读与恢复

打开一份多页 PDF → 左右滑到第3页 → 放大平移 → 切纵向 → 全屏 → 返回退出全屏 → 关闭并重开。至少确认页号、布局、位置记忆、缩放/翻页分工与系统导航。一次真实UI操作比几十个只断言设置值的测试更有价值。

### 2.2 转换与输出

选择一个带中文/换行的文本 → 生成多页 PDF → 查看首末页与文字复制 → 另存/分享。再对已有 PDF 转图片/文本确认统一入口没有破坏现有工具。对新增图片编码检查实际格式和方向；不要只用扩展名判断。

### 2.3 扫描不回退

手动拍一页 → 编辑页 → 裁切/增强 → 导出。仅对本轮碰到的相机/导航代码做这条冒烟；若没有修改模型，不重跑全部识边/OCR语料。真实纸张留待有设备时核验，不能凭模拟器宣布质量达到成品竞品。

### 2.4 文档管理

长按多选 → 批量收藏/分类/分享中的一条 → 移入回收站并恢复 → 对专用测试文档直接删除一次。确认最近与全部都能找到这些操作，现有功能不因UI改版消失。

### 2.5 安装与交付

构建目标安装包、核对版本/包名/签名、确认可以覆盖开发版；安装包实际安装启动。发布时对应源码tag与附件哈希一致，旧版本保留。只交付完成构建的ABI，不把未构建包写进发布说明。

## 3. 扫描问题样例最小集合

后续有真机时先用少量自己会遇到的材料：普通A4、白纸浅桌、贴边小字、展开书、长票据、彩色印章、弱光/反光中的真实问题。每种一两张起步，保留一部分未调过的样例。

观察：是否切字、是否扭曲比例、是否拍成重复页、是否必须拖四角、完成用时、是否保留原件。把具体失败纳入回归，不以“平均IoU好看”替代人能否正常读。

参考目标可以先定“清晰普通页大多数无需手改、边缘文字不丢、重复拍摄可控”，达到前不报百分比。若要量化，明确样本数/设备/场景和人工标注口径，不能只给一个准确率。

## 4. OCR与文字层

选择一页中文/英文混排和一页表格/编号。检查原始识别、自动选择/用户修改、复制顺序、搜索命中框；再在另一阅读器中复制文字。快/均衡/精细分别记录耗时，但不在所有UI改动后重复三档基准。

CER、词框定位、阅读顺序和实际总时间分开。置信度不是校准后的出错概率；相关输入视图不当作独立模型。新引擎试验超过时间盒没有收益，记录结论并保留原实现。

## 5. 各类转换最有价值的检查

| 路线 | 检查重点 |
| --- | --- |
| 图片→PDF | 页序、方向、透明底、原比例、清晰度与OCR开关 |
| PDF→图片/长图 | 页码范围、像素尺寸、背景、分段和实际编码 |
| 文本/MD/HTML→PDF | 中文字体、自动分页、列表/表格、链接、资源 |
| PDF→DOCX | 段落/图片/表格是否真的可编辑，模式说明是否诚实 |
| 表格→CSV/XLSX | 行列、合并、前导零、金额、长编号、编码与工作表 |
| Office→PDF | 字体、分页/打印区域、隐藏页、备注、表头与公式显示值 |
| PDF→EPUB | 章节顺序、目录、脚注、图片、回原页与乱码 |
| OFD/DjVu→PDF | 版面/字体/印章外观/页序，原件仍在 |
| PDF压缩 | 大小变化、内容和图像对象、文字链接表单未被全页重绘 |
| PDF/A | 实际校验器结果，目标等级和失败原因 |

每条新路线先两个代表样例加一个失败场景即可。批量能力再做一次混合成功/失败，确认只重试失败项。只有发现新格式问题才扩大样例集。

## 6. 数据、任务与失败恢复

保存一次前后原件哈希；中断一个任务再恢复；模拟目标目录不可写一次；重命名/移动外部文件后重新定位一次。备份恢复用小库验证阅读位置/书签/设置/原件，而不是只确认ZIP能打开。

清缓存检查能重建缩略图，历史恢复所需资源未被删；删除测试仅针对专用生成文档。后台任务不在每次恢复时偷偷重跑已完成页，也不靠全局busy锁死所有阅读。

## 7. UI检查

主要屏幕各看一次浅色与深色；系统大字号检查关键按钮和长名称；相机/阅读确认系统栏与面板不遮主动作。宽屏布局在真正做相关改造时再检查，不强行把整个设备矩阵加到每次小版本。

用户流程中的文字不出现内部模型名、异常栈、修复阶段编号。诊断详情可复制导出，但默认一行说明和可用下一步。

## 8. 完成记录模板

每个里程碑记录：实际完成卡、未完成卡及原因、产物版本/源码、相关检查结果、模拟器/真机范围、仍需本人使用观察的点。报告应让人知道“这次能用什么”，不写一长串与改动无关的测试数量。

发布阻断只用于真正的问题：构建失败、打开/保存失败、明显内容丢失、版本签名不匹配、宣称功能没有实现。普通界面细节和未知长期表现可以如实记录并后续改，不制造没有必要的审批流程。
