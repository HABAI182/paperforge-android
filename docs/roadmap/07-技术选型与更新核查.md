# 技术选型、项目链接与更新核查

> 执行更新（2026-10-24）：已按用户追加要求改为手机优先；Office 手机引擎、表格、结构 Word 与 PPTX 的实际实施状态见第11章。下文保留完整研究路线，不代表全部已经实现。


核对：2026-10-24。版本是当前观察，不是自动升级命令；本计划不要求一次更新全部依赖。

## 1. 保留什么，逐步替换什么

保留 Android Kotlin/Compose、CameraX、Room、WorkManager 和现有扫描/PDF基础。近期先通过阅读器状态、工具布局和转换路由改善体验，避免同一版同时替换相机栈、OCR引擎、PDF渲染器和数据库。

建立窄接口：`CaptureSession`、`GeometryMapping`、`OcrBackend`、`ReaderDocument`、`ConversionEngine`、`JobStore`。接口承载实际差异，不提前搭一整套抽象框架。性能重的模型与渲染资源按需创建，关闭文档/任务时释放。

## 3. OCR 后端决策

默认保留已内置、无GMS首开可用的ML Kit。新增快速/均衡/精细档，让额外处理按页面情况发生。第二引擎有统一文本块与坐标输出，不能把不同引擎置信度直接当同一概率比较。

候选顺序：

1. PP-OCRv6 tiny/small：新模型体量与语言覆盖适合研究移动端，但实际导出算子、字典、CPU耗时和内存必须验证。
2. PP-OCRv5 mobile：官方已有Android shell demo，作为较成熟路径；不能由此保证v6直接套用。[OC03]
3. Tesseract：特定脚本、字体和常规印刷体候选；不为一个备用引擎默认捆绑全部语言模型。
4. Docling/PP-Structure等较重结构管线：电脑优先；论文或服务器显存数据不能直接变成手机承诺。

时间盒：一个候选后端先用少量真实问题页和已知基线回答正确率、时间、内存、包体是否值得；1–2人日没有可用成果便停止深入，继续已有路径优化。不要因为“已接了模型”就加一个没有有效行为的设置项。

## 4. 扫描与曲面研究方向

已有恢复模型继续作为本地候选，原有后备路线保留。记录模型输入、输出、预处理、后处理、来源哈希与实际接入范围。模型权重、调用封装和完整产品算法是不同层；不能把其中一层称为整个私有算法已还原。

DocRes、UVDoc、DocScanner可以提供公开的恢复/网格思路；Doc3D与UVDoc数据可辅助开发。优先复用现有运行时和必要算子，避免引入第三套大运行时。手机性能与真实书页内容优先，论文图更白不等于字符更正确。[CV01][CV02][CV03][CV04][CV05]

曲面处理结果保存网格、来源和处理版本，OCR、裁切、批注与阅读锚点都能转换坐标。简单强度插值不能解决所有折痕和遮挡；允许用户只修局部或回到原图。

## 5. 阅读引擎决策

先保留现有PdfRenderer并补交互，建立稳定`ReaderDocument`。新平台文字能力和AndroidX PDF按版本适配；API26/27继续基础阅读，不先抬最低系统要求。

AndroidX PDF新发布与旧指南存在兼容信息差异：采用具体artifact后查其manifest/API标注，再用最小原型确认。横向Pager只负责布局，不代替缩放、文字选取、分块渲染和任务取消。[AN01][AN02][AN07]

PDFium/MuPDF等候选仅在需要功能和维护成本明确时引入。读写引擎不必相同：阅读使用渲染器，页面操作使用保留对象的PDF库，避免为“统一”把所有PDF都栅格化。

## 6. 转换引擎决策

| 场景 | 首选方向 | 不应误用 |
| --- | --- | --- |
| 图片/文字→PDF | 手机原生绘制与字体嵌入 | 所有图片反复JPEG重编码 |
| PDF页面/对象操作 | 现有PDF工具逐步完善 | 全页截图替代对象保留 |
| Office→PDF | LibreOffice/成熟Office引擎，电脑助手优先 | 解析库直接当分页渲染器 |
| PDF→结构文本/表格 | 原生文字优先，必要OCR和布局模型 | 先把所有PDF图片化 |
| 电子书 | 结构化HTML/章节路线，calibre可选 | 每页截图包装为EPUB |
| OFD/DjVu等 | 独立适配器与原件保留 | 转出来能看便声称签章/结构全保留 |
| PDF归档 | 有验证器的PDF/A转换 | 改扩展名/metadata当作合规 |

每个适配器存输入输出能力、引擎版本、状态与限制。用户只看可用路线和简短说明，工程细节在诊断页。转换不引入必须登录的公共云。

## 7. 后台任务和资源

现有WorkManager已经承担部分PDF工具，但扫描导入、单页处理与备份仍需逐步统一。持久任务保存输入快照与每页完成点；取消保留可恢复结果；输出文件和数据库登记解耦。

Android16长任务可能受JobScheduler配额约束，不能假设开了前台通知便无限运行。按任务性质选择分块WorkManager或合适的用户发起前台服务，优先断点恢复，不靠不断拉起后台绕限制。[AN04]

渲染、OCR、照片处理各有限并发，避免三条管线同时占满内存。大图解码先读尺寸，分块/采样后处理；临时空间可估算，不足时给可操作的清理或改质量方案。不要预先扫描全设备和索取无关权限。

## 8. 文件与数据库演进

当前Room6中，文档有修改时间但没有独立最近打开；新增ReaderState、输出记录、任务和资源引用逐步迁移。格式/模型/处理版本进入缓存键，旧OCR不能覆盖新几何。

SAF URI不是普通文件路径，可能失效、只读、不可seek或来自网络提供程序。先处理实际能力，外部文件不默认删改。未来可提供自己的DocumentsProvider，便于其他软件访问导出，但先完成导入/另存的稳定路径。[AN05][AN06]

## 9. 关于页面与检查更新

### 9.1 首期离线版本

显示：应用名、版本/code、构建渠道、主页、发布列表、更新记录、问题反馈、开源组件、设置导出。链接通过系统浏览器打开；按钮文案“查看更新/打开发布页面”。不添加网络权限也能完成这一层。

当前代码About对话框没有项目主页/更新链接，需要补。版本号从BuildConfig/包信息读取，避免多个屏幕手写0.5.0造成不一致。

### 9.2 后续可选联网更新

用户开启后应用才在线查询；核心扫描/OCR/阅读仍本地可用。更新信息：最新适用版本、发布日期、渠道、大小、更新内容、下载或打开发布页。失败显示原因/重试，不把404与没有更新混同。

版本比较按SemVer和versionCode/channel约定；不能按字符串把0.10排在0.9之前。忽略draft，按用户选择包含/排除prerelease；正式版渠道当前无发布时说明这一事实，不误推荐旧版。

下载选择适合ABI的APK，保留进度和断点；完成后核对清单哈希和APK签名与已安装版本。系统安装由标准安装流程完成，用户可取消；不静默安装，不修改旧tag或删除旧包。开发版继续兼容现有签名；切正式签名要做一次明确迁移方案。

不要每次启动弹升级窗口；手动检查始终可用，可选后台低频检查与忽略此版本。只在确有适用新版本时提醒。

## 10. 来源复用和工程记录

研究竞品的行为、参数和输出，也可复用合适开源组件。导入时记录具体文件/模块、版本、修改与随包声明；不是额外的道德审查流程。根目录写MIT不代表仓库所有子目录同一许可，Stirling当前根LICENSE就有目录例外。[CV10]

用户提供的恢复模型继续标注来源和接入范围；本轮不再次逆向整包，不把研究时间耗在与下一版无关的壳层。不要从不明破解包引入运行库，工程上也难以确认正确性与版本。

## 11. 开发落点

- `ui/ReaderScreen.kt`：Pager/连续布局、全屏、视口状态、按需工具。
- `ui/HomeScreen.kt`：统一文档入口、首屏密度、搜索/筛选、现有多选保留。
- `ui/PaperForgeTheme.kt`：完整颜色角色、字体/尺寸/形状。
- `ui/PdfToolsDialog.kt`：路由与类别，逐步迁移转换中心。
- `MainActivity.kt`：系统文件/分享入口、About链接、导航。
- `MainViewModel.kt`：把全局busy逐步拆为任务/文档状态，转换入口复用现有队列。
- `data/Database.kt`、`Repository.kt`：最近打开、阅读状态、资产与输出记录。
- `ocr/*`：速度档、区域、原始/校正分离、统一布局。
- `pdf/*`：格式转换、原生对象保留、输出命名与完整写入。

实施优先做近期里程碑，不在第一版重构所有文件，也不因为看到了上游新版就同时升级整条依赖链。
