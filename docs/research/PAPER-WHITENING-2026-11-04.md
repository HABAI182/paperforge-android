# 纸面白度 + 灰痕层的最终归一化：第三步（实验，未接入）

2026-11-04。承接 `PAPER-MODEL-LAB-2026-11-03.md`（单图 context V1/V2 在任何阈值都过不了“淡墨 99.99% + 透印 90%”）、`PAPER-PAIRED-2026-11-04.md`（竞品只是**目标**不是真值；真实页问题是域差距）与 `PAPER-MULTIFRAME-2026-11-04.md`（多帧只能压独立噪声，压不动照明偏置）。

本轮只做实验：**在渲染出来的灰度页面上加一步“最终纸面归一化”，把空白拉到接近 255、把灰痕层压到不可见，同时不损坏笔画**。没有接入产品，没有改 `app/`、模型资产、`scan_params.json` 或版本号，没有 Android 构建，没有 git 写操作，没有新开模拟器。

## 结论先行

1. **复现成立但前提要改：上一轮的三页对照里，“我们的输出”用错了图。** notes-1/notes-2 用的是 `old-N-crop.png`，book 用的是 20011 的 `v4/book-crop.png`；这四个文件与 20010 录下的 **前后对照里的 `before-book/source-crop.png` 逐字节相同**（`59034836…`），像素统计也是未增强裁切的样子（空白区 p90 = 177/193/205，最大灰度 197/229/215）。同一次跑里真正的增强输出就在旁边：`old-N-workbook.png`、`book-automatic.png`（空白区 p90 = 253/254/255）。
2. **因此“空白 155.6–197.2 对竞品 254.9–255”是仪器差距，不是交付差距。** 用正确的输出重测，空白区均值是 **252.69 / 252.75 / 254.82**（竞品 254.90 / 254.99 / 255.00），近白(≥250) 比例 **1.000 / 0.990 / 0.996**（目标 ≥95%）。**“空白 ≥250、近白 ≥95%”这两条验收在本轮基线上已经满足。**
3. **灰痕层差距是真的，但只有原来的 1/3 左右。** 灰痕层平均墨迹 0.0097 / 0.0068 / 0.0077（上一轮报 0.025–0.037 是裁切图上的数），“仍可见”(>0.05) 比例 **1.7% / 2.7% / 4.6%**（上一轮 9%–16%）。
4. **四个方案里，只有“纯除法(不提 knee)”是免费的。** A（全局面元拉伸）在当前输出上是**恒等变换**——纸面 p90/p95 已经是 255，增益被夹到 1.0；C（CLAHE）**放大灰痕**（可见比例 +1.2 / +0.9 / +8.9pp）；B（除法+软 knee）能提到 255 但**灰痕几乎不动**，还固定损失 1.0–1.6pp 淡笔画；D（带笔画保护的混合）在同参数下把损失压到 0.5pp 以内，但灰痕也不动。
5. **“灰痕基本不可见(≤2%)”与“淡字不下降”在幅度域上是互斥的，这一轮把它量化了。** 把 knee 抬到能把灰痕压到 ≤2% 的档位（floor 0.05–0.085、宽度 0.10），淡笔画 1px 保留掉 **5.2–9.2pp**、内容保留掉 1–8pp；换成“保护掩膜只放行非笔画区”的 D-strict，代价降到 **1.1 / 2.6 / 0.9pp**，灰痕到 **2.27% / 2.18% / 0.85%**——三页里两页仍差一点才进 2%。
6. **保护掩膜为什么救不了灰痕：它覆盖了 88%/90% 的“可见灰痕”像素。** 也就是说，被判定为“笔画”的东西里绝大多数正是要清掉的透字——这是 `PAPER-PAIRED` 里“灰痕带高频结构与真实笔画之比 0.74”的另一种量法。book 页只有 36%，所以 book 页最容易压下去。
7. **DocUNet 20 页回归：激进 knee 不可接受。** D-strict 在真实照片上淡笔画 1px 保留从 0.7095 掉到 **0.5168**（−19pp），前保留 0.8498→0.7498。B0 纯除法只掉 1.0–1.9pp。
8. **合成边界：B0 与温和 knee 七个用例全过；激进 knee 与 D-strict 在“低对比铅笔(约 5% 残差)”上把笔画**整个擦掉**（残差比 0.000）。这是本轮的硬否决项。
9. **建议：默认只加“纸面白度”一步（B0，纯纸面场除法），灰痕 knee 默认关闭、参数入档但不启用。** 想让灰痕进 2% 而淡字不掉，需要的是**内容判别**（不是幅度判别），这与前几轮的结论一致。

## 环境与仪器

Python `work/office-env/Scripts/python.exe`（3.12.14，opencv 5.0.0，numpy 2.5.4，onnxruntime 1.31.0，torch 2.15.0+cpu，Pillow 13.0.0；scipy/skimage 缺失且未使用）。

仪器沿用 `paired-frontback/scripts/competitor_reference.py` 的掩膜定义（content / faint / ghost / blank），掩膜在**任何候选跑之前**按页冻结一次，候选无法移动自己的评分区。额外加了三类指标，因为旧指标能被“提白”骗过：

| 新增指标 | 定义 | 为什么需要 |
|---|---|---|
| 空白噪声 | 空白区高频 std（−GaussianBlur σ=2）与低频 std（σ=15） | 提白常伴随噪声放大 |
| 光晕 | 笔画外环（dilate 5…17 之间的环）均值 − 空白均值 | 除法/闭运算会在笔画旁留暗环 |
| 笔画损失 | 同一图像基线判为 content 的像素中，归一化后掉到 0.03 以下的比例；以及 ink 幅度比 | “保留率”是阈值约定，不是可见性 |

**本轮修了两个仪器 bug，都改变了结论：**

- **对齐门限。** `notes-3-reference.png` 这一页可以被“配准”出 **172 个 RANSAC 内点**，但那是笔记本横线的重复纹理：ink 相关 **+0.017**、内容重叠 0.07。内点数不是配准门限；`measure.alignment_gate` 另外要求 ink 相关 ≥0.15、内容重叠 ≥0.30。该页据此被弃用——与上一轮“notes-3 不可用”的结论一致，但上一轮的理由（11 内点）只是表面现象。
- **学习前景的双 sigmoid。** `app/src/main/assets/retouch/paper-ink-v1.onnx` 的图输出**已经是 sigmoid 后的概率**（输出名 `foreground`，范围 0–1）。再套一次 sigmoid 会把它推到 ~1，保护掩膜覆盖全页，混合算子退化成恒等——这一版曾把 D 的“灰痕不动”误读成结论。修正后保护区占 16–19%。

## 四、四种候选（参数全部记录）

所有候选都是对已渲染灰度页的纯算子，`paper_normalize.py` 每个函数返回 `(输出, 参数字典)`，字典里的键名直接对应可入 `scan_params.json` 的名字。共用背景估计：`background_close(gray, kernel)` = 大核椭圆闭运算（填掉暗笔画）+ σ=kernel/6 高斯平滑；`paper_field(...)` 复刻 `EnhancePipeline.paperField` 的“有界尺度 + dilate + median”。

| 方案 | 操作 | 本轮参数 |
|---|---|---|
| **A 全局面元拉伸** | 取全页 q 分位为纸面 P，`out = clip(g·255/P)`，增益夹在 [1,2]，斜率不弯 | q = 90 与 95；`maxGain=2.0` |
| **B0 纯除法（白度步）** | `out = 255·g/B`，只把局部纸面场除到 255，不动残差 | `backgroundKernel=61` |
| **B 除法 + 软 knee** | 在相对墨迹 `i=1−g/B` 上：`i<floor` 归零，`i>high` 不动，中间 smoothstep 乘 | `kernel=61/31`，`floor/high = 0.022/0.055`（另有 0.010/0.030 温和档） |
| **C 局部自适应** | 除背景后用 CLAHE 提局部对比，按 `blend` 混回，限幅 `clipLimit`，再走 knee | `clipLimit=2.0`(强)/`1.35`(软)，`cell=8`，`blend=0.5/0.32` |
| **D 混合 + 笔画保护** | B 的提白照做，但 knee 只在“非笔画区”生效；保护 = 梯度(>0.10) ∪ 学习前景(`paper-ink-v1.onnx` >0.35) ∪ 文本行(水平闭运算 15px) 再 dilate 5px 羽化 3；保护区内用 0.004/0.012 的极低 knee | `floor/high = 0.022/0.055`（常规）与 **0.070/0.170（strict）** |

## 六、灰痕/淡字前沿：为什么“压到 2%”要付钱

把 B 的 `floor` 从 0.010 扫到 0.100、宽度取 0.03 与 0.10（`results/sweep.json`，每页同一掩膜）：

| floor / 宽度 | notes-1 灰痕 / 淡字1px | notes-2 | book |
|---|---|---|---|
| 基线 | 0.0298 / 0.8320 | 0.0267 / 0.7515 | 0.0456 / 0.9340 |
| 0.010 / 0.10 | 0.0238 / 0.8060 | 0.0227 / 0.7102 | **0.0106** / 0.9022 |
| 0.020 / 0.10 | 0.0230 / 0.8020 | 0.0220 / 0.7055 | 0.0078 / 0.8976 |
| 0.050 / 0.10 | 0.0196 / 0.7799 | 0.0189 / 0.6788 | 0.0007 / 0.8758 |
| 0.085 / 0.10 | 0.0168 / 0.7523 | 0.0160 / 0.6595 | 0.0000 / 0.8510 |

- **宽度 0.10 的 knee 是“乘法斜坡”**，凡是 ink 低于 `floor+0.10` 的像素都会被按比例压暗；淡笔画平均 ink 0.16–0.21 正落在斜坡中段，所以内容保留也掉（book 0.827→0.712 @0.085）。
- **淡字“保留率”掉不等于“字没了”。** 同一档下淡笔画平均 ink 仍有 0.142 / 0.202 / 0.164，是竞品目标淡笔画（0.041 / 0.042 / 0.046）的 **3.4–4.8 倍**。损失主要是跨过了我们自己的 0.03 阈值，不是变白。
- 但**内容保留**掉到 0.712（book）就不是阈值问题了——那是真笔画被压薄。

### 带笔画保护的 D-strict（floor 0.070 / high 0.170）

| 页 | 被保护区 | 可见灰痕被保护覆盖 | 灰痕可见 | 淡字1px | 内容 | 空白 |
|---|---:|---:|---:|---:|---:|---:|
| notes-1 | 18.5% | **88.1%** | 0.0227 | 0.8203 | 0.472 | 255.00 |
| notes-2 | 19.4% | **89.7%** | 0.0218 | 0.7255 | 0.545 | 254.53 |
| book | 15.7% | **35.9%** | 0.0085 | 0.9254 | 0.819 | 254.99 |

- 保护掩膜只有 16–19%，却盖住了 88–90% 的“可见灰痕”像素——**这就是幅度域做不下去的直接证据：要清的灰痕在形状上和要留的淡字是同一类东西**。
- 所以 D-strict 的收益几乎全部来自 book 页（那一页的灰痕被保护掩膜漏掉了 64%）；两页笔记只从 0.030/0.027 走到 0.023/0.022，仍未进 2%。

## 七、DocUNet 20 页回归（公开相机照片，非机主手机数据）

`docunet_regression.py` 直接 import `real_document_eval.py` 的 `ink_map / fit / content_crop / register / tolerant`，掩膜口径不变：真值 = 扫描墨迹 >0.15；淡笔画 = 真值中照片 ink<0.06；灰痕 = 扫描空白且照片 ink 0.012–0.30。评分改成图像自身的 ink（被测对象是算子，不是网络）。20/25 页通过配准（内点 ≥60），5 页弃用。

阈值 0.02 的像素汇总：

| 算子 | 前保留 1px | 淡笔画 1px | 灰痕清理 1px | 空白均值 | 空白近白 |
|---|---:|---:|---:|---:|---:|
| baseline（不处理） | 0.8498 | 0.7095 | 0.1324 | 163.74 | 0.000 |
| A-p95 | 0.8291 | 0.6712 | 0.2087 | 205.58 | 0.403 |
| A-p90 | 0.7940 | 0.6190 | 0.3342 | 215.36 | 0.565 |
| **B0 纯除法** | 0.8398 | 0.6906 | 0.1958 | 226.84 | 0.389 |
| B knee | 0.8311 | 0.6739 | 0.2111 | 228.68 | 0.561 |
| B knee 温和(0.010/0.030) | 0.9012 | 0.8095 | 0.1328 | 227.37 | 0.431 |
| C CLAHE | 0.9532 | 0.9100 | **0.0881** | 220.70 | 0.381 |
| D | 0.8300 | 0.6718 | 0.2113 | 228.59 | 0.554 |
| **D-strict** | **0.7498** | **0.5168** | 0.4797 | 231.16 | 0.711 |

- **D-strict 在真实照片上不可接受**：淡笔画 1px 0.7095→0.5168。
- **B0 掉 1.0pp 前保留 / 1.9pp 淡笔画**，同时灰痕清理 0.132→0.196：这是“纸面不平”的输入上除法把暗区一起抬起来的副作用。
- **连真照片也提不到 250 以上**：最好的档位（D-strict）空白均值 231、近白 0.71。相机的纸面本身不是 165 就是一个分布很宽的东西，单靠除一次背景解决不了——这也是把这一步放在**已有平场之后**、而不是替代平场的另一个理由。
- **注意口径陷阱：** 这里的“分数”是图像自身的 ink，而 ink 是相对局部中值场的。任何把这页纸推白到 255 的算子都会让局部中值场升高，从而**机械地抬高测量 ink**（C 的 0.95/0.91 就是这么来的，同时它的灰痕清理掉到 0.088；灰痕平均墨迹也从 0.0575 抬到 0.0902）。所以这组数字只用于**方向性否决**（有没有崩塌），不能当“提升”读。
- 这些照片**不是机主手机拍摄**，是公开 DocUNet 研究照片；而且算子作用在照片上、不是作用在我们的渲染结果上，属于压力测试。

## 八、合成边界 sanity（7 个用例）

判定写死在脚本里（`synthetic_sanity.json` 有每项阈值与实测）：

| 用例 | 期望 | B0 | B 温和 | B 激进 | D-strict |
|---|---|---|---|---|---|
| 纯白(255, 微噪) | 纸面 ≥254.5、不压暗 | PASS | PASS | PASS | PASS |
| 灰纸 205 + 文字 | 纸面 ≥252、笔画 ≥0.90 | PASS (0.999) | PASS (0.999) | PASS (0.993) | PASS (0.999) |
| 阴影梯度 120→250 | 近白 ≥0.90、笔画 ≥0.80 | PASS (1.001) | PASS (0.989) | PASS (0.956) | PASS (0.971) |
| **低对比铅笔(~5%)** | 笔画 ≥0.85、纸面 ≥250 | PASS (0.996) | PASS (0.902) | **FAIL (0.000)** | **FAIL (0.000)** |
| 彩色印章 | 红通道对比保留 ≥0.90 | PASS (1.031) | PASS (1.031) | PASS (1.028) | PASS (1.032) |
| 浓黑文字 | 笔画 ≥0.95、最暗 ≤20 | PASS | PASS | PASS | PASS |
| 极暗拍摄(纸面 70) | 笔画 ≥0.80 | PASS (1.001) | PASS | PASS | PASS |

- **硬否决：任何 floor ≥0.03 的 knee 会把“均匀 5% 残差”的铅笔整条擦掉。** D 的保护也没救下来，因为这类笔画**同时**低于梯度门限（0.05<0.10）、低于文本行二值门限（ink<0.08）、也低于学习前景门限——保护依据本身看不见它。这与第五节里 D 在真实页上掉 0.9–2.6pp 淡字同源。
- **极暗拍摄这一行要当心：** 除法把纸面 70 拉到 255 时，笔画只到 109，绝对对比被压掉。真实链路里纸面已经在 250 以上，不会出现这个场景；但作为算子必须有 **fail-safe**：纸面估计 < ~120 时直接返回原图。
- 彩色印章按通道比例缩放保留色相（`apply_keep_chroma`），红通道对比 1.03，未被灰化。

## 九、建议接入位置、参数与风险

### 接入位置

**先给一个“不接入”的选项：**按本轮的验收表（空白 ≥250、近白 ≥95%），当前输出**已经达标**，接入唯一的确定收益是 0–2.2 个灰阶的余量。如果不打算同时承担下面列出的饱和/彩色/极暗风险，**什么都不做**也是可辩护的结论；B0 的价值主要在“纸面本来就偏灰”的输入上（DocUNet 那种空白 163.7 → 226.8），而不是在这三页上。

若仍要接入：`EnhancePipeline.apply` 里 WORKBOOK/CLEAN 分支的出口——即 `localWorkbook(...)` 写完 `destination` 之后（`WorkbookContent.write` 之后），在把 `destination` 交给缩略图/页面渲染/PDF 之前；`PdfImageEnhancement` 与批量编辑应调用同一个函数（`SoftMonochrome` 的注释已经说明这条链路是共用的）。作用对象必须是**灰度页**，彩色输入走 `apply_keep_chroma`。

### 参数（建议只启用白度步）

| `scan_params.json` 键 | 建议值 | 含义 |
|---|---|---|
| `paperWhiteFinal` | `1` | 总开关（默认开） |
| `paperWhiteKernel` | `61` | 背景闭运算核（按 long side 归一：`61·long/1400`） |
| `paperWhiteEdge` | `800` | 背景估计的有界尺度，复用 `paperFieldEdge` 同一量级 |
| `paperWhiteMinimumPaper` | `120` | 纸面估计低于此值时返回原图（极暗 fail-safe） |
| `paperWhiteMaximumGain` | `1.15` | 单像素最大抬升，防止局部误估 |
| `paperGhostFloor` | `0` | **默认关闭**；打开时建议 ≤`0.030` |
| `paperGhostHigh` | `0` | 与 floor 成对；建议 `floor+0.03` |
| `paperGhostGuard` | `0` | D 的笔画保护（梯度/学习前景/文本行），打开时保护区 16–19% |

### 风险

1. **残留收益很小。** 当前输出空白已 252.7–254.8，白度步只买 0–2.2 灰阶。
2. **饱和风险。** 把纸面推到 255 会吃掉 JPEG 余量；如果后续还有锐化/压缩，255 的平台区会放大量化边界（本轮光晕指标 +0.23 在 notes-1 上已可见，但仍在噪声内）。
3. **彩色页。** 必须按比例缩放而不是置白，否则印章/荧光笔会被灰化。
4. **knee 不可默认开。** 合成用例与 DocUNet 都给出否决；它会让“均匀淡铅笔”这类内容整片消失，而那是最不可恢复的错误。
5. **性能。** 闭运算 + 平滑在 `paperWhiteEdge=800` 上做，与现有 `paperField` 同量级；全分辨率只做一次乘除。

### 仍缺的一步

要把灰痕压到 2% 以内而淡字不掉，需要**内容判别**（这段结构属于正面笔画，还是反面透字），而不是更聪明的幅度曲线——保护掩膜覆盖 88–90% 可见灰痕这件事已经说明两者在形状上不可分。这与 `PAPER-PAIRED` 的双面证据结论（完美减法上限 0.9953/0.7868、残差地板 0.00827 高于真值门限）指向同一个缺口。

## 失败与被否决的记录

- **上一轮对照的 “ours” 选错文件。** 这是本轮最重要的发现，也是本轮所有基线数字变更的原因；不是竞品或掩膜的问题。逐字节证据在 `output-inventory.json`。
