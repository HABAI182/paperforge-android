# 前景模型优化实验：尚未接入

机主要求“优化满意再接入”。本批只增加离线训练、评估工具及候选权重实验，没有更换 Android 模型、处理参数、UI、版本或 20011 APK，也没有重新封包或发布。

## 实际工作

`scripts/train_paper_context.py` 实现原创 36,665 参数的两尺度编码/解码网络，保留全分辨率跳接，以保护细笔画。输入复用现有三个墨迹特征平面，输出前景分数；不生成字符、不做 OCR 改写或笔画膨胀。相比现有 537 参数局部模型，增加空间上下文。

训练数据仅为程序生成的字形、曲线、横线及淡墨，叠加反向模糊墨迹、污点、照明残余；没有训练用户照片或参考 App 截图。验证用独立随机种子，增加未见缩放/旋转及孤立公式标点。它仍属于同一生成器的数据域，不是独立真实文档测试。正面真值阈值为 `max(0.004, contrast×0.1)`，不代表所有抗锯齿尾部。

- V1：640 个生成块、1800 步，较高正面保留权重。
- V2：1280 个生成块、3000 步；增加 30% 无正面文字的训练块，提高透印负样本权重。
- 各模型 ONNX 约 156KB，权重及私有照片输出只保存在仓库外 `work/model-lab-20261103`。

`scripts/evaluate_paper_context.py` 在完全相同的 100 个留出夹具上比较旧模型和候选，另对同一真实代码页做截图配准空白区代理检查。阈值曲线完整保留，不能只选择某个有利指标。旧模型在这里是单独探针，**不是带有源内容保护的实际 Android 增强器**。

## 两轮结果

下表固定前景分数阈值 0.02，表示低于它的像素被判为可清理候选，尚未应用生产保护规则。

| 独立程序夹具指标 | 现有模型单独探针 | 上下文 V1 | 上下文 V2 |
|---|---:|---:|---:|
| 正面像素保留率 | 54.1804% | 99.9674% | 99.7582% |
| 淡墨正面像素保留率 | 21.0290% | 99.9577% | 99.4344% |
| 透印候选排除率 | 92.4007% | 48.1672% | 71.3498% |

V1 改善淡字保护但放过较多透字。V2 在这个阈值下改善清理，同时增加淡笔画损失。两个候选都没有同时通过初步筛选要求（淡墨保留 ≥99.99%、合成透印排除 ≥90%）；真实正文、标点完整性和手机性能还需要独立验收，初步筛选不能代替最终接入标准。

真实代码页与参考截图有 501 对匹配、342 个 RANSAC 内点，参考墨迹膨胀后取远离文字的弱负区，71,938 个候选像素。阈值 0.02 下，V1 排除 36.7233%，V2 排除 63.3170%；阈值 0.1 下分别为 49.4884%、80.6764%，但同时损失更多合成淡字。因此仍不接入。

截图空白并非逐像素真值，没有真实淡字完整标注；配准误差、照明及几何均会影响结果。两张原照片只用于离线推理检查。`photo-*-offline-proposal.png` 是实验候选可视化，**不是 APK 输出，也不是合格的最终成片**；可视检查仍见手部轮廓、透印和局部灰色正文，未达到参考效果。

V1/V2 动态奇数尺寸 73×101 的 ONNX 与 Torch 最大绝对误差分别 1.49e-6、7.15e-7，转换检查通过。V2 桌面 CPU 四线程单次代码页推理约 138ms，旧模型探针约 44ms；未含整个增强流程，且不是 Android 或真机耗时，不能据此声称单页 3 秒达标。

训练初次执行遇到模块命名与 PyTorch `half()` 冲突，已重命名；评估遇 OpenCV 浮点图不支持文字绘制，改为字形掩膜合成后，从已保存权重恢复评估，没有假称首轮全程成功。两份脚本语法检查、两轮实际训练、实图推理及导出一致性均已执行。

## 复现

需要既有实验环境的 PyTorch、OpenCV、NumPy、ONNX、ONNX Runtime，不增加应用依赖。权重输出必须在仓库外。

```text
python -X utf8 scripts/train_paper_context.py --out <private>/context-v1 --steps 1800 --samples 640 --photo <crop.png>
python -X utf8 scripts/train_paper_context.py --out <private>/context-v2 --steps 3000 --samples 1280 --sparse-blank --photo <crop.png>
python -X utf8 scripts/evaluate_paper_context.py --candidate <private>/context-v2 --reference <reference-page.png>
```

真实对照输入使用 20011 保留的 `book-crop.png` 与 `math-crop.png`；实际哈希、全部阈值、参数和来源记录在各实验 `report.json`、`comparison.json`。V1 从权重恢复后的 `seconds` 为导出/评估阶段时间，不是全训练时间；原训练进度日志单独保留。

## 研究依据与后续边界

复查了 [DocRes 官方实现](https://github.com/ZZZHANG-jx/DocRes)及 [MIT 许可](https://github.com/ZZZHANG-jx/DocRes/blob/master/LICENSE)，保留现有 DocRes；查阅 [GDB 的任务/数据索引](https://github.com/Royalvice/GDB)和[二值化模型评测集合](https://github.com/RichSu95/Document_Binarization_Collection)。本轮没有复制这些项目的新实现、下载训练数据或将它们的权重加入产品。候选代码原创，复用本项目的程序字形生成器。

两轮结果表明“保淡字”和“删透印”仍缺可靠分离，继续增大清理权重会重复这个取舍。下一实验应加入经确认的真实正面/反面分离监督和跨页面验证，并以保留真实公式/标点为约束。现有参考图只有一个可配准代码页，不能作为通用验收集。纸边/手部和展平模型尚未在本批优化，不将前景实验冒充这两项完成。
