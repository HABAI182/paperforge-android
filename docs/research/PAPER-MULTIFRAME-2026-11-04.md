# 多帧堆栈能否压低残差地板：第二步（实验，未接入）

2026-11-04。承接 `PAPER-MODEL-LAB-2026-11-03.md`（单图 context V1/V2 在任何阈值都过不了“淡墨保留 99.99% + 透印排除 90%”）与 `PAPER-PAIRED-2026-11-04.md`（没有真实正/反配对；完美双面减法的上限 0.9953 / 0.7868，1px 配准误差使排除降到 0.743；残差地板本身高于真值门限）。

本轮只做实验：**多帧平均/中值堆栈能否把残差地板压到门槛以下**。没有接入产品，没有改 `app/`、模型资产、`scan_params.json` 或版本号，没有 Android 构建，没有 git 写操作，没有新开模拟器。

## 结论先行

1. **多帧不能把门槛做穿。** 合成淡墨夹具上，单帧在 99.99% 保留处排除 0.4979；最好的堆栈（stable 4 帧均值）0.5614；门槛要 0.90。最好情形仍差约 4.4 倍（透印通过率 0.4386 vs 允许 0.10）。
2. **瓶颈不是传感器噪声。** 把噪声与照明**全部清零**的理想墨迹（`clean`，任何去噪器都达不到的上限）在钉死阈值处只有 0.5063 排除，阈值无关 AUC 0.9760（单帧 0.9710，+0.005）。也就是说，即使多帧变成完美去噪，能买到的可分性也只有 0.005 AUC 这一量级。
3. **残差地板由偏置撑住。** 空白像素上一帧残差均值 0.00934 ≈ 照明 shade 0.00827 + 散斑 0.00088 + 截断/微量透印残差 0.0002；传感器高斯噪声均值 0、σ=0.0025。shade 偏置单项就高于最小真值门限 0.004；8 帧中值只能把总偏置压到 0.00615（flicker）或 0.00869（stable），仍高于 0.004。均值堆栈几乎不动偏置（0.00939）。
4. **真实照片只有两对同页，不是一页四视图。** new-1~new-4（422 内点、−89.85°）与 new-2~new-3（118 内点、+0.46°）是两页；两对之间没有内容对应。2 帧堆栈只把空白区墨迹标准差降 24.1% / 19.6%（理想 29%），因为 27.6% / 51.7% 的方差是堆栈拿不掉的固定结构（透印、纸纹、JPEG、配准残差）。
5. **真实代理指标上，堆栈相对“重采样后的单帧”几乎没有额外收益**（pair-A 0.9249 vs 0.9257；pair-B 0.9646 vs 0.9338）。没有淡字真值、也没有参考渲染，这个数字只是空白区阈值读数，不能当精度。
6. **多帧不值得作为独立方向继续。** 它只能压“独立噪声”一项，而当前门槛被两件它动不了的事卡住：透印幅度与淡字幅度重叠（幅度证据 AUC 仅 0.575），以及照明 shade 偏置的固定项。
7. `duplex-v1` 的表述已在其目录内更正为“输入不成立，未验证”（§D）。

## 方法

### A. 合成夹具与帧模型（`multiframe/scripts/multiframe_synthetic.py`）

- **夹具集合**：`scripts/train_paper_context.py` 的 100 个留出夹具（`heldout=True`，种子 811735），按 `evaluate()` 完全相同的 rng 顺序抽取，因此淡墨子集就是文档里的 **36 个**。生成器副本与官方 `fixture` **15 次抽样逐位相等**；类规模与 `paired-frontback/duplex-evidence.json` 完全一致（正类 162,520、负类 193,611、淡墨正 63,831、淡墨负 63,602 px）。
- **帧 0** 与文档基线打分的帧逐位相同（同噪声场、同光照场）；帧 1..7 只模拟重复拍摄会变的东西：

| 场景 | 每帧变化 | 含义 |
|---|---|---|
| `stable` | 独立散斑 + 高斯噪声（σ=0.0025），**照明场不变** | 三脚架 + 固定光源的理想连拍 |
| `flicker` | 上面的噪声 + **照明 shade 场每帧重抽**（同分布） | 手持/光源晃动 |
| `handheld` | 上面的 + 每帧增益 0.97–1.03、亚像素位移 ±0.5px，**堆栈时不做配准/增益补偿** | 不执行采集协议的代价 |

- **堆栈**：2/4/8 帧的前缀（嵌套，保证配对比较），均值与中值各一套。
- **推理**：用 **context-v2 的 ONNX 产物**（`paired-frontback/inputs/context-v2/context-ink.onnx`，sha256 记录在 JSON）跑 `onnxruntime`；输入是 `features(stack)`。
- **门槛口径**：不挑阈值。要求 99.99% 淡墨保留，阈值就被钉死（淡墨正类分数的 0.01 分位），此时透印通过率是唯一要看的数（允许 0.10）。同时给出 99.9% / 99% 两个较宽门槛，以及整条阈值扫描曲线。
- **参考条件**：`clean = clip(front + bleed)`（无噪声、无照明，任何去噪器都达不到的上限，但仍含透印）。

### B. 真实帧（`multiframe/scripts/real_stacks.py`）

- SIFT（8000 特征、比值 0.72）+ RANSAC（4px）把第二帧 warp 到第一帧几何；曝光用纸面亮像素的中值增益/偏移拟合，raw 与 normalized 两套都报。
- 空白区掩膜是**参考自由**的：两帧都不出现 ink>0.20 且距其 25px 以外，去掉 40px 边框。
- ink 定义沿用 `evaluate_paper_context.py`（`1 - gray/medianBlur(dilate(gray), 0.035·min·|1)`）。
- 代理指标沿用 `bookScreenshotProxy` 的**阈值读数**，但空白区不是来自参考渲染（见 §B 限制），因此标注为代理。

## A. 合成结果

### 1. 钉死阈值下的透印排除率

淡墨正面像素（36 夹具）为保留类，全部 100 夹具的透印像素为负类；“钉死阈值”为达到该保留率所需的阈值。**门槛：保留 99.99% 时排除 ≥0.90。**

| 配置 | 99.99% 保留时排除 ↑ | 99.9% | 99% | 钉死阈值 @99.99% |
|---|---:|---:|---:|---:|
| 单帧 | 0.4979 | 0.5888 | 0.7542 | 0.00281 |
| `clean`（零噪声零照明，不可达上限） | 0.5063 | 0.6145 | 0.7716 | 0.00095 |
| stable 均值 2 / 4 / 8 帧 | 0.5415 / **0.5614** / 0.5475 | 0.6308 / **0.6429** / 0.6322 | 0.7755 / 0.7739 / 0.7717 | 0.00289 / 0.00277 / 0.00211 |
| stable 中值 2 / 4 / 8 帧 | 0.5415 / 0.5533 / 0.5360 | 0.6308 / 0.6487 / 0.6273 | 0.7755 / 0.7720 / 0.7713 | 0.00289 / 0.00219 / 0.00173 |
| flicker 均值 2 / 4 / 8 帧 | 0.5069 / 0.5189 / 0.5295 | 0.6365 / 0.6366 / 0.6150 | 0.7744 / 0.7758 / 0.7735 | 0.00203 / 0.00168 / 0.00157 |
| flicker 中值 2 / 4 / 8 帧 | 0.5069 / 0.5002 / 0.5136 | 0.6365 / 0.6010 / 0.5963 | 0.7744 / 0.7667 / 0.7680 | 0.00203 / 0.00138 / 0.00128 |
| handheld 均值 2 / 4 / 8 帧 | 0.4846 / 0.4627 / 0.3578 | 0.5788 / 0.5587 / 0.5000 | 0.7219 / 0.6926 / 0.6551 | 0.00159 / 0.00099 / 0.00031 |
| handheld 中值 2 / 4 / 8 帧 | 0.4846 / 0.4012 / 0.3378 | 0.5788 / 0.5257 / 0.4586 | 0.7219 / 0.6982 / 0.6576 | 0.00159 / 0.00056 / 0.00024 |

读法：

- **最大增益 +6.35pp**（0.4979 → 0.5614），出现在“照明完全不动”的理想场景；离 0.90 还差 0.339。
- **照明一动，增益就消失**（flicker 最好 0.5295）；**不执行采集协议会变差**（handheld 8 帧 0.3578，比单帧差 0.14）。
- 4 帧与 8 帧的差异落在噪声里，不构成“帧越多越好”的证据（见 §A.4）。
- 较宽门槛（99.9%）下最好 0.6429，仍然远低于 0.90。

### 2. 残差地板：偏置 vs 标准差

空白像素 = 无正面真值且透印 ≤0.012；“残差”= 堆栈墨迹 − `clip(front+bleed)`。

| 配置 | 残差均值（偏置） | 残差标准差 | 空白像素超自身真值门限的比例 |
|---|---:|---:|---:|
| 单帧 | 0.00934 | 0.01161 | 0.2177 |
| stable 均值 8 | 0.00939 | 0.01086 | 0.2148 |
| stable 中值 8 | 0.00869 | 0.01089 | 0.1973 |
| flicker 均值 8 | 0.00925 | **0.00468** | 0.2638 |
| flicker 中值 8 | **0.00615** | **0.00432** | **0.1560** |
| handheld 中值 8 | 0.00776 | 0.00753 | 0.1869 |
| `clean` | 0 | 0 | 0 |

单帧残差分量（同一批空白像素）：**shade 均值 0.00827**（p99 0.0463）、散斑均值 0.00088（p99 0.0170）、传感器 σ 0.0025。

这就是“残差地板”为什么压不下去：**均值堆栈只削标准差，不动偏置**；shade 偏置 0.00827 本身已经是最小真值门限 0.004 的两倍。中值在 flicker 下把偏置降到 0.00615，是因为它取到了更暗的光照分位——这不是“去掉了照明”，只是“挑了暗帧”，仍然高于 0.004。stable 场景下每帧照明相同，任何堆栈都无法减小它：只有平场/照明校正能。

### 3. 分数分布尾部与 AUC

负类（透印）分数分位与阈值无关的 AUC（淡墨正 vs 全部透印）：

| 配置 | 透印 p99 | 透印 p99.9 | AUC | 透印 p90 / 淡墨正 p0.01 |
|---|---:|---:|---:|---:|
| 单帧 | 0.8952 | 0.9871 | 0.9710 | 72× |
| `clean` | 0.9001 | 0.9866 | **0.9760** | — |
| stable 均值 8 | 0.8725 | 0.9835 | 0.9733 | — |
| flicker 中值 8 | **0.8646** | **0.9829** | **0.9742** | — |
| handheld 中值 8 | 0.9200 | 0.9934 | 0.9495 | — |

- 尾部确实压缩：p99 从 0.8952 到 0.8646（最好），p99.9 从 0.9871 到 0.9829。但**压缩的是高分尾部**，而门槛看的是钉死阈值（≈0.003）处的通量，那里由“透印幅度是否高于淡字幅度”决定，不由尾部决定。
- AUC 最多 +0.0032（堆栈）/ +0.0050（clean）。门槛要求同一保留率下把通过率从 ~0.50 降到 0.10，这不是 0.005 AUC 能给的量级。
- 一个结构性事实：门槛要求“透印 p90（0.2035）低于淡墨正 p0.01（0.00281）”，两者差 **72 倍**。任何小幅改进都不可能跨过去。

### 4. 夹具重采样的不确定性（36 个淡墨夹具）

对淡墨夹具做 200 次有放回重采样，每次重钉阈值，报“淡墨正 vs 淡墨负”的通过率：

| 配置 | 通过率中位数 | 95% 区间 |
|---|---:|---|
| 单帧 | 0.6929 | 0.5924 – 0.7900 |
| stable 均值 8 | 0.6157 | 0.5367 – 0.7070 |
| stable 中值 8 | 0.6269 | 0.5304 – 0.7165 |
| flicker 中值 8 | 0.6432 | 0.5501 – 0.7297 |
| handheld 中值 8 | 0.8064 | 0.6880 – 0.8803 |

区间大幅重叠：**在 n=36 的夹具抽样意义下，堆栈带来的 4.5–7.8pp 改进不能与抽样噪声分开**。这比“平均提升 6pp”更诚实。

## B. 真实同页帧

### 前提更正

`additional-paper-views.jpg` 的四张裁切图**不是一页四视图**（`pair-verification.json` 已记录）：new-1~new-4 是同一页旋转 −89.85° 的重复拍摄，new-2~new-3 是同一页尺度 1.096 的重复拍摄，两对之间没有内容对应（new-1~new-2 只有 2 内点）。因此本轮做的是**两页、每页 2 帧**，不是 4 帧堆栈。

| | pair-A（new-1 + new-4） | pair-B（new-2 + new-3） |
|---|---|---|
| 匹配 / 内点 / 内点率 | 714 / 422 / 0.591 | 240 / 118 / 0.492 |
| 旋转 / 尺度 | −89.853° / 0.998 | +0.459° / 1.096 |
| 重投影 RMS | 1.05 px | 1.85 px |
| 帧间曝光增益 | 0.8986（差 10.1%） | 0.9461（差 5.4%） |
| 空白区像素（占重叠） | 307,194（30.3%） | 588,222（44.5%） |

### 噪声：堆栈拿掉多少

| | pair-A | pair-B |
|---|---:|---:|
| 单帧 A 空白区 ink 标准差 | 0.01717 | 0.02215 |
| 单帧 B（重采样后） | 0.01541 | 0.01860 |
| 2 帧堆栈 | 0.01303 | 0.01781 |
| 标准差下降（相对单帧 A） | **24.1%** | **19.6%** |
| 方差下降比（理想 0.5） | 0.638 | 0.759 |
| 固定结构占比（由方差比反解） | **27.6%** | **51.7%** |
| 方差比推算 4 帧 / 8 帧 | 0.457 / 0.366 | 0.638 / 0.578 |

- 理想的“独立噪声”应让方差比趋近 0.5、标准差降 29%；实测只有 24.1% / 19.6%，**且 pair-B 有一半方差是固定结构**（透印、纸纹、JPEG 块、1.85px 配准残差）。
- 高频部分的方差比 0.585 / 0.645，比整体更接近 0.5：说明**真正独立的是高频噪声，低频“噪声”其实是固定内容**。这也解释了为什么堆栈对“空白区灰痕”帮助有限。
- 4/8 帧的数是**由 2 帧比反解外推**，不是实测；真实 4 帧还会受配准误差累积影响，只会更差。

### 代理指标（不是淡字真值）

`bookScreenshotProxy` 的原始口径需要“参考截图”来定义文字外空白区。对这两页**没有参考**：`probe_reference_pages.py` 把 new-1..new-4 与四张参考截图两两配准，最好只有 12 内点（阈值要求 ≥40）。因此改用**参考自由的空白区 + 同样的阈值读数**，并明确它是代理。

同一掩膜（`blank` 且单帧 A 判为 faint：ink∈(0.012, 0.20)，pair-A 80,524 px / pair-B 135,896 px），context-v2 的弱负排除率：

| 阈值 | pair-A 单帧A | pair-A 单帧B | pair-A 堆栈 | pair-B 单帧A | pair-B 单帧B | pair-B 堆栈 |
|---|---:|---:|---:|---:|---:|---:|
| 0.02 | 0.7937 | 0.9257 | 0.9249 | 0.8109 | 0.9338 | **0.9646** |
| 0.05 | 0.8589 | 0.9556 | 0.9605 | 0.8781 | 0.9640 | 0.9838 |
| 0.1 | 0.9013 | 0.9697 | 0.9797 | 0.9141 | 0.9779 | 0.9905 |
| 0.2 | 0.9327 | 0.9809 | 0.9905 | 0.9378 | 0.9868 | 0.9940 |

关键点：**单帧 B 本身就要高得多**，因为把 B warp 到 A 的几何时做了插值，插值已经平滑了高频噪声。所以“堆栈 vs 单帧A”的 13–15pp 提升里，大部分来自**重采样**，不是来自第二个帧：pair-A 堆栈 0.9249 甚至略低于单帧 B 0.9257；pair-B 堆栈比单帧 B 高 3.1pp。

这不是“多帧无效”的证明，而是“**两帧 + 1–2px 配准 + 10% 曝光差**的条件下，它给不出可用的余量”。

### B 的限制（必须一起读）

- **无淡字真值**：真实淡字的保留率本轮**未测**。上面全是空白区代理。
- **无参考渲染**：无法复用 `bookScreenshotProxy` 的原始空白掩膜；改用的掩膜来自图像自身的 ink 阈值，存在循环性（但用的是“远离深墨”的保守定义）。
- **样本是 2 页 × 2 帧**，不覆盖纸张、光照、书写工具的变化。
- **输入不是原始拍摄**：四张裁切图是应用自己的输出裁切（`pair-verification.json` 记录“source is the app's rectified camera crop”），长边只有 984–1319px，低于采集协议的 ≥2000px 目标，也低于检查脚本 1200px 硬线。它们很可能已经被应用的整流/增强链路处理过，所以本轮测到的不是原始传感器噪声地板，18–24% 的下降幅度不能外推到原片。
- 曝光差 10.1% / 5.4% 是实测的；对齐后 raw 与 normalized 的代理差异 <1pp，说明单靠增益对齐修不了主要问题。

## C. 采集协议

见 [`PAPER-CAPTURE-PROTOCOL-2026-11-04.md`](PAPER-CAPTURE-PROTOCOL-2026-11-04.md)。要点：≥5 页同一张纸，每页 `front_normal`（8 帧连拍）+ `front_blackback`（黑背无透印参考）+ `front_transmitted`（逆光）+ `back_normal`（翻面），三脚架、固定曝光/白平衡、关闭 HDR/降噪/数码变焦，长边 ≥2000px，严格命名 `<pageId>_<side>_<condition>_f<NN>`，交付 `manifest.json` 与（手写页）标注 JSON。

协议配套了 `multiframe/scripts/check_capture_set.py`：读交付目录，按命名契约分组，检查分辨率、每组帧数、帧间配准内点/RMS、帧间曝光增益、页数与缺项，输出 `capture-check.json`（0 error 才 `usable: true`）。已用私有 35 张图做过冒烟测试（全部命名不符 → 报警告；同一页两帧配准 611 内点 / 0.56px RMS；曝光差 30.9% → 报 `exposure-drift`），说明检查链路可用。

## 是否值得继续多帧方向

**不值得作为独立方向继续。** 理由按证据强度排序：

1. **上限被量化了**：把噪声与照明全部清零（`clean`）也只到 0.5063 排除 / AUC 0.9760。多帧能给的最好情形不会超过它；而门槛要 0.90。
2. **偏置项不可平均**：shade 偏置 0.00827 是每帧相同的光照场，独立噪声的堆叠对它无效；stable 场景下 8 帧均值把偏置从 0.00934 变成 0.00939（没动）。只有平场校正能动它。
3. **真实两帧只降 18–24% 标准差**，且固定结构占比 27.6%/51.7%；按反解外推，4 帧也只到 0.457/0.638 的方差比。
4. **收益落在抽样噪声里**：36 夹具 bootstrap 的 95% 区间大幅重叠。
5. **违约采集会变差**：handheld（±0.5px、±3% 增益、无补偿）8 帧反而比单帧差 0.14 排除率。

如果仍要在这个方向投入，前置条件必须同时满足（否则只是重复本轮的取舍）：

- **先做平场/照明校正**（它比多帧便宜、可测，而且直接消掉 0.00827 的偏置）；剩余地板再由多帧处理噪声。
- **≥4 帧、配准 RMS ≤0.5px、帧间曝光差 ≤2%**；这要求三脚架 + 固定曝光，即采集协议。
- **门槛本身需要重新审视**：在“钉死 99.99% 保留”下，透印 p90 与淡墨 p0.01 相差 72 倍；要么接受更低的保留率，要么引入振幅以外的证据（内容/几何），而不是继续加帧。

真正值得排在前面的顺序：**照明/平场校正 → 真实双面采集（协议 C）→ 多帧（作为前两者的附加项）**。这与 `PAPER-PAIRED` 的建议一致。

## 失败与限制（如实记录）

- **“四视图”前提不成立**：new-1..new-4 是两页各两帧，不是一页四帧。按 4 帧堆栈写报告会造假，本轮改成“两对 2 帧”。
- **`clean` 行存在域偏移**：context-v2 在带噪声数据上训练，零噪声输入属于分布外，所以它的钉死阈值（0.00095）不能与其它行直接比较；本报告用它的 **AUC（阈值无关）** 作为主证据，门槛读数只作参考。
- **stable 场景 4 帧 > 8 帧**（0.5614 vs 0.5475）是非单调的，符合“差异在噪声里”的解释，没有挑有利帧数。
- **2 帧时均值 = 中值**（数学上相同），表里两行数值一致不是复制错误。
- **合成帧模型不含**：固定图案噪声、JPEG 块、摩尔纹、局部散焦、纸张弯曲。这些在真实照片里是固定结构，会让多帧收益更差而不是更好。
- **真实代理指标有循环性**：空白区由图像自身 ink 定义，不是参考渲染。
- **私有冒烟测试目录**里有 35 张无关裁切图（含 old-*、workbook 等），只用于验证检查脚本能跑通，不代表交付集。
