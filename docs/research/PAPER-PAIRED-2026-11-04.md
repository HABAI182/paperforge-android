# 配对（正/反面）证据核查与双面模型可行性：第一步

2026-11-04。承接 `PAPER-MODEL-LAB-2026-11-03.md` 的结论（537 参数前景模型与 context V1/V2 无法同时满足“淡字保留 ≥99.99%”与“透印排除 ≥90%”），以及 `CAMERA-PAPER-2026-11-03.md` 的“尚未解决及下一实验”第 3 条（保留同一张纸的正/反/逆光/无透印参考，用真实留出页比较前景损失与灰痕残留）。

本轮只做可验证的第一步：**先查清手上到底有没有可用的“双面配对”证据**，再决定该不该往双面模型走；同时把手上唯一可用的真实留出页（25 组 DocUNet 相机照片 + 平板扫描）跑成真实指标，作为“真实前景损失 / 灰痕残留”的基线。没有接入产品，没有改 app 代码、模型资产、`scan_params.json` 或版本号，没有 git 写操作，没有 Android 构建。

## 结论先行

> **修正（同一轮内）**：初版只查了 `work/` 下的私有照片，漏掉了仓库内的 `bench-private/docunet`。那里有 25 组「同一页的两张 12MP 相机照片 + 平板扫描」，是**真实留出页 + 同页干净参考**。下面第 4 条与“真实留出页”一节是据此新增的；正/反面配对仍然不存在，双面区分度仍不可测。

1. **现有数据里没有真实的“同一张纸正/反面”配对。** `weak-pairs.json` 的四行是“应用输出的相机裁切图 ↔ 参考截图”，同一面、两种成像；`additional-paper-views.jpg` 是四张私有笔记裁切图（new-1..new-4）的拼版，其中 new-1/new-4 与 new-2/new-3 是同一页的重复拍摄，仍然都是同一面；`bench-private/docunet` 是同一页的两次相机拍摄，也不是两面。
2. `duplex-v1` 报的 `unverified-no-correspondence` 不是“双面不可行”的证据：按它记录的哈希，它比的 `new-1-crop.png` 与 `new-2-crop.png` 是**两页不同内容**的笔记，本来就不该有对应。该实验既没验证也没否证双面路径。
3. 因此**真实双面证据的区分度本轮不可测**（不是“测了不好”，是“没有可测的样本”）。为避免用合成分数冒充真实结论，双面路径只在生成器上做上限与代价测量，并逐项标注。
4. **但“没有真实页可测”这个判断是错的。** 用 25 组 DocUNet 真实页（20 组可配准）实测：context-v2 在阈值 0.02 下只保留 **71.5%** 的扫描真值墨迹、**52.5%** 的淡笔画，只清理 **40.4%** 的文档内灰痕。合成集上的 99.76% / 99.43% / 71.35% 不代表真实页；**真实瓶颈是模型在真实页面上的域差距，而不是合成门槛那条取舍曲线**。
5. 生成器上还有一条对“双面”更不利的数字：**即使把真实的透印图层精确减掉，也达不到门槛**（保留 0.9953 / 排除 0.7868）。瓶颈不只在透印，还在照明/底噪残差本身落进了“淡字”幅度带。这意味着**先做双面模型并不能解开当前这个门槛**，除非同时处理照明残差或改掉评估规则。
6. **和机主提供的竞品输出对齐后，差距的位置变了。** 在同一页上，竞品的空白区灰度是 255、灰痕层平均墨迹≈0；我们是 156–197、灰痕层 0.025–0.037（9%–16% 的像素仍可见）。而淡笔画保留我们并不比竞品差（1px 容差 94.5/83.6/99.9 对 96.2/98.1/100）。也就是说**要补的是“纸面白度 + 灰痕层”，不是淡字保留**——这跟“继续提高前景阈值”方向正好相反。
7. 基线复现是**逐位一致**的（下文表格全部 0 差异），所以后续所有对比都站在和 codex 相同的坐标系上。

## 配对数据核查

方法：SIFT（8000 特征、比值 0.72）+ RANSAC 单应（4px），比较匹配数、内点、恢复的旋转/尺度、配准后灰度与墨迹皮尔逊相关，并检查极性（是否灰度反转）。判定规则写在 `verify_pairs.py`：只有内点 ≥40 且内点率 ≥0.30 才算“共享书写内容”；本轮不相关配对上的偶然内点实测只有 2–8 个（匹配数 20–143），离阈值很远。

### `duplex-v1` 的“正反面”到底是什么

`duplex-v1/report.json` 记录的 `frontSha256=009f8bfb…`、`backSha256=962381ad…` 在本机全量哈希后，对应 `new-1-crop.png` 与 `new-2-crop.png`。而这两张是上表中内点只有 **2** 的不同页。也就是说 codex 当时的双面实验把两页不同的笔记当成了一张纸的两面；`correspondences: []` 与 `decision: unverified-no-correspondence` 是**预期结果**，不能用来评价双面路径的可行性。

**结论：可配准的配对清单只有“同一面的成对成像”（weak-pairs 四行、new-1/new-4、new-2/new-3）。真实正/反面配对：不存在。**

## 真实留出页：25 组同页相机照片 + 平板扫描

初版漏查了仓库内的 `bench-private/docunet`：25 组 `original/N_1.jpg`、`original/N_2.jpg`（3024×4032 相机照片）与 `scan/N.png`（同一页的平板扫描）。这不是正反面，但它是**真实页 + 同页干净参考**，正好补上原文档“只有一张可配准代码页，不能作为通用验收集”的缺口。codex 此前只用它测几何检测（`work/docunet-baseline/report.md`，模拟器上 20/20 返回四角），没有用它测前景或灰痕。

方法（`scripts/real_document_eval.py`）：扫描件先裁到墨迹外接框（否则扫描留白会把桌面/手/地板映射进画面，把背景纹理算成灰痕——初版就是这样错的，已修正），再 SIFT+RANSAC 配准进照片帧（长边 1400，内点 60–619，20/25 通过；弃用 6/10/11/15/21，内点 2–53）。掩膜定义：

- 正面真值 = 扫描墨迹 >0.15；
- 淡笔画 = 真值中照片墨迹 <0.06 的像素；
- 灰痕 = 文档内空白（离墨迹 ≥31px）且照片墨迹在 0.012–0.30 的像素。**这是“灰痕候选”，混合透印、纸张纹理、照明与配准误差，不是纯透印真值。**
- 另给 1px 容差版，避免把配准误差算成模型漏检。

阈值 0.02（括号内为 1px 容差）：

| 真实页（20 组，按像素汇总） | 正面保留 | 淡笔画保留 | 灰痕清理 |
|---|---:|---:|---:|
| context-v2 | 71.48%（82.41%） | 52.45%（69.08%） | 40.41%（30.76%） |
| 537 参数现有探针 | 54.48%（65.01%） | 23.44%（38.98%） | 87.32%（80.34%） |

阈值 0.1 与 0.5 也整段不接近门槛：context-v2 在 0.1 时 63.83% / 41.10% / 51.37%，在 0.5 时 54.40% / 28.65% / 64.94%（容差版 70.86% / 51.71% / 51.53%）。现有探针反过来：淡笔画越保越少、灰痕越清越多，但正面保留只有 50% 上下——**它就是“靠多擦”换来的灰痕数字**，这也解释了它在合成集上 92.4% 的透印排除率。

逐页离散度（context-v2，t=0.02，1px 容差）比均值更重要：

| 指标 | 最小 | 中位 | 最大 |
|---|---:|---:|---:|
| 正面保留 | 61.19% | 90.13% | 99.95% |
| 淡笔画保留 | 48.54% | 81.11% | 99.84% |
| 灰痕清理 | 0.00% | 36.44% | 84.38% |

三件事由此确定：

1. **合成门槛不是真实瓶颈。** 合成 99.76% 的正面保留在真实页上掉到 71.5%；淡笔画 99.43% 掉到 52.5%。真实域差距比“淡字 vs 透印”的取舍大得多，先扩前景分割不会先受益。
2. **单页结论不可外推。** 灰痕清理逐页从 0% 到 84%，同一模型在不同页上表现差一个量级，任何“某页从 X 改善到 Y”的陈述都需要逐页给出并注明页数。
3. **灰痕带并非纯阴影。** 灰痕带的高频占比相对真实笔画为 **0.74**（0.359 vs 0.534），即它带有笔画级细节，符合薄页杂志的透印/透字特征；但它仍混有纹理、照明与配准误差，不能当纯透印真值，也不能据此断言“灰痕=透印”。

同页两次拍摄的一致性（11 对可配准，`N_1` vs `N_2`）：灰痕带灰度相关中位 **−0.001**（范围 −0.085…0.142），但同一批真实笔画的相关中位只有 0.322。**仪器不足**：真实笔画的相关都只有 0.32，说明 4px 单应 + 纸张弯曲留下的局部错位与两次曝光差异已经吃掉大部分结构，此时灰痕的零相关无法与“配准误差”区分。因此这一项**不作为灰痕不可重复的证据**，只记录为被否决的仪器。

## 竞品 reference 对照：目标长什么样、差在哪

机主此前提供的三元组正好齐了：**原图**（`behavioral-v1/device/notes-1..3.jpg`，即竞品 refer 目录里的那三张 1279×1706 照片）、**竞品输出**（竞品导出的 PDF 第 1–3 页渲染成 `behavioral-v1/notes-N-reference.png`）、**我们自己的输出**（`old-N-crop.png`；book 页用 `feedback-20011/v4/.../book-crop.png`）。把三者用 SIFT 配准到竞品的页面坐标，竞品输出就变成**目标**：竞品为空白、原图却有可见痕迹的位置，就是目标清掉的东西；竞品保留的笔画，就是目标保住的内容。

这是**目标**，不是逐像素真值：竞品的渲染、水印（book 页可见其 logo）与几何来自另一套引擎，可能过度清理。

| 指标（3 页：notes-1、notes-2、book） | 竞品目标 | 我们的输出 |
|---|---:|---:|
| 空白区平均灰度 | 254.90 / 254.99 / 255.00 | **155.63 / 176.40 / 197.16** |
| 空白区近白（≥250）比例 | 100% / 100% / 100% | **0.11% / 6.87% / 0%** |
| 灰痕层平均墨迹 | 0–0.00005 | **0.0250–0.0366** |
| 灰痕层“仍可见”（墨迹>0.05）比例 | 0% | **9.05% / 14.76% / 15.98%** |
| 内容保留（竞品保留处，我们墨迹>0.03） | 100%（定义上） | 54.49% / 61.56% / 91.01%（1px 容差 67.30% / 71.15% / 94.61%） |
| 淡笔画保留（1px 容差） | 96.2% / 98.1% / 100% | 94.45% / 83.59% / 99.86% |

（notes-3 的原图配准失败——只有 11 个内点、34 个匹配——因此排除；3/4 页可用。）

![整页三列对照：原图 / 我们 / 竞品目标](work/model-lab-20261103/paired-frontback/results/competitor-reference-fullpage.png)

由此得到三个可以直接用来定目标的结论：

1. **差距不在淡字，而在灰痕与纸面。** 淡笔画保留我们并不比竞品差（1px 容差 94.5/83.6/99.9 对 96.2/98.1/100），但灰痕层我们留下 0.025–0.037 的平均墨迹、9%–16% 的像素仍可见，而竞品在同一位置基本为 0；空白区平均灰度我们 156–197，竞品是 255。
2. **竞品的目标本身是“低对比”的。** 它自己的淡笔画也有 1.8%–33% 掉到 0.03 以下（strict 保留 66.8/69.4/78.4%），说明**直接把竞品输出当训练目标会把淡字一起压掉**。可以用它定“灰痕与白度”的目标，不能单独用它定“淡字保留”的目标。
3. **内容保留只有 55%–91%**，1px 容差抬到 67%–95%，其中相当一部分来自配准误差（竞品页面与我们的裁切几何不同）。这一项在掩膜定义固化之前不宜当模型指标。

这三页的对照还解释了机主最初的抱怨：notes-1 原图右半页有大量**镜像的透字**，我们输出把它们当淡字保留了，竞品则清掉——正是“淡正面 vs 反页透字”这个分离问题，只不过现在我们有了同一位置上“该清/该留”的真实参照。

## 模型优化尝试：ghost-v1 / ghost-v2

目标改成对齐竞品后，做了两个候选（都是 36,665 参数同构，权重只在仓库外）。监督信号**不取竞品渲染**（它会压掉淡字），而取**同页平板扫描**：扫描无墨而照片有墨的位置，就是应该被清掉的灰痕层。

- **ghost-v1**：以 context-v2 预热，19 张 DocUNet 真实页（1400 配准、1000 平面）+ 程序化淡字夹具，3000 步。
- **ghost-v2**：在 ghost-v1 上继续 1500 步，并在真实页patch上叠加**镜像模糊透字增强**（`fliplr` + 高斯 σ1.5–4.5 + 增益 0.15–0.55，概率 0.6），因为平板扫描语料里没有机主这种“镜像手写透字”。

验收（`accept_candidate.py`，把模型提议 `1 - ink×score` 渲染后与竞品目标同掩膜比较，3 页均值）：

| 指标 | 竞品目标 | context-v2（预热） | ghost-v1 | ghost-v2 |
|---|---:|---:|---:|---:|
| 灰痕层“仍可见”比例 | 0% | 7.59% | 8.22% | **6.63%** |
| 灰痕层平均墨迹 | 0.00003 | 0.0189 | 0.0186 | **0.0158** |
| 灰痕清理（1px 容差） | 100% | 87.20% | 87.48% | **89.32%** |
| 淡笔画保留（1px 容差） | 98.11% | 93.09% | **93.99%** | 92.56% |
| 内容保留（1px 容差） | 100% | 72.75% | **73.55%** | 72.58% |
| 空白区平均灰度 | 254.97 | 254.49 | 254.46 | 254.45 |

DocUNet 留出页（13/14/20，含墨迹判据）上差异更明显：ghost-v1 把内容保留从 0.695 提到 0.898、灰痕平均分从 0.463 降到 0.347；ghost-v2 更激进，灰痕再降到 0.212，但内容保留回落到 0.751。**这是一条取舍曲线，不是双赢。**

结论要如实说：**还没有到位。** 相对 context-v2，ghost-v2 把灰痕可见比例压了约 13%，代价是淡笔画 −0.53 个百分点、内容保留 −0.17 个百分点；离竞品的 0% 仍差 6.6 个百分点。改进方向是“清得更狠但代价更小”，而现在的曲线每清 1 个点要付出约 0.1 个点的淡字。

另外两项结构性发现，决定接下来该改哪里：

1. **纸面白度不是模型的锅。** 模型提议的空白天区灰度已经是 **254.45–254.49**（竞品 254.97），但机主看到的我们输出是 **156–197**。说明差距发生在渲染/色调环节，不在前景模型。
2. **全局白点拉伸补不回来。** 对我们的输出做 p99/p97 白点拉伸，空白区灰度只从 176.4 抬到 191.5（p99）/191.9（p97），离 255 仍远——灰度里有一层**局部阴影/照明**，需要局部背景归一化，而不是一个全局增益。

## 双面证据的区分度

由于没有真实正/反对，真实数字只有一条：**不可测**。下面全部是**生成器上的**测量（`train_paper_context.fixture` 同分布、留出、种子 811735、100 个夹具；正类 = 正面真值 162,520 像素，负类 = 仅透印 193,611 像素；淡墨子集 36 个夹具、63,831 / 63,602 像素）。所有数字都带“合成”标签，不能当作真实文档结论。

生成器副本先做了逐位等价校验（15 次抽样，`ink`/`truth`/`negative`/`contrast` 全等），否则任何数字都不可比。

### 1. 正/背在同位置的相关性

生成器里正反面是独立随机书写场：正面真值像素中仍有 **26.46%** 同时带 >0.012 的透印（p90 = 51.94%）。这就是“同一位置正/背灰度相关”的上限约束——背部信息与正面信息在位置上大量重叠，**知道背面并不等于知道该像素有没有正面淡字**。

### 2. 阈值无关的可分性（AUC，正类=正面淡字，负类=仅透印）

| 单图证据 | 全部夹具 | 仅淡墨夹具 |
|---|---:|---:|
| 墨迹幅度（ink） | 0.7824 | 0.5753 |
| 墨迹梯度 | 0.7518 | 0.6112 |
| 墨迹“尖峰度” ink/blur(ink,2) | 0.7544 | 0.7006 |
| **完美背面证据（−透印真值）** | 0.8685 | 0.8690 |
| **context-v2 前景分数** | **0.9847** | **0.9629** |
| 537 参数现有模型分数 | 0.8161 | 0.6631 |

两点值得记：

- 单图幅度类证据在淡墨夹具上接近随机（0.575/0.611），与“继续调阈值只是取舍”的既有结论一致；纹理类（尖峰度 0.7006）比幅度好，但仍远不够。
- **完美背面证据只有 0.869，低于 context-v2 的 0.963。** 在生成器上，背面信息作为“逐像素判别证据”比现有单图模型还弱，因为它对 26% 的重叠像素一律判“有透印=不是淡字”。所以双面证据只能当**减法**用，不能当分类器用。

### 3. 门槛点的位置（不用挑阈值）

门槛要求淡字保留 99.99%，这就把阈值钉死了；此时透印还不被清理的比例就是唯一要看的数字（门槛允许 10%）：

| 证据 | 钉死阈值 | 淡字保留 | 透印仍通过 |
|---|---:|---:|---:|
| context-v2（全部正类） | 0.00352 | 99.99% | **47.7%** |
| context-v2（淡墨夹具正类） | 0.00281 | 99.99% | **50.2%** |
| 完美背面证据 −透印 | −0.173 | 99.99% | 99.9% |
| 墨迹幅度 / 梯度 / 尖峰度 | ≤0.037 | 99.99% | 100% |

要过门槛，同样 99.99% 保留下透印通过率得从 ~48–50% 降到 10%，也就是这个错分尾部要缩小约 **5 倍**。AUC 0.963 到“能在 99.99% 处做到 10%”仍有实质差距，但这不是“再调阈值”能补的（曲线已给出整段取舍），也不是“改双面”自动补上的（见下）。

### 4. 完美双面减法的上限与代价

把生成器里真实加入的透印图层精确减掉，再按训练真值规则 `max(0.004, contrast×0.10)` 判定：

| 配准误差 | 增益误差 | 模糊失配 | 淡字保留 | 透印排除 |
|---:|---:|---:|---:|---:|
| 0 px | 0% | 0 | 0.9953 | 0.7868 |
| 0 px | 0% | σ=1 | 0.9940 | 0.7587 |
| 0 px | +10% | 0 | 0.9904 | 0.8506 |
| 0 px | +25% | 0 | 0.9786 | 0.9037 |
| 1 px | 0% | 0 | 0.9905 | 0.7434 |
| 2 px | 0% | 0 | 0.9838 | 0.7053 |
| 4 px | 0% | 0 | 0.9710 | 0.6384 |

30 个配置里**没有一个同时过两道门槛**（`passBothGates = 0`）。而且即使在“零误差、有完美透印图”的理想情形：

- 淡字保留 0.9953 < 0.9999，损失来自正向饱和裁剪；
- 透印排除 0.7868 < 0.90，因为减掉透印后的残差里，**照明/底噪（shade 最大 0.07、噪声、±0.0025 高斯）本身就高于 0.004–0.10 的真值门限**，于是“已经清干净”的像素仍被判成有墨。

这条最关键：**光有双面证据不够，残差地板（照明/噪声）会先把门槛占满。** 双面路径若要做，评估与模型都得同时给出残差地板项，否则再好的透印图也过不了这个门槛。配准误差的代价也很明确：1px 已让排除从 0.787 掉到 0.743，4px 掉到 0.638。

## 失败与被否决的记录

- **淡墨富集探针被否决。** 曾想用“正面淡墨层是否落在背面墨迹位置上”做富集比（含随机位移空分布）。它没有通过自己的正对照：同一页两次拍摄（new-2~new-3，118 内点）富集 0.96，低于随机位移的 P95 1.21；而不同页对照（book~math）反而给出 2.03 的假阳性。仪器不可信，因此**不从中得出任何结论**，只把数字留在 `pair-verification.json` 供复查。
- `verify_pairs.py` 首版把单应方向写反（用 A→B 的矩阵去 warp B），导致同页配对的灰度相关接近 0；修正为 B→A 后才得到 0.29/0.61/0.79 的合理值。首版的判定也把“偶然内点”写成“共享内容”，已改用内点数+内点率阈值。这两处是真实 bug，不是数据问题。
- `duplex-evidence` 首版把“正类/负类”池接错（`KeyError`），以及画图脚本把同一个数值同时映到 x、y 轴，均已修正后重跑；下图与 JSON 是修正后的产物。
- 生成器上的“双面”结论都是**合成**的；它既不能证明真实纸面可减，也不能证明不可减。真实纸面的透印是非线性的、空间变化的，而且正面墨会遮挡背面信号，这些都没建模。
- **`real_document_eval.py` 首版灰痕掩膜被背景污染。** 扫描件含大片白色留白，单应把留白映射到桌面/手/地板，`ink` 落在 0.012–0.30 带的背景纹理被当成灰痕（面板图可直接看到键盘、手掌、地板）。改为先把扫描裁到墨迹外接框后重跑；**上面所有真实页数字都是修正后的**。修正前后汇总值变化在 1 个百分点内，但逐页污染程度差别很大，旧的逐页结论作废。
- **同页双拍一致性被否决。** 真实笔画在两次拍摄间的灰度相关中位只有 0.322（4px 单应 + 纸张弯曲），仪器分辨不了灰痕的结构，故“灰痕不可重复”这一说法不成立也不否证，只记录仪器失败。
- **本轮初版对可测数据的判断也是错的。** 初版只扫了 `work/`，漏了仓库内 `bench-private/docunet` 的 25 组真实页 + 平板扫描，才得出“没有可测的真实页”。这一条按修正后的真实评估重写；教训是查语料要连仓库内 `bench-private` 一起查，而不是只看 `work/`。

## 对“下一步”的建议

1. **先把目标定在“纸面白度 + 灰痕层”，不是淡字保留。** 竞品对照已给出可直接验收的数字：空白区平均灰度 255（我们 156–197），灰痕层可见比例 0%（我们 9%–16%）。建议把这两项写进下一轮验收表，同时保留“淡笔画 1px 容差保留率不低于竞品”这条不倒退约束。
2. **把竞品输出用成目标，但不要单独拿它训练。** 竞品自己的淡笔画也有 1.8%–33% 掉到 0.03 以下；直接当标签会把淡字一起学掉。可行用法是只用它定义“灰痕/白度”的目标区，淡字区仍用弱标签 + 真实页淡笔画掩膜。
3. **先把真实域差距当成主线。** 真实页上 context-v2 的正面保留只有 71.5%、淡笔画 52.5%，而合成集是 99.76% / 99.43%。在补这个差距之前，任何“淡字 vs 透印”的取舍讨论都是在合成分布内自转。建议先用现有 20 组真实页 + 平板扫描做逐页误差归因（配准 vs 墨迹估计 vs 模型），再决定改数据、改特征还是改模型。
4. **真实集要按页报告、给出页数。** 灰痕清理逐页 0%–84%，中位仅 36%，单页数字不足以支持任何普适结论；先把验收集扩到 `bench-private/docunet` 的 50 张照片与全部 25 张扫描，并固化掩膜定义。
5. **暂不扩大前景分割。** 合成上单图最强证据在 99.99% 保留处错分 48–50%，真实页上更差；更大的同结构卷积没有任何证据能补这个量级。
6. **若仍要做双面，先补真实双面采集。** 最小可用集：≥5 张纸，每张拍正面 / 反面 / 逆光（背光透射）/ 无透印参考；标注淡字、标点、公式与空白区；并满足配准 ≤1px、增益 ≤10%，同时显式处理照明/底噪残差，否则门槛在数学上不可达。
7. **复核现有弱标签用途**：notes-3 只有 89 内点、墨迹相关 0.149，若继续当 holdout，其“99.99% 弱正保留”不宜当作强证据；建议把配准质量写进每个 holdout 行的可信度列。
8. **纠正 duplex-v1 的结论表述**：它是“两页不同内容”的对照，不能作为双面可行性的负证据；文档里应改成“输入不成立，未验证”。
