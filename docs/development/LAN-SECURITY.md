# 局域网传输协议 v2

## 信任与加密

- 仅监听 HTTPS；不提供 HTTP 回落。允许 TLS 1.2/1.3，使用 TLS 1.3 AEAD 或 ECDHE + AEAD 密码套件。
- 手机在 AndroidKeyStore 创建独立 ECDSA P-256 签名密钥，不导出私钥；证书指纹跨服务重开保持不变。首次创建/更换身份时撤销旧配对，避免沿用曾经通过 HTTP 传输的凭据。
- 本地证书没有公共 CA 背书。**首次连接必须在浏览器证书详情中读取 SHA-256，与手机界面逐组核对，一致后才继续。** 不一致就停止连接；不能仅相信网页自己显示的指纹。浏览器手动信任/例外不等于自动身份认证，必须先完成这一步。
- 二维码/复制链接的 fragment 带配对 nonce 与预期证书摘要；fragment 不随页面请求发送。页面核对预期身份、显示说明并要求明确确认，再发配对请求。手输八位配对码也必须先核对浏览器证书。
- 手机和随包浏览器页面清晰显示 HTTPS 保护。浏览器无需安装全局根证书，应用没有关闭系统 TLS 校验；只有测试客户端按预期证书精确绑定测试服务。

身份核对完成后，TLS 保护传输中的文件、文件名、请求路径、Cookie 及配对码，包含上传、下载、JSON 状态、Range 与续传请求。它不保护已被控制的手机/浏览器，也不替代用户对首次证书身份的核对。

## 配对及会话

`GET /api/hello` 返回协议号、证书摘要与服务器时间。`POST /api/pair` 要求当前 nonce/配对码、证书摘要和身份确认标记；沿用五分钟票据、失败次数限制及成功后轮换。

会话仅保存随机 token 的 SHA-256 摘要；Cookie 限定 `Secure; HttpOnly; SameSite=Strict`，30 天失效。服务器同时检查有效期，不依赖 Cookie 自行过期；撤销会话立即关闭该设备的活动连接。浏览器配对过期后需重新配对。

认证 API 附加一次性 `X-PaperForge-Request-Id`（128 位随机）与 `X-PaperForge-Time`；服务端拒绝重复及超出五分钟窗口的请求。每次服务开启生成独立 epoch；认证 API 必须绑定当前 epoch，旧服务的请求不能直接在新服务重放。已用标识保存十分钟，缓存满时拒绝新增而不提前驱逐。客户端按 hello 响应校准时间偏差。重试生成新标识，业务续传仍使用实际文件 offset 与 SHA 校验。

普通浏览器下载不能附自定义请求头，因此文件下载依赖 HTTPS 记录认证、会话 Cookie 与权限检查，继续支持原有 Range 续传；不生成会破坏续传的一次性下载链接。API 的重复请求保护与 TLS 记录完整性是不同层次的检查。

浏览器跨来源请求按 Origin/Host 拒绝；静态页面沿用严格 CSP、无跨域授权和无第三方脚本。浏览器页面不用自制加密算法，不传输私钥。

## 兼容性

- 协议 v1 HTTP 地址及配对不继续受信任；用户从手机复制新的 HTTPS 地址并重新配对。队列对象和断点文件保留，新 HTTPS 会话正常暂停/续传。
- 证书有效期十年，身份失效/更换后需重新核对；旧身份的配对一并撤销。
- 发布版 1.0.1 仍为旧 HTTP 实现；本文描述后续主分支，不能将旧安装包误称为加密版本。

## 协议依据

AndroidKeyStore 密钥与证书参数采用 [Android KeyGenParameterSpec](https://developer.android.com/reference/android/security/keystore/KeyGenParameterSpec)；TLS 记录认证和重放边界参照 [RFC 8446](https://www.rfc-editor.org/rfc/rfc8446)。本应用不启用 TLS 0-RTT 业务请求。
