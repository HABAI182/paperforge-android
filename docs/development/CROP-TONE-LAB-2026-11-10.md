### 实际生产 Kotlin 检测链路

`build_crop_jvm.py` 编译生产检测源码副本并执行 PageNet、CoverOutline、TopSheetRules、DocumentDetector.refine 及已启用的后处理；使用 Java ORT 1.22 / Windows OpenCV 4.9，Android 为 4.12。57 张执行、54 张计分，均保留 720 / 2000 的四角与逐阶段时间。当前资产中 `edgeQuad`、`ruleFrame`、`sheetEdge` 均为 0，不把未启用的重处理当作实际性能瓶颈。这仍不是物理手机 CameraX 测量。

|---|---:|---:|---:|---:|---:|---:|---:|
| 发布版 / recovery 320 | 0.91430 | 0.94884 | 0.94568 | 0.97834 | 0.90719 | 0.90246 | 90.16ms |
| 发布版 / recovery 224 | 0.91237 | 0.94485 | 0.94568 | 0.97834 | 0.90719 | 0.89958 | 64.30ms |

224 恢复把总体桌面时间降低约 29%，但 14_1 IoU 由 0.67706 退为 0.62513，不全局替换。v5 对部分机主照片有提升，却在 10_2 将木纹并入纸面，IoU 由 0.9616 降为 0.2794；蓝封面纳入了右邻练习纸。已查看三列边界联系图，不以少数页面变好作为合格证据。

后续改试保持 recovery 320、核 9、固定 RNG 0，仅将 GrabCut 的 3 次迭代改为 2 次：54 页 IoU 0.914300→0.914666、覆盖率 0.948843→0.949127，三组机主照片 still 四角逐页完全不变；33/54 页四角完全相同。DocUNet 最差 IoU 回退为 3_2 的 -0.001765（四角约 0.16～1.67 像素变化），最大移动 17_2 的约 36 像素则是向真值改善。已看对照图，尚未做逐字符人工验收。桌面 still 均时约 90.16→74.82ms、720 均时 77.62→64.36ms；分次运行存在主机负载影响，不作为手机提速承诺。

这项较稳妥的改动已在本地提交 `10e3f6b`，增加 `pageNetRecoveryIterations=2` 可扫参，保留原分辨率和模型。该新参数只影响保存 crop 之前的检测，明确排除在 appearance fingerprint 外，避免为这项提速让所有历史 flat 页面重新增强；实际旧类、无新键、新键为 2/3 的指纹相同，而修改 appearance 参数会改变指纹。真实新 ScanParams 与 PageNet 源码已定向编译，合同通过，没有为此重复整套模型基准。

局部 native 角点模型 v2 在已存实际生产四角上比较 heat-peak / mask-intersection 两个固定解码器，均为 0/216 角采纳：presence 最高仅约 0.776，固定门为 0.9，mask 两边交点证据亦不足。额外桌面开销约 4.53 / 5.09ms，不能把“结果不变”称为提升。没有根据机主真值放宽门槛。

## 已执行的不同策略

- **全局四角头**：复用 PageNet，保留 mask / boundary 两通道，增加四角热力图。12,000 张新合成图、480 张独立种子验证、6,000 步训练；机主照片无梯度训练。真实表现如上，未接入。
- **冻结已有网络**：完整冻结发布版编码器、mask / edge 头及 BatchNorm，只训练新的空间四角头，防止破坏现有分割。合成定位不足，未接入。
- **局部源边缘拟合**：沿四边取法向梯度与内外材质变化，分布支持与 Huber 拟合排除短遮挡。全量 IoU 0.89267，七图却从 0.94633 降为 0.94220，且额外约 31ms 桌面处理；未接入。
- **完整四边形联合评分**：新增 `stable_quad_fit.py`，比较所有有限四边形提案的软 mask 覆盖与 boundary 支持，检验能否避免“第一个满足 epsilon 的四边形”造成跳框；结果单独记录，不冒充已提升。
- **局部角点网络**：`train_crop_refiner.py` 保留全局选纸，只对四个定向源图小块精修，并训练角点存在性。它与全局替换属于不同实验，精度、额外延迟和拒绝情况须分别验收。

### 合成标签修正

审计发现新增实验最初将 `paste` 的变形前控制四角当作训练标签；`curl` 对纸张做了正弦重映射，实际纸角并不仍在原坐标。这是**本轮新增实验标签的问题**，不是发布版 PageNet 的标签变更。随后也修正了镜像和热力图的像素中心约定：训练用 `(pixel+0.5)/size`，转换到已有 Quad 端点约定时用 `(u*size-0.5)/(size-1)`，避免一像素标签偏差。

`page_scenes.curl(..., with_corners=True)` 现反求重映射的源纸角，再投影到场景。原有三返回值接口和默认生成图不变。旧标签实验保留作失败记录；第三轮已主动停止，写入 `corners-v3-replay/ABORTED.json`。新训练明确要求 `cornersDefinition=post-curl-projected-pixel-centres`，拒绝无声复用旧标签缓存。确定性检查已通过：80 个 curl 样本和 72 个完整场景的图像、mask/alpha 与 RNG 结束状态全部一致；角点逆映射最大残差 3.42e-5 像素。已看 12 张角点联系图。校正后的数据含 12,000 张 mixed 场景，另存 native 分辨率角点小块。v5 采用发布版 teacher 约束及相邻输入噪声一致性，6,000 步约 628 秒，权重 SHA256 `61a59eca432108f63e93a2102625504a82074e0db753e1c0192446798c088eae`；结果仍未合格，说明修正标签不等于解决真实场景泛化。

### 公开实拍域适配

完整审计后保留 1,037 张唯一图，隔离 338 个重复副本、3 组同图却角点冲突的记录，以及 52 个越界、非凸/自交或面积低于本实验 0.02 门槛的配对（后者不全是源数据错误）。CSV 在 EXIF 转正后的显示空间，不是原始 JPEG 的宽高：已核实 3/6/8 与无旋转样本，不能直接忽略 EXIF。常用环序为 TL/TR/BR/BL，manifest 坐标定义为像素 / `(W-1,H-1)`；训练 mask 与 decoder 则明确转换到 half-pixel 的 edge-normalized 约定。

同编号、exact-image alias、每 20 连续编号与旋转感知的 rectified pHash/dHash 近重复合并为 37 组；77 个近重复候选均在同组。人工看过跨组候选，包含同封面转 90/180 度的照片，单纯未旋转的 dHash 会漏掉。真实物理文档身份没有提供，分组只能减少、不能证明完全消除内容泄漏。最终 grouped manifest SHA256 `32253e88d4e73ff36d601f0e0979c3f0b6209004ca106c1154f6cc9f1ace8c60`。

`train_page_domain.py` 复用发布版的两通道 PageNet，冻结 BatchNorm running statistics，以半批公开真实照片、半批 procedural replay 训练，并只在 replay 上加冻结 teacher 约束。870 张训练、167 张独立分组验证；机主照片不用于训练或 checkpoint 选择。第一个未完成预处理在获得更保守的旋转分组后停止，未开始梯度训练；最终 `domain-v2-grouped` 才是有效实验。6,000 步约 463 秒，公开验证基线 mask-quad IoU 0.78726，选择的 3,000 步 checkpoint 为 0.89345；这是新的公开集、PC mask 解码口径，不能与上表完整 Kotlin 的 54 页均值直接混比。

公开域适配 v2 权重 SHA256 `b9db5230b83da61631bb635bcbffc29249750e9c145316505ef4d84206066552`。随后在相同 iter2 配置的实际 Kotlin 路线评估，54 页 IoU 却由 0.914666 降为 0.907943，角平均误差由图像对角线的 1.479% 升为 1.640%。blue-book / notes-left / math-booklet 分别回退约 0.154 / 0.149 / 0.067；已目视确认是收入邻纸或顶边误裁，置信度反而变高，不能仅用高置信度挑新模型。称作 CS33 的额外样本实际只有一图，并非 33 张；单独追加后 IoU 也由 0.968738 降为 0.957971。v2 保持离线，没有替换应用资产。

下一轮 `domain-v3-edge` 使用同一公开分组缓存，只训练最后一个高分辨率 decoder 与 mask/boundary head（2,602 / 262,354 参数），冻结其余权重和全部 BN running statistics，避免继续全网适配。训练末尾会核对冻结 state 逐值相同；这不等于保证输出选纸不变，仍须用真实照片验证。已做参数清单及有意修改冻结权重/BN 的 guard 检查，4,000 步实验正在执行。`--prepared` 校验 manifest SHA 后复用数据，避免重复读图；AMP 跳过溢出梯度时也跳过 scheduler 更新。

## 透印：先核对真正的处理路径

默认练习册主路径是 `EnhancePipeline.lightFirstPage → PaperField.edgePreserving → ToneZones.apply`，通常会在旧 PaperGhost 路线之前返回。只调旧模型无法说明主路径已修复。

`build_tone_jvm.py` 编译实际 ToneZones v29、PaperField、ParallelFilter 等源码，配少量平台 stub 在桌面执行；使用 OpenCV 4.9，Android 是 4.12，桌面时间不当作手机时间。八页诊断插桩前后 PNG SHA256 完全相同。它验证的是实际 tone 阶段，不包含整个 Android 导入、外缘处理和导出。

`train_source_ink_guard.py` 用独立合成的正/反面、汉字、英文、公式和淡墨训练源证据模型，限制低置信区域被曲线加深。控制合成曲线中，逆透暗度增量从约 0.0894 降为 0.0238；**这不是实图改善证据**。实图无保护应用会压淡弱笔画/线，保护后不少页面零改变，因此不能接入或宣称解决。

实验指标已单独修正于 `56c5fe0`：置信阈值计数不再命名为“未增强透印”，固定 `.35/.85` gain-bound 统计从阈值扫参表拆开；`min(source, existingTone)` 下界只是构造不变量，不冒充真实字符保留率。旧报告保留，没有重新训练或编造缺失逐像素统计。

另实际执行缓存的 Apache-2.0 bleed-through-cleaner 两个公开 checkpoint：原 Conv/BN/attention/transposeConv 架构 strict 加载全部 255 个 state tensor；400 输入不触发 torchvision 的 resize 分支，适配仅去除未用 import 并设置调用即失败的守卫，未伪造层或装全局依赖。10 个实际 ROI × 两个 checkpoint 的桌面推理及输入等价检查完成。较好的 finetune 模型仍误拒合成已知浅正面字约 34.85%，去除 64px 边界和 ruling 带后仍为约 31.2%；真实书页中央也压淡有效暗像素。因此不接入、不把局部变白当作成功。下一步转向许可明确的真实配对前景监督，而不是继续套用会伤浅字的权重。

参考图配准仅是弱代理。光流残差大的区域不得当作逐像素真值：须列出支持/循环一致性有效像素、远离正文的背景区，并检查代码小字、公式、标点和弱线。已有八图未完整复现“非常浅透印被加黑”的反馈，还需从当前新照片与实际源尺度找到反例，而不是在不相干的干净图上宣称成功。

## 预览与最终裁切的已知差异

审计在当前代码中发现：实时框有平滑与缓存；快门采用 raw quad；稳定帧可能重复推理；still 路线另有纸边恢复与细化；渲染时 ContentCrop 还可能扩大边界。模型准确度实验不能替代这些链路的一致性修复。后续需对同一源帧复用一次推理、统一坐标及最终裁切几何，避免只让框看起来稳定。

本轮已在本地提交 `b605db4`：live 每帧只执行一次生产检测，不保留跨帧三秒的旧四角；canonical reference 保存当前实际显示框，匹配签名也从相同框采样；过期、移动和场景变化仍重新检测；旧任务默认非 canonical，保留原处理。OutlineTracker 的 coast/pending 状态不能作为当前锁定框，CameraX 尚不能映射 overlay 时也不建立 canonical 承诺。去掉了 Canvas 的第二层 screen-space spring，保留 OutlineTracker 平滑，避免实际画出的动画中间框与快门保存目标框不同。没有改动页面布局。

明确锁定且匹配的 frame 跳过第二次 still / refine / outline，持久化 `capture.exactFrame` 防止 render 和 flatten 准备时偷偷扩边。内部展平仍是 warp grid，不能宣称最终像素仅做四点单应。20 项相关 JVM 单元测试零失败，最终生产与 AndroidTest Kotlin 编译通过；实际序列化/旧 payload/metadata 经 dewarp→sourceAppearance 保留合同通过；实际 Mat 路线 6/6 次检查均为每次恰好一次 Learned 调用、与 canonical 路线四角完全一致。无设备，新增 Android 的同源标记像素、匹配/过期/解锁仪器测试仅编译，尚未运行；物理手机 CameraX 帧同步、实际速度和画框观感仍待验收。
