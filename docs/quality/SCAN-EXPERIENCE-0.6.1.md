# 0.6.1 扫描检查与界面改进

## 触发问题与改动

扫描完成进入 `EditorScreen`，不是已有左右翻页的 `ReaderScreen`。旧编辑器的预览固定为 280dp，名称输入、多个工具行、滤镜和页条长期占位。本版拆出 `ScanEditorLayout` / `ScanPageCanvas`，画布占剩余空间，左右切页，双击或双指缩放 1–5 倍，放大时优先平移；回到原比例继续翻页。全屏隐藏系统栏和编辑工具，点击或返回即可退出。名称改为点按修改，滤镜/缩略图按需展开，重拍、旋转、页管理、删除和撤销仍可访问。

回收站统一为首页/文档/工具顶栏的固定入口；进入后有独立标题和返回文档按钮，不再混在收藏筛选项里。保留批量恢复、移入回收站和直接删除。首页移除宣传卡、搜索置顶、扫描悬浮按钮；文档卡片显示实际首页缩略图，缓存随修改失效。视觉增加统一 Typography / Shapes、语义表面、警示色、数字字形、动态配色与纯黑主题。

## 增强

修复 `CLEAN` 原本落入灰度分支的问题，去阴影保留彩色内容。`AUTO`、`TEXT`（清晰）、`COLOR` 使用不同强度的亮度局部对比与阈值锐化，色度单独保留；自然、去阴影、灰度、黑白、白板仍可选。对比原图保持同一裁边和旋转范围。

局部对比参考 [OpenCV 的 CLAHE 官方说明](https://docs.opencv.org/4.13.0/d5/daf/tutorial_py_histogram_equalization.html)：使用限制对比的局部处理，避免直接套用全局直方图均衡。此处参数及亮度融合/锐化为本项目实现。现有 CamScanner 来源边缘和曲面模型保持原样；本次查看提供的逆向成果，其 README 明确 Java 业务层仍受加固、部分功能只有线索/伪代码，没有把未验证伪代码宣称为完整私有增强源码。

新增“更多 → 保存本页诊断包（含原图）”：ZIP 包含原图、增强结果、坐标、滤镜、检测来源与评分、设备信息、解码/检测/渲染耗时、当前 Java/native 堆占用及系统热状态。只在手机本地生成，不自动上传。堆占用是采样值，不是峰值；亮像素比例不是反光真值，质量指标仅为启发式。

## 实际验证

- API35 AOSP x86_64 模拟器：5 个聚焦 Android 检查通过，覆盖编辑器、增强色块、相机手拍到编辑器、回收站恢复/直接删除及首页工具。
- 编辑器补充检查通过：裁边后实际图像可见、双击放大后恢复、全屏切页、同裁边原图对照、通过菜单导出诊断 ZIP 并读取参数/结果。
- 单元检查 16 项通过；本版完整 assemble / unit / lint 通过，lint 为 0 错误、50 警告。没有关闭 lint 规则；首次新增的 Activity 获取方式被 lint 拦下后，已改为 `LocalActivity` 并通过。
- 已查看编辑器、全屏及首页实际截图。截图采用生成开发样张；早期截图恰好抓到加载状态，已用等待实际图像后的结果覆盖。
- 未重跑整套扫描基准；未接入实体 ARM64 手机，未获得 50–100 张真实纸张标注集，也没有同图运行竞品的独立对比。因此不声明已达到或超过 CamScanner 实拍质量。
