## Implementation

- `HomeScreen.kt` keeps a single owner for documents, filters, selection, dialogs and effects. All four existing `LazyListState` objects stay hoisted. Its unchanged top-bar, list, cards, FAB and settings items are rendered in three stable real pages. One existing bottom bar remains outside the pager. Recent/All remain document subfilters in page 0.
- `PaperRootPager.kt` uses the existing Compose Foundation 1.8.2 `HorizontalPager`, with opaque real adjacent pages, a clipped viewport and one-page snap distance. No crossfade, dimming, cloned bitmap, fake wraparound page or background black frame is used. Beyond-viewport count is 1; boundary stretch is disabled.
- Distance threshold is explicitly 20%; velocity reaches the native fling only at >=550dp/s and >=32dp displacement. The critically damped snap spring continues from the current position. Final duration depends on displacement/velocity and system animation scale, rather than an added waiting timer.
- Business tab and bottom selection change only after a finger gesture settles. Bottom navigation uses immediate `scrollToPage` plus the existing V6 stationary route motion. Repeated settled destination clicks are a no-op. A new click invalidates an obsolete gesture target.
- `DocumentWorkspace.kt` consumes only marked settled root gestures, suppressing a second route-entry animation. Its existing click, detail, editor, reader and fold/sidebar behaviour stays intact.
- Busy/selection/modal states disable root gestures. The root search fields and horizontal filter strips retain their own gestures. Native nested scrolling arbitrates vertical lists. Touch exploration and reduced motion retain bottom navigation without root swiping. No system back exclusion is installed.

## Startup issue found during review

The first post-install emulator run was killed before the UI tests started. ANR traces show initialization in AndroidX WorkManager's `WorkDatabase.create` on the main thread, with repeated cold bytecode verification; this was not a passing test. Full `speed` AOT compilation was cancelled because it took several minutes without resolving review work efficiently.

`PaperForgeApp` now supplies the existing default WorkManager configuration; only its Startup initializer is removed from the merged manifest. Initialization and recovery run in the application IO scope. Full-package update schedule synchronization and HomeScreen PDF indexing also run off the main thread. Other Startup components and the existing worker classes, scheduler defaults, task state and database are retained. This follows the [official on-demand WorkManager initialization contract](https://developer.android.com/develop/background-work/background-tasks/persistent/configuration/custom-configuration). Subsequent launches and targeted UI/worker-access checks passed without recurrence of the initial ANR. The final distribution check also inspects the packaged manifest: WorkManagerInitializer absent, Internet permission and other Startup lifecycle initialization retained. This is narrower evidence than physical-device cold-start acceptance.
