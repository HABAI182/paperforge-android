# Scan PDF image encoding

PdfBox-Android pinned v2.0.27.0 source tag resolves to `45da92629dad5b3c9887eceefecc89a1423f5457`. Actual artifact constructors and model getters were inspected before implementation. JPEGFactory's byte-array API declares RGB, so PaperForge constructs the PDImageXObject with an explicit colorspace.

AUTO/COLOR/WHITEBOARD/ORIGINAL export opaque RGB JPEG. GRAY/CLEAN use a true single-channel OpenCV JPEG and `/DeviceGray`. BW packs 1-bit rows and uses `/FlateDecode /DeviceGray`. No `/SMask` is created for these opaque derived scans. This encoder is not used to discard imported real transparency. JPEG JFIF densities use the selected DPI; Auto page geometry uses actual pixels ×72/DPI.

No Group 4 claim: the pinned CCITT Bitmap API's presence is not evidence of a Group 4 encoder, and no validated TIFF/G4 encoder was introduced. The v2.3 brief explicitly permits a measured 1-bit Flate fallback. It is lossless for the binary bitmap.

On the identical synthetic regression source, standard-preset 10-page BW output shrank from **2,820,336 to 241,115 bytes (11.70×, 91.45%)**. New enhancement and effective raster dimensions differ from v0.2, so this is a pipeline result, not a codec-only experiment. pypdf reads 10 pages, first image **1515×2090, 1-bit DeviceGray, no SMask**. The 12 MP High export contains **2631×3507 RGB pixels, 300 DPI** at its Auto page geometry; standalone render test reaches long edge3508. Neither path invents source detail.

API35 AOSP PdfEncodingTest verifies actual RGB/gray/one-bit object dictionaries and Android PdfRenderer black/white patches. QualityBenchmarkTest (82 fixed synthetic cases, OCR and PDFs) also passes after integration; OCR CER remains 3.92%, regression13/13. Large files stay in ignored bench-results/encoding-final. Independent object/render report is generated by scripts/bench/inspect_pdf.py; final cross-renderer figures are recorded in PDF-INTEGRITY.md after the acceptance run.
