# 2.0.0 / 20005 扫描反馈与成片质量审核

本批只做局部细化：保持工作台、分类、编辑器的结构和对称布局。只交付本地完整 ARM64 审核包，不创建 PR、tag 或 Release。上一批导出流程记录见 [20004](EXPORT-FOREGROUND-2026-11-02.md)。

## 行为与实现

| 反馈 | 本批行为 | 主要文件 |
|---|---|---|
| 多页拍下后无反馈 | 快门即时缩放并显示正在拍照，写入期间禁用；真正保存后提示第 N 页，可选触觉；失败不报成功，慢速增强队列不影响保存提示 | CameraScreen、CaptureSavedFeedback |
| 四个结果按钮不均、文字换行 | 保留 2×2，统一同色等宽等高；标签为分享/保存/预览/打开，完整含义保留无障碍描述；保存位置独立留白，特殊大字号仍自适应 | OutputResultDialog |
| 纸面中央多出凹槽 | 从实际局部横线选择中央起点，不强迫所有线通过平均峰或水平切线；曲率惩罚压制字迹引入的折点，相邻至少三条线一致才恢复窄折痕；平直页面返回恒等映射，不误入后备模型 | RuledPageRefinement、FlatDocument |
| 透印、暗点和横线发虚 | 原创小型学习模型输出前景置信度；只筛选原始墨迹，不重绘文字。长横线采用覆盖率与局部平均墨色，允许小缺口；横线证据限制最大墨色，防止连带加深噪点；孤立点结合连通域和正文邻近关系处理 | FastInkModel、InkComponents、EnhancePipeline、NeuralPaper、paper_pixels.cpp |
| 过渡割裂、闪黑、重叠 | 保持一个实时内容树和不透明背景，单一弹簧继承中断时的速度；取消分类卡片第二套错峰淡入，保留按压回弹；最近/全部仍即时筛选 | DocumentWorkspace、SectionCards |

快门成功胶囊放在现有反馈列、单页/多页控件上方。最初视觉复核发现叠到切换按钮，已修正并加实际边界检查，没有增加常驻控制面板。

页面弹簧阻尼 1、刚度 550，最大轻位移约 18dp、缩放不超过 0.6%；卡片按压 0.975。减少动效设置继续关闭页面运动。上述值避免拖长全页淡出，也避免不同入口反复重播卡片动画。

## 模型来源和参数

PaperForge Ink v1 是本项目原创前景分类器，537 参数、ONNX 4,386 字节；输入为归一化墨色、Gaussian 0.8 和 Gaussian 2.0，输出前景概率。模型只调制原图，不生成新字。训练仅使用原创程序生成的 OpenCV Hershey 字符、曲线、透印和噪声；没有读取机主照片、参考应用输出或专有模型。模型 SHA256：`6e9de1734e3f880e7551927c64715e208f4b74a0f80a9e20c469bafeee984710`。

训练生成器在 `scripts/train_paper_ink.py`，固定随机种子、7,000 步；训练工具版本及生成器哈希见 `assets/retouch/paper-ink-v1.json`。独立合成种子验证 precision 0.9259、recall 0.9044，**只是合成数据结果，不代表真实文档识别率**。

`ScanParams` 沿用现有参数读取接口，可扫 `learnedInk`、`learnedInkEdge`、`learnedInkFloor/Range/Strength`、`workbookRuleInkCeiling`、`workbookSpeckArea`、`ruledCurveSmoothing`、`ruledSharedFold` 等。每日快速模式默认轻量模型，输入长边最多 1280；完整 DocRes 深度精修仍默认关闭、可选运行。极高淡字保留会绕过新模型和孤立点擦除。旧模型及已有原图保持原字节。

逐像素墨色合成与连通域支撑循环使用现有 C++ 引擎；OpenCV 负责连通域和形态学。连通域统计整批读取，避免每个小点多次跨 JNI。新缓存版本为 flat-paper-3、retouch-7、coherent-ink-4；DocRes 推理权重/提示未变，推理缓存仍沿用 docres-foreground-2。

## 有证据的效果与差距

几何合成样张：25 条已知弯曲横线，含窄折痕。横线偏离 RMS 从 **5.1298px 降至 0.2804px**；已经平直的样张像素完全不变。该结果验证人工凹槽回归与明确折痕，不等于所有实拍场景都已修复。

真实同图使用机主之前给出的 P3 原片，手动固定相同四角；参考为机主 P1 输出截图，去除主要应用栏后以 900px 分析。下表比较的是**当前同一管线关闭/开启轻量模型**，不是整个 20004 与 20005 的版本对比；共用基线配准来隔离外观变化。

| 指标 | 快速：关闭 → 开启 | 深度 DocRes：关闭 → 开启 |
|---|---|---|
| 参考空白区内暗点比例，越低越好 | 0.26373% → 0.23535%（减少 10.8%） | 0.07613% → 0.05417%（减少 28.9%） |
| 参考空白区平均残余墨色，越低越好 | 0.33795 → 0.28164 | 0.10879 → 0.08370 |
| 二值墨迹 IoU，越高越好 | 0.324569 → 0.324495（微降） | 0.384554 → 0.384482（微降） |

完整 JSON 保留独立配准、共用配准、横线自主选择与参考种子追踪的全部结果，包括退步。各自重新配准时 IoU/横线指标会明显漂移，不能把配准变化冒充算法提升；截图本身也不是无损真值。数据见 [验收指标](../acceptance/next/v200-capture/fast-visual-metrics.json)。本地审核资料提供同图三列接触表和局部图，私人照片与参考视频不提交 Git。

目前仍有较深透印、重叠笔画和零散污点，不能承诺 100% 复现参考应用。原始单面照片中某些淡字与背印不可区分，新模型也不是语义级前后页判断。最新红圈凹槽截图没有配对原片，不能声称已在那张原始照片上证实修复；已证实的是造成类似问题的中央锚点与平面误回退两条代码路径。

下一实验应使用该页未处理原片，以及至少 20 张带铅笔、淡横线、密集公式和双面透印的配对照片，标注需保留的细笔画；在固定几何下扫前景阈值，联合计算背景残留和有效笔画召回，避免只追求纸白。当前包先供机主实拍审核。

## 相关验证

Android 35 x86_64 模拟器，9 个不同的相关场景有最终通过记录：两次实际 CameraX 保存、130% 有效字号四按钮对齐/文字布局、平面恒等与已知折痕、多次中断切换、快速/深度模型消融、含小缺口淡横线、快速6次处理与原生迁移像素一致、旧7张素材滤镜复核。只有改动后或失败的路径补跑。

一次结果弹窗检查发现测试夹具把 130% 置于应用自定义倍率之前，实际字号叠加超过 140%，于是命中了原有单列自适应；修正夹具为主题内部的有效 130% 后通过。日志保留早期失败和最新成功，不把失败记录删掉。

七张历史裁切素材全部处理成功，输出包含新1–4、旧1–3；接触表显示淡横线比先前完整，未将这项处理成功当作文字保真认证。几何和滤镜分别检查，历史裁切图本身不用于评价本批自动裁边。

原生连通域循环迁移前后在机主 P3 样张上 `Bitmap.sameAs` 为真。新增学习和横线保护的快速成片连续6次合计 **17.781秒**，首次4.860秒，后续2.424–2.750秒；同输入复用前景缓存，2000px，统计不包含保存证据PNG。与20004较简单管线的10.815秒相比有额外质量处理开销，没有把新算法宣传为整体提速。原生循环迁移前本批同项18.872秒；两次运行的冷启动/系统负载并未完全受控，不把差值全部归因于迁移。完整 DocRes 仍较慢，首次该样张约199秒，不用热缓存结果代替冷启动速度。

可复核 JSON：[几何](../acceptance/next/v200-capture/geometry-metrics.json)、[快速耗时](../acceptance/next/v200-capture/fast-speed.json)、[相关场景](../acceptance/next/v200-capture/targeted-results.json)。

没有重跑 Office、备份、局域网等历史全套；仅核验这批受影响的场景。Release 打包另外核对原签名、单 ABI、版本码、16KiB 对齐、模型字节、R8 映射及 JNI 导出，不等同于实体手机运行验收。
