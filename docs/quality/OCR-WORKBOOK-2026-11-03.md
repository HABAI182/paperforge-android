# 20009 本地审核：OCR、滤镜与手部边缘

日期：2026-11-03。版本 2.0.0，完整功能候选编号 20009。仅在本机准备审核，不建 PR、不推送、不打 tag、不发布、不发微信、不关机。本文不是“达到本地样本应用画质”的声明。

## 已实施

- `PageResources`、`FlatDocument`、`DewarpTrace`、`ScanProcessor`：旧成片中的增强外观归为 WORKBOOK；原图读取保留的未调色裁后像素；增强参数变化从保留的原片与网格重建，不叠加滤镜。相同参数复用已完成外观。OCR 单独选择与当前滤镜一致的几何、未调色的识别输入，避免文字框与 PDF 错位。
- 自动流程只用清理后的分析图估计几何，从原色像素采样成片，最后统一处理肤色和阴影；修复早期抹去肤色、后续再也无法识别残边的问题。零强度、2×2 网格直接恒等采样，修复滤镜重放时四边被挤向四分之一位置的问题；复用同一网格采样器并更新缓存指纹。
- `UserSettings`、`SettingsScreen`：本次升级恢复练习册作为默认滤镜，之后保留手动选择；新滤镜入口收拢为原图、练习册、强力去背景、灰度，旧 AUTO/BW 数据仍可处理。
- `WorkbookPaperBoundary`、`FingerFringe`：已有 OpenCV GrabCut 只在已接受的边缘手部周围精修，限定粗图、ROI、迭代数和一像素轮廓余量，不对整张纸分割。移除遮挡，不重建被遮住的文字。
- `WorkbookBackground`、`WorkbookContent`、`PaperPixelEngine`：强力去背景采用独立弱背景阈值；区分真实边缘锚点与小连通域保护，保留横线、色笔、图形和受支持的源笔画。参数进入 `scan_params.json`。
- `RetouchJobs`、`MainViewModel`、`ScanEditorLayout`：一键扁平化复用较快的自动成片路径，限制输入尺寸，原位发布结果、保留撤销；按钮和消息说明结果位置，后台结果不强行打开另一份文档。
- `NavigationExpansion`、`DocumentWorkspace`、`SectionCards`、`WorkspaceComponents`：栏目和工具入口从卡片位置向全屏展开，保持一份实际内容树和冻结的上一帧；减少动态时跳过，不更换现有布局、配色和对称结构。中间帧审查修正了“空洞先展开、标题很晚才出现”的问题。
- `OcrLineFusion`：后续识别找回的非重叠整行不再被丢弃；排除重叠碎片，保留坐标与实际观察到的整行候选，不凭词典改写原文。Latin 候选不替换含中文的原行。
- `OcrInputPreparation`、`OcrEngine`、`RoutingOcrEngine`、`OcrRequest`、`SettingKeys`、`OcrModelsScreen`：光照归一化是额外视图；行块使用合适采样高度。自动选择已安装、语言匹配的 Paddle 模型，无包时内置离线回退，明确手动选择仍有效。整个任务固定模型身份，更新识别缓存签名。

开源来源与许可核查见 [研究记录](../research/OCR-CLEANUP-2026-11-03.md)。不增加模型权重或运行时依赖；原有模型保留。

## 实图与 OCR 测量

输入为机主 1279×1706 的书页原照片，OCR 使用保存的 927×1400 裁后图。参考 App 成片是截图，不能作为像素级真值。私有输入、逐行输出和对比图在工作目录 `work/workbook-ocr-sweep-20261103`，不进入 Git。

手工从原照片核对了 19 个代码区域、356 个非空白字符，位置固定，以 `scripts/november_ocr_report.py` 计算编辑距离。此项仅衡量这些区域，不是全页 CER，更不是通用 OCR 准确率。

| 同图识别视图 | 区域字符编辑错误 | 完全正确区域 |
|---|---:|---:|
| 内置原始视图 | 21/356（5.90%） | 5/19 |
| 内置均衡行块补识 | 21/356（5.90%） | 5/19 |
| 单独光照归一化视图 | 23/356（6.46%） | 5/19 |
| 已安装 PP-OCRv5 Mobile 原始视图 | 13/356（3.65%） | 10/19 |
| PP-OCRv5 Mobile 光照归一化视图 | 21/356（5.90%） | 12/19 |

归一化视图会改善部分行，也会使其它行更差，因此保留原始输入，不整体替换。全页 Latin 补充没有收益，已撤回自动执行。18 个部分文字锚点里，内置原始/均衡均为 17/18；“用户输入”等易混汉字仍有错误，不能用平均置信度代替准确率。

同轮模拟器测时：内置原始 5008ms、行块均衡 5501ms；Paddle 原始 4791ms（含 330ms 冷加载）、归一化 3788ms（已热机）。这些不是等温、多设备统计，也不是手机性能承诺。

使用既有模型包 `paddle-ppocrv5-mobile-f1d703cc`，指纹 `f1d703cc481d8f559afdc1869855db6a80a9f25c1e973aa4c0e25944a5d913cd`。自动模式只使用已经安装的匹配模型，不隐式下载。

## 图像与交互核查

- 同图、同裁后几何做了多轮 WORKBOOK/CLEAN、GrabCut 开/关、轮廓余量及弱锚点清理比较。手部宽灰边明显减少，细轮廓与部分灰斑仍可见。
- 固定代码框内 5728 个旧版深色像素，在同图新结果中保留至少半数对比度的比例为 1.0。它只是相对旧结果的深色像素检查，不是全部淡字真值。
- 合成夹具中印刷、铅笔、横线、彩色和图形的半源对比度保留比例均为 1.0；这不替代真实淡字验收。新增紧邻手部的铅笔和边缘彩笔负例，遮挡掩膜未覆盖这些内容。
- 一处人工确认无正面内容的灰斑区域，WORKBOOK 平均残余对比度 1.2679，CLEAN 为 1.2564，低于 250 的像素占比仍为 10.83%。放宽弱锚点仅到 1.2527，收益很小，默认未采用；进一步针对图形保护的泛白补丁没有实质收益，也已移除。
- 既有增强成片在练习册中读回的 RGBA 像素与保存 PNG 完全一致。`Bitmap.sameAs` 判断曾失败，改为直接验证尺寸和所有像素，并保留两次失败日志。原图、重复滤镜、PDF 内嵌页像素、零强度网格边缘和 OCR 原图坐标检查通过。
- 最终原文档扁平化任务成功原位发布为 WORKBOOK，标题保留，撤销回到原片；从入队到发布 8767ms。一次 1400px 自动成片核心处理 3522ms，连输出保存 3592ms，不包含前面的检测/解码。这仍超过 3 秒目标；修复两段处理衔接前为 3355ms，不能声称这次画质修复也降低了总耗时。
- 栏目转场截取中间帧及结束帧，确认目标内容随容器展开、只保留一个界面树，动画后释放旧帧。三大根页面另存静态截图复核，沿用既有布局。

## 未解决

1. 部分灰斑、透印与手部细轮廓仍不能可靠区分；当前轻量模型不是经过真实前后页标注校准的语义分类器，不宣称完全清除。
2. 3 秒自动成片目标仍未完全满足；原位后台任务端到端更长，已有进度、结果位置和任务中心入口，但仍需继续优化。
3. 数学手写、淡铅笔、复杂混排及更多真实照片没有完整人工转写和像素真值；不得由此书页或合成掩膜推断通用识别率。
4. 没有物理手机的本轮性能与视觉验收；机主需实际审核。当前没有“100% 复现参考 App”的证据。
