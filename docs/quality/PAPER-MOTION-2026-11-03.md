# 20010 本地审核：纸面、手部投影与返回动效

2026-11-03，2.0.0 / 20010，完整 ARM64 审核候选。只留本机，不建 PR、不推送、不创建 tag/Release、不发微信、不关机。以下记录实际实现与不利结果，不代表已达到参考 App 的画质。

## 代码与行为

| 文件组 | 实际修改 |
|---|---|
| `WorkbookPaperBoundary.kt`、`FingerFringe.kt` | 使用相对纸面色比例识别阴影中的肤色；先在弱肤色里连接强种子，再判断边缘接触，修复大手部因亮芯不触边而漏检。精修不得丢掉原已接受种子；GrabCut 结果只保留连接种子的分量，防止附近断开的铅笔被当手部。中性投影按局部照明比例归一化，保留阴影下可见笔画；不重建被手指遮住的文字或横线。 |
| `EnhancePipeline.kt`、`InkComponents.kt` | 横线证据先通过方向连续性筛选，再做占用率聚合，避免大量浅色透印连成假横线。印刷页和分布式横线页分别选连通阈值，保留淡铅笔的弱边缘锚点。 |
| `WorkbookContent.kt`、`WorkbookBackground.kt`、`paper_pixels.cpp` | 在归一化纸面对比度中混合增强强度，减少原灰黄纸底回混。白底判定结合源对比度、平滑程度、已有轻量前景证据和笔画邻近关系。颜色相对纸色判断，避免暖纸被保护为彩色笔迹。默认笔画增益从 1.4 改为 1.15，不用膨胀加粗。 |
| `PrimaryPaperFrame.kt` | 多段平行竖边按覆盖率聚合，识别碎片化叠纸边；保留单一边框与中央表格保护。这项目前只有夹具覆盖，不能声称新照片的所有纸边已消失。 |
| `ScanProcessor.kt`、`FlatDocument.kt`、`scan_params.json` | 带旧增强指纹且保留原片的页面，回放原网格应用当前外观；当前指纹、无版本旧结果及缺原片结果继续复用。原图读取未调色原片。所有新增阈值进入现有配置，诊断输出包括各阶段耗时、纸边/手部掩膜与投影像素数。 |
| `NavigationExpansion.kt`、`DocumentWorkspace.kt`、`MainActivity.kt` | 记录入口矩形和路由，返回时将退出页面静帧收回原卡片；实际父页面固定显示在下方，取消额外横向回程位移。展开约 460ms，收回约 420ms，可打断，减少动效时跳过。只有一份真实页面树。 |
| `HomeScreen.kt`、`MainViewModel.kt`、各入口的返回操作 | 保留栏目和搜索条件各自的滚动位置，扫描 FAB 使用同套展开；工作台/设置底部内边距从 100dp 减为 16dp。文档页仍给悬浮扫描按钮留空间。布局、卡片数量、对称和配色不变。 |

复用既有 OpenCV、前景模型、几何网格、原片和缓存。没有新增模型权重、第三方运行库或复制新的外部实现；原有组件及许可记录不变。此批没有训练经过真实正反页标注校准的语义模型。

## 实验取舍

- 放宽弱边缘阈值到 0.20/0.24 会使夹具铅笔的半源对比度保留率降到 0.9398，0.32 更差；拒绝，默认保留 0.16。
- 只增加背景置信阈值几乎无收益，原因之一是浅色文字被错误保护为横线，已修正方向证据，而非单纯提升清除强度。
- 逐通道修正手部投影会重新带出黄色光晕，拒绝，改为统一亮度比例。
- 无限幅的 1.4 笔画增益在代码框内产生 7219 个深色像素，太粗；严格限制边缘后只剩 3888，细字偏虚。最终采用较轻的 1.15 增益，4919 个深色像素，在实际对比中较平衡。
- 保留强种子和先连接弱肤色才解决本张数学页的大块手部漏检；只增加 GrabCut 迭代不能解决这个前置错误。

## 剩余差距与下一步

1. 新照片的暖色手部主体明显减少，但中性细轮廓、断开的横线端点和部分叠纸边仍存在；不会凭空补出被挡文字。
2. 代码页和数学页仍有灰色透印，尚未完全清除。下一实验应收集同一张纸正反面与无透印参考，标注前景、反页和手部投影；比较真实样本上的前景损失及残留，不能靠继续提高阈值保证全部淡字安全。
3. 本轮 x86 模拟器 Debug 核心处理代码页 4283ms、数学页 6803ms；检测/解码/裁切另为 1770ms、717ms，保存、任务排队和分享不包含在核心内。3 秒目标尚未满足，未进行本轮实体手机性能验收。
4. 参考截图配准代理和合成夹具不是“100% 复现”或通用准确率证据。机主仍需审核 APK 中真实照片、淡字、纸边和动画手感。
