# 1.2.0 相机与文档库反馈

本批次继续本地审核，不创建 PR、tag 或 Release。沿用完整 ARM64 单 APK、包名与原证书；现有边界、曲面及本机审核模型均保留。私人照片、对照图和模型权重不加入 Git。

## 实现

| 反馈 | 修改与行为 |
|---|---|
| 相机上下拥挤 | `CameraScreen.kt` 把顶栏、拍摄反馈和单页/多页切换叠到取景区；删除常驻档案/定时行与模式说明行，设置集中在扫描设置面板，底部只保留模式栏、相册、快门和完成/重拍。沿用 CameraX 坐标变换与 FIT_CENTER，避免布局调整改变四角映射。 |
| 多页、证件、重拍 | `UserSettings.kt` 一次性迁为多页，之后保留手动选择；`ScanCaptureModes.kt` 移除黑白拍摄模式，证件配方采用 ORIGINAL。已有黑白页面和编辑滤镜仍可正常显示。缩略图旁可点“重拍”，冻结目标页并沿用现有替换/历史链路。 |
| 手动旋转 | `ScanRotationDialog.kt`、`ScanEditorLayout.kt`、`EditorScreen.kt` 在主工具栏提供旋转，左右 90°、±45° 微调、0.1°步进、网格参考、实时预览与复位。保存进入原有撤销历史，预览和导出共用扩展画布，不裁掉角落内容。 |
| 透印与横线 | `EnhancePipeline.kt`、`scan_params.json` 把长横线/竖线证据和普通弱纹理分开。方向形态学容忍轻微弯曲，再与实际墨色相交，保护原线而不加粗空白区域；普通低对比灰痕使用更强的软曲线。所有新参数仍可通过 ScanConfig 扫描。 |
| 分享与去水印 | `Repository.kt`、`MainViewModel.kt`、`MainActivity.kt` 对名称、来源或前两页文字可识别的 本地样本应用/本地样本应用分享件自动清理可分离的对象水印，然后打开文档；原始 PDF 注册为文档资源，随原有备份保留。其他 PDF 直接打开。`PdfToolsDialog.kt` 常用区增加去水印。没有自动弹出另存或转发界面。 |
| 局域网直接打开应用文档库 | `LibraryTransferProvider.kt` 在完整 APK 内提供同 UID、只读文档接口；`LanDocumentLibrary.kt`、`LanHttpServer.kt` 在已有配对后提供目录、封面、分类和 PDF 下载/范围续传，隐藏回收站及未列出的内部文档。扫描草稿使用当前编辑效果按需生成 PDF，默认不 OCR。无需客户端打开 Android 文件管理器。 |
| 本机选应用文档 | `LanLibraryPicker.kt`、`LanActivity.kt` 提供按标题/分类搜索、多选加入发送队列；手机文件选择器作为额外入口保留。浏览器页面同时提供搜索、分类、封面、全选和下载所选，浏览器批量下载受其多文件下载权限管理。 |
| 生硬的动效 | `DocumentWorkspace.kt` 按标签方向、进入/返回和文档场景区分横移与轻缩放；`SectionCards.kt` 添加短时错峰进入和按压回弹；局域网页按钮和卡片有轻量反馈。仍是单内容树，避免重复运行相机/OCR；遵守减少动效。 |
| 丑陋的标题标点 | 原生 LAN 页与浏览器均将“文件，就在手边。”改为“文件就在手边”，智能工具短标题去掉句号。扫描模式的文字破折号改成图形选中指示。检查主应用、联网模块的标题/按钮文案，保留长说明里的正常句读。 |

## 参数与质量边界

本批次练习册 noise=13、gamma=2.05、弱字证据范围26–84、输出墨色底值7；强力去背景 noise=22、gamma=2.35。横线支持长度为短边的6%（31–161px），垂直容差5px，线条证据底值6、范围14、增益1.9。现有按页淡字保留滑块不变。

七张机主原片复用已经测过的裁切结果，仅重算本次变化的两个滤镜，不重复识边或原有全量回归。照片没有新增清晰真值或同图参考输出，因此不将白像素比例当作 OCR 正确率，不宣称透印全部消失或达到参考 App 的所有场景质量。新2/3顶部失焦区域仍是限制：正面淡字和背面透字的灰阶重叠，单张输入无法可靠区分；可提高淡字保留或使用原图/自然。

自动去水印沿用已有对象处理器，适用于可分离的角落文字及独立图像标记；不承诺抹除已烧录在整页扫描图中的任意水印。证书签署或保留原样的 PDF 应使用保留的原始副本。普通 PDF 工具去水印为主动操作并生成新结果。

## 动效研究

参考用户指定的 [Web Motion Showcase](https://holynova.github.io/web-motion-showcase/?lang=zh&theme=slate&mode=light) 及其 [公开源仓库](https://github.com/holynova/web-motion-showcase) 中进入、错峰、按压与轻浮起的节奏；实际 Android 实现采用现有 Compose Animatable/graphicsLayer 和 interactionSource。参考 [Android Compose 动效指南](https://developer.android.com/develop/ui/compose/animation/quick-guide) 的打断、绘制阶段更新与生命周期建议。未复制该站 JavaScript 或引入新的动效运行时。

局部纸面估计和连续规则线保护为项目 Kotlin/OpenCV 代码；查阅本机逆向中的 rollingBallBackground、clean_background_nois 和灰阶映射入口仅用于技术研究，不将伪代码当作参考 App 实际启用参数的证据。本轮没有新增借用的 OSS 源码。

## 验证记录

- 首轮 5 项通过（92.772 s）：旋转90°+3.5°保存、默认多页/证件原图/重拍目标；已知区域滤镜+七图输出；真实浏览器及配对后文档库、封面、原 PDF 下载、范围续传和扫描草稿 PDF；真实 ACTION_SEND 的普通 PDF 与带 本地样本应用 文字水印 PDF。
- UI 截图发现长设备名造成浏览器横向溢出，修正网格最小宽度和换行；旋转预览补齐输入合并期间的加载反馈，截图等待实际预览完成。仅复查受影响的两项通过（18.203 s），包含小屏文档宽度不溢出断言。
- 滤镜合成区域比较中，弱模糊透印平均墨色0.264→0.155，暗前景区域墨色23.088保持不变；连续规则线更清晰。它验证已知样本上的方向，不代表照片全部前景保留或 OCR 准确率。
- 新照片2/3的浅横线仍偏弱时，再把线证据门槛降为6、范围14，复用已有裁切只更新两种滤镜，最终1项通过（70.029 s）。
- 不重复票据、命名、Office 转换或所有历史用例。

三张既有参考导出仍按原片 SHA-256 配对，更新了参考/上版练习册/本版练习册/本版强力去背景联系表。与参考的单应配准代理指标有改善也有退步：它混合了线条强度、裁边留白和非线性曲面差异，不能当作全局质量结论。下一步质量实验应使用同一几何、清晰正面字迹标注与局部非线性配准，分开衡量前景保留和透印抑制；不要靠继续推高全局白化来掩盖失焦。
