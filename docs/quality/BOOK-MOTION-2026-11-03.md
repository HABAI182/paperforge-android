# 2.0.0 / 20008：书页去痕与底栏跟随

基于机主新给的四张附件继续实际修改。书页原片为 1279×1706；参考和被拒绝的应用结果来自截图，已经裁去界面，但不是原始参考导出或真实干净页。多层练习册纸边这次只有处理后截图，不能当成新的原始实拍样本。所有私人图像留在仓库外。

## 验证方法与失败保留

`WorkbookNovemberFeedbackTest.kt` 使用机主这张原片，实际运行检测、裁剪、自动展平和增强并保存 Android PNG。旧外观消融使用新几何和边界处理，不冒充上版完整应用。最终性能顺序先执行新默认路径，再执行旧外观消融，避免把后续暖缓存速度当成冷启动性能。

定向检查还覆盖原有淡字/公式/颜色/拓扑、页眉和页边负例、多层纸边与单独表格边；动效覆盖拖动、取消、反向、落定以及中途新点击。`scripts/november_feedback_report.py` 只整理实际输出，并复用已有 SIFT/空白残墨诊断，不以 Python 增强代替应用。

首轮 5 项有 1 项失败：淡铅笔保留指标约 78.34%。第二轮恢复连通域保护后仍为 96.89%，没有放宽测试门槛；继续调整弱清晰笔画的锚点证据，第三轮原有断言通过。失败输出和日志保留在私人审核目录。首轮该书页约 17.8/11.5 秒的顺序耗时，第二轮约 8.8/5.8 秒，第三轮约 6.2/3.43 秒；期间工作尺寸和算法发生变化，不能当成同条件硬件排行榜。

## 最终结果

- 源码和测试 APK 构建通过，最终一次为 2 分 42 秒；补充自适应计时的测试包构建为 48 秒。
- `instrumentation-final.log`：5 项通过，26.942 秒。真实书页、淡字/公式/颜色/拓扑、已知几何与图形拒绝、原片滤镜回放、页眉和页边保护。此前首轮的多层纸边/单表格边与完整 V7 拖动/反向/取消/新点击检查通过，之后未改动这些实现。
- `instrumentation-adaptive.log`：单项实图计时通过，10.828 秒。新默认路径先执行，1400px 首次图像处理 3675ms；下一页按真实预算缩到 1201px，2526ms；最后的旧外观消融 1400px 为 2712ms。另一次新默认首次记录为 3812ms。
- 上述 `processingMs` 包含纸面准备、几何和外观处理，不包含前置解码/检测/裁剪及最终 PNG/数据库 IO。**首次仍超过 3 秒，端到端单页 3 秒尚未证明达成**。后续自适应图像处理达到该样本的目标，但有清晰度取舍，不能外推到所有手机。
- 合成的“至少保留一半源对比度”检查中，印刷、铅笔、规则线、颜色和图形掩码均为 100%；真实照片没有这种像素标注，不据此声称真实文字召回 100%。

| 输出 | 空白平均残墨 | 空白深残墨比例 | 墨迹 IoU |
|---|---:|---:|---:|
| 机主被拒绝的应用截图 | 3.17885 | 0.003062 | 0.42379 |

平均空白残墨比被拒绝截图减少约 76%，但 IoU 下降，没有选择性隐藏这个不利结果。SIFT 对齐、字重调整、分辨率与截图压缩都影响 IoU，不能将它当成识字准确率。实际输出仍有灰痕、手指外沿灰影和纸边碎片；没有宣称达到参考画质。完整 PNG、局部拼图、日志和 JSON 保存在私人 `work/feedback-book-20261103`，不提交私人图片。

## 仍有的边界

- 不把所有低对比度内容判成背面文字；正文、淡铅笔与透印证据相同的地方仍保留不确定内容。因此仍可能留下部分灰痕。
- 真实被手挡住的内容没有可恢复的源像素，本版不补造字符。手部附近仍可能有灰边，纸面严重曲面和多层边界不能保证逐页都被正确识别。
- 参考截图的像素与压缩和原片不同，分别配准后的 IoU 只是诊断，不能代表 OCR 或有效文字召回率。
- 自动工作尺寸与处理预算有明确取舍；原片和手动高清路径可用。实体手机首次运行、持续拍摄和是否满足 3 秒目标仍需实际设备核验。
- 不宣称完全复现参考应用，不以合成保护测试替代真实照片验收。未创建 PR、tag 或 Release。
