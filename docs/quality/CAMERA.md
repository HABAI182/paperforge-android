# Camera quality gate

CameraX 1.4.2 analysis explicitly requests1280×960 with closest-lower/higher fallback and RGBA output. Packed rows are copied in bulk respecting rowStride. RGBA channel order follows the [Android ImageAnalysis contract](https://developer.android.com/reference/androidx/camera/core/ImageAnalysis#OUTPUT_IMAGE_FORMAT_RGBA_8888). Detection now receives color, not only luma; actual chosen size/FOV and device conversion performance remain hardware acceptance.

Raw quads/confidence feed capture. A display-only tracker smooths corners, resetting on viewport/time/scene/large-step changes. Still detection always re-runs on the original capture. Adapted tracker/policy provenance and original NOTICE are packaged and recorded in LICENSE_NOTICES.md.

Paper interior is normalized to450×600 for Laplacian sharpness,3×3 detail-tile counts and brightness. Automatic capture requires detection confidence, stable geometry and absolute/relative sharpness. Unknown first-frame low-detail paper cannot label a blurred image as a blank reference. AF is requested at scene acquisition and taps; successful/unsupported AF allows quality-based capture. Per the owner's latest request, missing/failed AF metadata no longer blocks indefinitely: after1.2s, image quality may take over. Manual shutter remains available. Glare fraction is a gentle hint, not proof of recoverable highlights. Runtime confidence floor is now0.60 and sharpness floor45, with relative quality/stability still checked; these are configurable development values pending device calibration.

`CameraQualityTest` records30×200ms repeated-frame sequences from generated sharp/blurred text and a separate policy-only focus-not-ready replay (without CameraScreen's new timeout override). Actual OpenCV metric: sharp variance19524.38/detail6, Gaussian-blur variance3.06/detail0. Automatic captures: **sharp1; blurred0; focus-not-ready0**. Alternating ±.005 corner motion: raw0.39000, displayed0.18903 (**51.53% reduction**). See camera-sequence.json. These are deterministic synthetic replay measurements using the policy's default60 floor, not autofocus or camera-hardware results. The runtime45 floor, AF timeout, glare hint, throughput, preview mapping and continuous capture require real-device calibration.
