# #21 · 裁边/透视与拍后质检

本页记录已完成的两块，以及仍未做的部分。量化基准见 [扫描质量基准](../../scan-quality/README.md)。

## 已完成 1：满幅伪检测不再冒充已定位文档

空桌面、边框强的场景会被神经边缘模型当成整幅纸张（置信度 0.99、框覆盖 96–99% 画面），进而进入自动拍摄门槛。改动：`Quad.hugsFrame()`（四角贴边）+ `LearnedDocumentDetector.frameOnly()` 在出参处统一拦截，按「未定位」返回；成片仍按整幅裁切。

| 指标（synthetic-v1，74 检测 + 8 无文档） | 修前 | 修后 |
|---|---:|---:|
| 无文档误检率（置信度 ≥0.8） | 62.5% | **0%** |
| 有效裁切 IoU | 0.9950 | 0.9906 |
| 角误差 | 0.132% | 0.253% |
| 误裁率（IoU<0.7） | 0% | 0% |

代价：满幅类样例回退整幅裁切（IoU 0.99→0.95）。取舍见基准页。

## 已完成 2：拍后质检提示（不阻断保存）

`CameraQualityAnalyzer.postCapture()` 在照片落盘后基于**实际原图**评估，`CaptureHints` 给出可操作分类：`BLUR` 整体模糊、`MOTION` 局部模糊、`GLARE` 反光、`MISSING_EDGE` 缺边、`DARK` 偏暗、`BRIGHT` 过亮。取景框提示与拍后提示共用分类，但措辞分开；拍后只弹 `Toast` 建议重拍，页面照常入队。

- 局部模糊只在「有细节的 9 宫格中存在明显更软的格子」时才报告，空白页边不会误报。
- 缺边按四角贴边判定（`Quad.cutOffEdges()`），不是所有靠边都算——需要整条边贴边。

### 验证（API35 x86_64 模拟器，合成图）

`CaptureQualityHintsTest`：[hints.json](hints.json)

| 场景 | 输出 |
|---|---|
| 清晰页面（内缩四角） | 无提示 |
| 高斯模糊（σ=9） | `BLUR` |
| 页面反光块（约 10% 面积） | `GLARE` |
| 纸张左右贴边 | `MISSING_EDGE` |

`CaptureHintsTest` 单测另覆盖 `MOTION`（局部模糊）、`BRIGHT`、`DARK`、空白页边不误报。

## 仍未完成

- **真实照片未验证**：模糊、反光、缺边、淡字、铅笔都要用真实手机照片复测后才能作为发布结论。
- 裁边/透视本身未改动：弱边界、斜拍、遮挡等场景的算法改进仍待做，目前只有满幅伪检测这一项修复。
- 取景框提示只做了分类替换，未做「一键重检/手动微调」入口的新增（裁切页原有微调保留）。
- 既有 `EditorExperienceTest` 在本机 AVD 上于裁切画布手势处报 `Failed to inject touch input`，在 `main` 上同样复现（与本次改动无关），未修复；发布前的 UI 走查改用截图核验。
