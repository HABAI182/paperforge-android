## 1. 结论

一句话：编辑页的能力（本轮可数到 **44 个可执行动作**）并不缺，缺的是**分层**——21 个动作挤在「更多」的单列长菜单里（`EditorScreen.kt:357-544`），底部栏反而是"裁切/增强/识字/更多 + 继续拍/导图/导出"两行 7 个动作（`ScanEditorLayout.kt:132-168`），**旋转和删除不在任何一级入口**，缩略图条默认关闭（`ScanEditorLayout.kt:60`、`263`），页面网格要 2 步才到。

目标布局（本轮方案）：

| # | 变化 | 现状证据 |

| 1 | 缩略图条**常驻**，点选翻页 1 步、「管理」直接进页面网格 1 步 | 现在是 `thumbnails = false` 默认关，点页码徽标才展开（`ScanEditorLayout.kt:60`、`244-261`、`263-297`） |

## 2. 计数口径（先定义，否则数字没有意义）

- **起点**：编辑器主界面（某文档已打开、无弹窗、无面板展开）。
- **点击数** = 让该操作**落地**所需的离散点击/长按次数：打开面板或对话框 + 提交（应用/保存/生成/确认）。长按计 1 次。
- **计入**：打开面板/对话框；面板内的按钮（选滤镜、点"外扩"、"应用""保存""生成""确认""复制到"后选目标）；长按；从编辑器**退出到文档库**再操作的返回键。
- **不计入**：滚动、拖动角点、拖滑块、双指缩放、输入文字、等待任务/识别。
- 读法示例：滤镜 = 点「增强」1 + 点滤镜 1 = **2 步**；裁剪 = 点「裁剪」1 + 点「应用」1 = **2 步**；裁剪微调 = 裁剪 1 + 点「外扩」1 + 应用 1 = **3 步**；删除本页 = 更多 1 + 删除本页 1 + 确认 1 = **3 步**；导出 = 打开面板 1 + 生成 1 = **2 步**。
- 这条口径自带一个取舍：凡"必须按应用/保存才算完成"的动作都 +1。如果改成"只数到面板打开"，裁剪、调节强度、重命名、书籍双页、曲面校正各减 1，但**删除本页会变成 2 步**，全篇最重要的"删除 3→2"也就不成立了。所以选"含提交"并全表统一；`entry-map.csv` 的备注里保留了路径拆解，换口径可重算。

### 3.3 现状问题（只用代码事实）

1. **高频动作埋在 21 行菜单里**：旋转（`EditorScreen.kt:444`）、删除（`:469`）、页面管理（`:461`）都不在任何一级入口。
2. **菜单必然滚动**：`Column(verticalScroll)`（`:362`），18–21 行按钮（估算 ≥864dp），诊断包这类项在测试里都要 `performScrollTo`（`EditorExperienceTest.kt:139`）。
3. **缩略图条默认隐藏**：`thumbnails = false`（`ScanEditorLayout.kt:60`），条件渲染（`:263`）；不点页码徽标（`:245-261`）永远看不到多页概览。
4. **页面网格 2 步且有两个入口**：更多→页面管理（`EditorScreen.kt:461`）或 徽标→页面管理（`ScanEditorLayout.kt:296`）——两个入口说明它重要但难找。
5. **底部栏 2 行 7 个动作，但没有旋转/删除**（`ScanEditorLayout.kt:132-168`）：一级栏被"加页+导出"占了两格。
6. **导出在底部二级**（`:161`），与"继续拍/导图"混行，顶栏没有导出。
7. **菜单排版随状态变化**：3 个条件项（`:380`、`:405`、`:431`）会让同一菜单的行数与顺序变化。
8. **票据信息不在编辑器**（`HomeScreen.kt:1170`）：编辑时想核对票据要退出编辑器。
9. **识别设置是"菜单中段的控件"**（`EditorScreen.kt:379`）：`OcrOptionsControl` 改的是全局设置，却放在动作列表中间。
10. **"应用全部"不可一次撤销**：`applyAll` 逐页 `savePage`（`MainViewModel.kt:2738-2750`），每次 `savePage` 写一条历史（`Repository.kt:153-160`），撤销一次只回退一页。重排不会改变这点，方案里也不假装改变。

## 6. 风险与保持项

### 6.1 撤销必须继续可用

- 撤销/重做是**文档级**、基于 `edit_history` 表（`Repository.kt:278-282`）；顶栏位置不变，仍是 1 步。
- 单页操作（旋转/裁剪/滤镜/删除/重拍）各写一条历史（`savePage` `Repository.kt:153-160`；`deletePage → replacePages` `:426-432`），单次撤销即可回退 → 验收按此断言。
- **已知限制，本轮不修**：`applyAll` 逐页写历史（`MainViewModel.kt:2738-2750`），撤销 N 次才全退；批量删除同理（`deleteMany` `:2759-2760`）。方案不承诺"一次撤销回退整批"。
- 撤销后页数会变少 → 见 6.8。

### 6.2 多选

- 现有两套选择状态都不能被新交互污染：页面网格 `selected: Set<String>`（`PageGridScreen.kt:34`）、库内 `selection`（`HomeScreen.kt:1136`）。
- 缩略图条多选必须是**编辑器局部状态**，退出编辑器即清空；切页时是否清空要在实现时定（建议保留，与网格一致）。
- 多选态必须处理：pager 禁滑（现状 `userScrollEnabled = !zoomed`，`:209`，需要再加一个条件）、底部栏切换为批量条、删除是否允许删到 0 页（现状页面网格可以删到空，`PageGridScreen.kt:99-107` 无兜底；本轮保持同一行为，不新增规则）。

### 6.3 页面网格能力不丢

`PageGridScreen` 的 7 个能力（全选/旋转/删除/完成/复制到/移动到/拖排序）全部保留，本轮只改**进入成本**（2 步 → 1 步）。入口从"更多→页面管理与排序"和"徽标→页面管理"改为"缩略图条「管理」"；`vm.screen.value = "pages"`（`EditorScreen.kt:463`、`ScanEditorLayout.kt:296`）不变，路由不变（`MainActivity.kt:625`）。

### 6.4 无障碍

- 6 格底栏每格 ≥48dp；`ToolAction` 已有 `clearAndSetSemantics { contentDescription; role; onClick(label) }`（`EditorScreen.kt:561-570`），新按钮沿用同一封装，**不要**只留图标。
- 旋转按钮的语义必须是"顺时针旋转 90°"而不是"旋转"；长按菜单需要 `customActions`（参考 `ScanPageCanvas.kt:74-102` 的既有写法）。
- 取消页码徽标后，"第 x / y 页"必须在语义里保留（标题副行 + 缩略图 `contentDescription`，现状缩略图已有 `"第 ${index+1} 页"`，`:288`）。
- 长按多选必须同时有**显式可达路径**（更多 → 页面网格），否则 TalkBack 用户无法批量操作。

### 6.5 深色主题

只使用 `MaterialTheme.colorScheme.*`（现状缩略图条：`surface` + `outlineVariant`/`primary` 描边，`ScanEditorLayout.kt:265-278`）；不写死 `Color(0xFF...)`。底栏/弹层背景用 `surface`，卡片描边用 `outlineVariant`，不要引入新配色。**本轮不验证实际观感**（见 §7.4 走查清单留给下一轮）。

### 6.6 大字体

- 现状只有一处适配：副标题在 `fontScale > 1.5` 时隐藏（`ScanEditorLayout.kt:98`）。
- 6 格底栏 + 文字标签在 `fontScale 1.3` 以上会挤压/截断。方案要求：`fontScale > 1.3` 时底栏退化为**图标 + 隐藏标签**（`contentDescription` 兜底），或允许两行；阈值与现状 1.5 不一致，需要在实现时统一（决策点：用 1.3 还是 1.5）。
- 顶部栏在 `fontScale 2.0` 下"标题 + 3 个动作 + 导出"会挤：标题 `maxLines = 1` + `Ellipsis`（`:93-96`）保留，导出按钮允许退化为图标。

### 6.7 横屏

编辑器目前**没有任何横屏分支**（全仓库仅 `CameraScreen.kt:279-281` 判断横屏）。横屏 2340×1080 ≈ 780×360dp：状态栏 24 + 顶栏 56 + 缩略图条 80 + 底栏 60 + 导航 24 = 244dp，**画布只剩约 116dp**（估算，未做布局回读）。
方案：横屏时缩略图条转竖向（左侧）或折叠为一条 40dp 细条；**这属于新布局，列入本轮不做**，但必须在验收清单里记录为"已知未处理"，不假装解决。

### 6.8 分页器 key 越界（#23 修过，不能回退）

- 现状防护：`key = { pages.getOrNull(it)?.id ?: "pending-$it" }`（`ScanEditorLayout.kt:207`）、`val page = pages.getOrNull(index) ?: return@HorizontalPager`（`:212`）。**这两行必须原样保留**。
- 新增风险：缩略图条点选用的是 `itemsIndexed` 的 `index` 直接 `pager.animateScrollToPage(index)`（`:271`），列表缩短的瞬间没有夹取。方案要求改为 `index.coerceIn(0, pages.lastIndex)`（与 `EditorScreen.kt:96` 的既有写法一致）。
- 批量删除/撤销后：`LazyRow` 的 `key = { _, page -> page.id }`（`:269`）本身是稳定的；但多选集合里会残留已删除页的 id，实现时必须 `intersect(pages.map{it.id})`。
- 验收必须重跑"拆分双页 → 撤销"路径（#23 的崩溃场景）。

### 6.9 条件项与 busy 态

3 个条件行（`origins`/`ocrText`/`dewarp-grid`）不能因为分组而变成"永远显示"或"永远消失"；`!busy` 禁用要跟着每一项走；识别任务进行中"识字"与"重新识别"都应禁用（现状由 `active != null && !busy` 控制，`:143`）。

### 6.10 全局对话框与返回栈

OCR 结果是**全局** `SpaciousToolDialog`（`MainActivity.kt:787-846`），不是编辑器内的对话框。把"识字"从底部一级移到更多后，弹层必须先关闭再打开全局对话框，否则会出现"弹层上盖弹层"。同理「翻译与智能工具」「导出」都是全局对话框。实现顺序：`sheet = false` → 触发 `vm.openOcr(...)`。

## 8. 推断依据的弱点（自评）

1. **没有使用数据**：全项目没有埋点/统计入口，"高频"完全由"放置层级 + 重复入口 + 测试路径"推断。若真实高频是"识字"（扫描类 App 很常见），则把 OCR 降到 2 步是错的方向——这是本方案最大的不确定性，已列为决策点 2。
2. **测试样本很窄**：`EditorExperienceTest` 只覆盖"增强/裁切/更多/诊断包"；`SpreadSplitSampleTest`（#23）覆盖"更多→拆分"；票据相关测试直接调用对话框（`ReceiptReviewDialogTest.kt:49-59`），不覆盖入口。用这些反推频次，样本很小。
3. **计数口径高度敏感**：本表用"含提交"口径（应用/保存/生成/确认都算 1 步，长按也算 1 次）。若改成"只数到面板打开"，裁剪 2→1、裁剪微调 3→2、调节强度 3→2、重命名 2→1、书籍双页 3→2、曲面校正 3→2；更关键的是**删除本页会从 3 变 2**，"删除 3→2"这条改善立刻不成立。若"长按不算一次交互"，批量旋转 4→2、批量删除 4→2、拖排序 3→2 三项也失效。所以 §2 先定义口径、`entry-map.csv` 备注保留路径拆解，便于换口径重算。
4. **菜单行高是估算**：21 行 ≈ 864–1008dp 是按 Material `TextButton` 最小高 48dp 估的，未做布局回读。
5. **"更多"分组的边界是人为的**：例如"重拍本页"放「加页」弹层而不是「页面与结构」，理由是"它也产生页面"；用户可能认为它属于页面修复。这类归类需要用户确认。
6. **未确认项**：是否有平板/折叠屏规划（影响要不要做双栏）；是否允许取消页码徽标；票据信息是否允许进编辑器（文档级 vs 页面级语义）；是否存在外部约束要求"底部必须 4 格"。
7. **线框的保真度**：SVG 手绘尺寸，字体用系统字体栈，和 Compose 实际排版（最小触控、行高、`Arrangement.SpaceEvenly` 分配）有差距；线框通过 ≠ 实现通过。

1. **加页交互**：A 点击开弹层（2 步，推荐）/ B 点击直接拍摄 + 长按弹层（1 步，但藏功能）。
