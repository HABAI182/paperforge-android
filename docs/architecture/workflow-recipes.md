# 工作流配方

配方以有序步骤描述单份 PDF、Office、TXT 或图片的处理。十种已接入操作定义输入/输出类型，编辑器提示不匹配位置并阻止执行。命名配方随设置、配置档案的工作流分组和完整备份携带，目录只保存逻辑 ID。

执行复用 `CONVERT / RECIPE` 持久任务、重流水线预算和已有转换引擎。输入先复制保留，OCR 引擎/语言/模式固定到任务。步骤结果以原件 SHA256、当前输入 SHA256、步骤 ID/操作/参数和相关 OCR 签名判定复用，记录为任务资源。每步生成报告；失败后能看到具体步骤并调整继续。

改变步骤或前置输入会使对应阶段重新处理；若结果内容没有变化，后续阶段仍可复用。修改命名或保存目录不会重新 OCR。不同参数版本写入不同目录，已打开或发布的旧结果保持原路径，避免文档引用被新结果覆盖。Office 阶段也使用各自的版本输出路径。

保存步骤创建新目标并记录自己的 URI；写入失败可在同一目标重试。成功以完整字节数和 SHA256 读回核对。备份恢复移除保存 URI 和该阶段完成标记，需要在当前设备重新授权，之前的昂贵处理结果仍可复用。内部 OCR/Office 原生段并非任意位置续跑；只有阶段完成后才登记可复用结果。

当前一次处理一个输入文件。PNG 步骤返回逐页 ZIP；TXT、DOCX 与原生/图像 PDF 的能力沿用各引擎说明。没有提供任意命令或隐藏的外部服务。配方可手动运行，也可由默认关闭的自动导出规则触发；条件和生命周期见 `auto-export.md`。
