# 手机 Office 后台任务 · 协议 1

主应用在保留完整输入后建立 `CONVERT / OFFICE` 任务，冻结目标格式。既有 WorkManager 和后台重流水线槽位运行此任务；核心应用依然不需要网络。

## 绑定与消息

- 显式绑定 `cn.paperforge.office/.OfficeJobService`，服务位于独立 `:worker` 进程。
- `cn.paperforge.office.permission.CONVERT` 是签名权限。主应用和可选引擎须来自同一签名渠道。
- Messenger 请求码 `1`：`protocol=1`、稳定工作 ID `id`、目标 `format`、源后缀 `extension`、只读 `input` 和可写 `output` 两个 ParcelFileDescriptor，以及 `replyTo`。
- 回复 `2` 报告进度和详情；`3` 表示输出已复制、刷新并关闭；`4` 为失败详情。回复携带相同 ID 和协议号。
- 请求 `5` 取消同 ID 工作。独立引擎进程退出以中止同步原生调用；不会结束主应用或阅读进程。

描述符通过 Binder 传递，不依赖文件选择器 URI 授权在整个排版期间一直有效。服务将输入复制到自己的临时目录，原生 LOK 在单线程转换，然后将输出流回主应用的 AtomicFile。该任务有源件、格式与中间结果引用，完成后的保存到外部目录沿用独立 SAVE 任务。

## 生命周期与恢复

绑定由 Worker 持有，进入后台不会取消绑定。主进程退出时系统解绑，仍在工作的引擎进程随之退出；WorkManager 的下一次运行从保留输入重试。完成的 Office 输出通过原件 SHA256、目标格式与协议签名登记检查点；若只剩登记或外部保存失败，可直接复用该输出。

原生 `saveAs` 中间无法逐段恢复。取消/退出发生在转换完成前会重做这一段，转换完成后不会为另存文件再排版。引擎任务临时目录在完成后删除；突然退出遗留目录在下次引擎任务开始时清理。空闲解绑后引擎进程退出，释放原生内存。

运行时资源安装使用进程间文件锁和同步完成标记。兼容的旧 Activity 入口与后台服务共用相同转换实现，JNI 初始化接受 Context。没有运行时升级或新发布版本；整组交付仍随下一次大版本统一发布。

## 本组验证

`OfficeJobFlowTest` 通过真实 DOCX → 两页 PDF 的 WorkManager 流程，检查中文/编号/金额、源 SHA256、结果登记与完成阶段复用。独立 MuPDF 再读和实际任务中心打开结果见 [验收记录](../acceptance/next/office-job-summary.json)。没有额外运行取消、杀进程和多个 OEM 后台策略的压力组合；原生内存峰值/真机帧时仍属于 JOB03 的未完成部分。
